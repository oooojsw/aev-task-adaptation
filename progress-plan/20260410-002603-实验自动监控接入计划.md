# 实验自动监控接入计划

时间：2026-04-10 00:26:03

## 目标

在不推翻现有 `auto-evolve` 系统的前提下，增加一个“实验启动即自动监控”的能力。

最终效果：

- 每次启动 `bootstrap / run-case / run-round / run-baseline` 时，自动确保外部监控页面在线
- 如果监控页还没启动，就自动启动并打开浏览器
- 如果监控页已经在线，就直接复用，不重复启动
- 监控页保持打开，不随实验结束自动关闭
- 后续新实验继续复用同一个监控页

## 设计原则

1. 不改现有实验主链  
   `auto-evolve` 的训练、评估、知识库更新逻辑保持不变。

2. 监控能力做成外挂层  
   监控应该是“先确保面板在线，再开始实验”，而不是把监控逻辑散落在每个执行函数内部。

3. 配置单独外置  
   和模型配置、权限配置一样，监控也要有单独的配置文件，便于以后切换端口、默认打开行为等。

4. 默认复用，不重复开多个窗口  
   如果已有 dashboard 服务在线，就直接复用。页面本身靠自动刷新持续更新。

## 具体实现

### 1. 新增监控配置文件

文件：

- `auto-evolve/monitor-config.json`

用于控制：

- 是否启用自动监控
- 是否自动启动
- hostname
- port
- 刷新间隔
- 默认显示数量
- 新启动时是否自动打开浏览器

### 2. 新增 monitor manager

文件：

- `auto-evolve/orchestrator/monitor.ts`

职责：

- 检查 dashboard 是否已经在线
- 如果未在线，则后台启动：
  - `bun run src/index.ts session dashboard --no-open`
- 等待健康检查通过
- 只有首次启动时才自动打开浏览器
- 写入运行状态到 `.runtime/monitor/session-dashboard.json`

### 3. CLI 统一接入

在这些命令开始前统一调用 monitor manager：

- `bootstrap`
- `run-case`
- `run-round`
- `run-baseline`

这样所有实验入口的行为保持一致。

### 4. 监控信息增强

沿用我们已经做好的 `session dashboard`，并增强：

- 优先显示当前工具标题
- 如果没有工具，就显示最近文本片段
- 完成后显示最后答案预览

这样用户能更快看出：

- 现在在哪个 phase
- 正在调什么工具
- 刚刚输出了什么

## 边界

当前版本能保证：

- dashboard 服务自动启动或复用
- 浏览器在首次启动时自动打开
- 页面持续自动刷新

当前版本暂不保证：

- 如果服务还在，但用户手动把浏览器页签关掉，系统能准确感知并重新打开
- 更细粒度的“每一步工具输入输出全量面板”

## 后续增强方向

1. 在 dashboard 中直接标出：
   - method
   - case
   - attempt
   - phase

2. 增加“只看 auto-evolve session”的过滤器

3. 增加会话详情侧栏：
   - 最近工具调用
   - 最近错误
   - 最近答案片段

4. 如果后面要接 `opencode-monitor` 外部项目，可以把现在这层 monitor manager 继续保留，只替换 dashboard 后端实现
