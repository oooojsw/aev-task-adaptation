# 经修 Agent 架构基础落地说明

日期：2026-04-10

## 本次完成的重点

- 经修 Agent 不再只是“一个维护 prompt”。
- 系统已经落地为：
  - 经修核心提示词
  - 反向传播模块
  - 维护操作系统
  - 预留的加载策略接口
  - 预留的维护权限等级接口

## 当前已落地的结构

### 1. 反向传播模块

- 目录：
  - `auto-evolve/reverse-propagation-modules/`
- 当前默认模块：
  - `direct-rewrite`

说明：

- 这代表当前基线方法的经验维护方式是“直接重写当前规范经验区”。
- 后续新方法可以增加新模块，而不需要重写经修核心。

### 2. 维护操作系统

- 目录：
  - `auto-evolve/maintenance-ops/`

说明：

- 每个维护操作现在都有独立 Markdown 定义文件。
- 当前已经支持默认操作集合，并允许后续继续新增、替换或裁剪。
- 经修 Agent 运行时会解析这些操作定义，再组装进自己的提示词。

### 3. 加载策略接口

- 当前保留接口，默认策略是：
  - `full-workspace-read-via-entry`

说明：

- 现在不对经修 Agent 做复杂选择性加载限制。
- 默认仍然允许它通过入口文件开始，并可继续读取整个经验工作区。
- 后续如果经验体系变大，可以继续扩展新的加载策略，而不用重写经修核心。

### 4. 维护权限等级接口

- 当前保留接口，默认等级是：
  - `full-access`

说明：

- 当前阶段先不做细粒度硬权限收紧。
- 这次只把接口和标识体系立住，便于后续扩展真正的权限层。

## 当前提示词分层

经修 Agent 当前已经按三层组装：

1. 核心提示词
2. 方法专属维护扩展
3. 运行时上下文

这次又补进了以下运行时块：

- 反向传播模块说明
- 加载策略说明
- 维护权限等级说明
- 当前可用维护操作列表

## 当前边界

- 加载策略目前只是预留接口，默认仍允许全读。
- 维护权限等级目前只是预留接口，默认仍视作全权限。
- 维护操作虽然已经可拔插，但目前仍是“提示词层操作定义”，还不是硬执行权限系统。
- 当前只有一个正式反向传播模块：
  - `direct-rewrite`

## 这次改动的意义

这一步之后，经修 Agent 已经不再是“简单接一个方法名然后直接改文件”。

它现在已经开始具备下面这种稳定架构：

- 核心不变
- 模块可换
- 维护操作可扩展
- 加载接口预留
- 权限等级接口预留

这为后面继续做：

- add-only
- subtract-only
- 权重型经验修正
- 对抗经验维护
- 多版本保留

这些新反向传播模块打下了基础。
