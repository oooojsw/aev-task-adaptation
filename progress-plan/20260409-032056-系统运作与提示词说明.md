# 系统运作与提示词说明

时间：2026-04-09 03:20:56

这份文档不讲代码细节，只讲现在这个系统整体是怎么运作的、我们现在在做什么、三阶段提示词系统是如何配合工作的。

## 1. 我们现在到底在做什么

我们现在做的，不是一个普通的“跑一次 AI 命令”的工具，而是一个**会自己积累专家经验的执行系统**。

它的目标是：

- 先给系统一批“材料 -> 标准答案”的训练样本
- 让系统先总结出一套专家经验
- 再让一个新的 agent 只依靠这套专家经验去解新题
- 如果解错，就把这次错误总结回专家经验里
- 不断循环，让专家经验越来越完整、越来越可泛化

你可以把它理解成：

- `OpenCode` = 执行引擎
- `auto-evolve` = 外层训练循环
- `knowledge-pack` = 专家经验库

## 2. 现在系统里最重要的几个部分

### 2.1 数据集

位置：

- `auto-evolve/dataset/cases/`

每个 case 里面通常有：

- `case.json`
- `material/`
- `expected/`

含义：

- `material/` 是题目材料
- `expected/` 是标准答案
- `case.json` 说明这道题怎么比较结果，比如是不是要求精确文本一致

### 2.2 专家经验库

位置：

- `auto-evolve/knowledge-pack/`

现在已经不是一份单文件了，而是一套 Markdown 文件：

- `manifest.md`
- `core/expert_rules.md`
- `core/output_contract.md`
- `core/execution_checklist.md`
- `patterns/general_rules.md`
- `patterns/exceptions.md`
- `lessons/failure_lessons.md`
- `change_log.md`

它们一起组成“专家经验系统”。

### 2.3 脚本层

位置：

- `auto-evolve/scripts/`

它的定位不是保存规则，而是未来给 agent 提供可复用工具和辅助脚本。

简单说：

- `knowledge-pack` 存“知识”
- `scripts` 存“能力”

### 2.4 运行结果目录

位置：

- `auto-evolve/runs/`

每次运行都会留下记录，方便复盘。

里面会保存：

- 这次用的 prompt
- OpenCode 的输出
- 事件流
- action trace
- 评估结果
- 知识包修改前后快照

## 3. 整个系统一条主链是怎么跑的

现在整个系统有三种主要运行方式：

### 3.1 `bootstrap`

作用：

- 第一次生成专家经验
- 或者强制重做一版专家经验

它做的事情是：

1. 读取全部已标注 case
2. 把这些 case 一起交给 OpenCode
3. 要求 OpenCode 根据这些训练样本总结规律
4. 把规律写进 `knowledge-pack`

所以：

- `bootstrap` 不是解题
- `bootstrap` 是“先写老师笔记”

### 3.2 `run-case`

作用：

- 处理单个 case

它做的事情是：

1. 先让一个 fresh agent 只读当前知识包去解题
2. 把它的输出和标准答案比较
3. 如果通过，就结束
4. 如果失败，就再开一轮，让 OpenCode根据失败信息修改知识包
5. 改完后再次尝试 solve
6. 重复，直到通过或者达到最大重试次数

所以：

- `run-case` = 解题 + 失败后修知识 + 再解

### 3.3 `run-round`

作用：

- 顺序跑完整个数据集

它做的事情是：

1. 按 case 顺序一个个跑
2. 前一个 case 学到的知识，会带到下一个 case

所以：

- `run-round` = 整批训练一轮

## 4. 提示词系统是怎么设计的

现在的提示词系统是一个**三阶段 prompt 系统**。

重点不是一条 prompt，而是三种 prompt 各自负责不同任务。

### 4.1 Bootstrap Prompt

用途：

- 用训练样本生成第一版知识包

它会给 OpenCode 这些信息：

- 知识包各个文件路径
- scripts 目录路径
- 全部训练 case 的材料和标准结果

它要求 OpenCode 做的事情是：

- 研究这些样本
- 提炼稳定规律
- 把规律分开写进知识包各个 Markdown 文件里

它的重点不是答题，而是：

- 写规则
- 写输出规范
- 写执行清单
- 写通用规则
- 写例外
- 写失败教训

### 4.2 Solve Prompt

用途：

- 用当前知识包解决一个具体 case

它会给 OpenCode 这些信息：

- 当前整套 knowledge-pack
- 当前 case 的材料
- 当前 case 的要求
- scripts 目录

它要求 OpenCode 做的事情是：

- 只把知识包当作自己的长期记忆
- 只解当前题
- 不改任何文件
- 最后只返回答案本身

Solve 阶段有一个很重要的约束：

- **只读**

也就是说：

- solve 不能改知识包
- 如果 solve 改了知识包，系统会认定这是违规，并恢复文件

### 4.3 Refine Prompt

用途：

- 在 solve 失败后，更新知识包

它会给 OpenCode 这些信息：

- 当前整套 knowledge-pack
- 当前 case 材料
- 标准答案
- 本次实际错误输出
- 本次结构化评估结果
- 本次 solve 的简化行动轨迹 `action_trace.md`

它要求 OpenCode 做的事情是：

- 研究这次失败为什么发生
- 不要推翻所有旧知识
- 只把这次失败中真正有价值的教训补进去
- 尽量做小修正，不要乱改
- 根据失败类型，去更新知识包中更合适的文件

简单说：

- `solve` 负责答题
- `refine` 负责复盘并修知识

## 5. 当前提示词系统为什么是连贯的

这三阶段现在的逻辑是连起来的：

### 第一步：先有知识

- `bootstrap` 建立知识包

### 第二步：知识驱动解题

- `solve` 只读取知识包去解题

### 第三步：失败再反馈回知识

- `refine` 把失败经验写回知识包

于是形成闭环：

1. 先写专家经验
2. 用专家经验解题
3. 错了就更新专家经验
4. 再用新的专家经验继续解题

这就是我们当前系统的核心学习闭环。

## 6. 知识包里每个文件大概负责什么

### `manifest.md`

负责：

- 说明这套知识包是什么
- 告诉 future agent 应该按什么顺序读这些文件

### `core/expert_rules.md`

负责：

- 核心专家经验
- 任务理解
- 总体解题原则

### `core/output_contract.md`

负责：

- 输出格式纪律
- 比如 `text_exact` 时不能多说一句话

### `core/execution_checklist.md`

负责：

- 解题步骤清单
- 告诉 fresh agent 应该先看什么、再做什么、最后检查什么

### `patterns/general_rules.md`

负责：

- 通用规律
- 适合泛化的稳定规则

### `patterns/exceptions.md`

负责：

- 例外情况
- 窄而明确的特殊规则

### `lessons/failure_lessons.md`

负责：

- 失败教训
- 常见错误模式
- 应该避免什么

### `change_log.md`

负责：

- 记录知识包什么时候被更新过

## 7. 评估系统是怎么判断对错的

每次 solve 之后，系统都会评估：

- 实际输出是什么
- 标准答案是什么
- 比较模式是什么

当前支持的比较方式有：

- `text_exact`
- `text_contains`
- `json_exact`

另外还会记录：

- 是否有工具失败
- OpenCode 退出码是否正常

所以评估结果不是一句“对/错”，而是一份结构化结果，告诉系统：

- 通过没通过
- 错在哪里
- 有没有工具失败

## 8. action trace 是干什么的

每次 solve 都会生成：

- `action_trace.md`

它不是完整隐藏思维，而是一个简化版行动轨迹。

它会帮助 refine 去理解：

- 这次 agent 实际做了什么
- 它是不是用了错误的工具
- 它是不是走错了规则
- 它是不是虽然思路对，但输出格式错了

所以现在 refine 不只是看“最后答案错了”，而是看：

- 错误结果
- 评估结果
- 行动路径

## 9. 当前系统已经做到什么程度

目前已经做到：

- 数据集能跑
- bootstrap 能生成知识包
- solve / refine 闭环能跑
- 单 case 能成功通过
- 知识已经从单文件升级成知识包
- 每次运行都有完整产物可复盘

## 10. 当前系统还没完全解决的地方

虽然主链已经跑通，但现在还有几个现实问题：

### 10.1 知识虽然拆成了多文件，但还不够“强路由”

意思是：

- 虽然有多个文件
- 但很多经验还是容易继续堆到 `core/expert_rules.md`

后面还要继续加强：

- 什么错误应该改哪个文件

### 10.2 还没有实验隔离

现在还是一套主知识包在学习。

后面你要做不同“反向传播”策略实验时，需要：

- 每个实验有自己的知识分支

### 10.3 还没有真正的 Git-tree 分支管理

你已经明确提出了这个方向。

后面应该做到：

- 多实验共享大部分知识
- 少量差异走分支
- 可比较、可回退、可合并

### 10.4 还没有并发实验调度

后面需要支持：

- 不同策略并行跑
- 不同会话并行比较

## 11. 用一句话总结现在这个系统

现在这个系统可以理解成：

**先用训练样本生成一套 Markdown 专家经验库，再让 fresh agent 只依靠这套经验去解题，失败后把这次教训写回经验库，从而不断提高泛化能力。**

## 12. 你现在最需要知道的最短版本

如果你只记 6 句话，就记这 6 句：

1. `bootstrap` 负责先写专家经验。
2. `solve` 负责只读专家经验去答题。
3. `refine` 负责答错后修改专家经验。
4. 专家经验现在不再是一份文件，而是一套 Markdown 知识包。
5. `scripts/` 是能力层，不是规则真源。
6. 后面真正的大升级方向是：知识分支管理、实验隔离、并发策略比较。
