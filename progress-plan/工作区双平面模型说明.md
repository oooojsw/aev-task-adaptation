# 工作区双平面模型说明

当前系统把 Experience Workspace 视为两个平面共同存在：

- 经验平面
- 运行时侧车平面

## 1. 经验平面

经验平面是系统真正管理的专家经验内容。

它包含：

- 专家经验 Markdown
- 受控 helper assets
  - 仅限 `tools/`
  - 仅限 `skills/`

经验平面参与：

- 工作区合法性校验
- 快照
- diff
- rollback
- acceptance
- propagation
- git-tree / commit

## 2. 运行时侧车平面

运行时侧车平面是工作区里允许存在、但不属于专家经验的运行时内容。

当前首个正式兼容的侧车目录是：

- `.opencode/`

它的定位是：

- OpenCode 自身生态目录
- 可承载全局规则要求的运行日志
- 可承载 `test_records.md` 这类记录文件

它不参与：

- 经验合法性判断
- 经验 diff
- 经验回滚
- 经验快照
- 经验版本树

## 3. 为什么要这样分

如果不做双平面模型，会出现两个问题：

1. `.opencode/` 明明是运行时侧车，却会被误判为经验污染
2. rollback 会误删运行日志，影响 OpenCode 本身和全局规则

双平面模型的目的就是：

- 兼容 OpenCode 的系统能力
- 同时保持专家经验体系干净、可控、可版本化

## 4. 当前边界

现在的正式边界是：

- `manifest.md`、规则模块、工具说明、失败教训等，属于经验平面
- `tools/`、`skills/` 下的受控文本资产，属于经验平面
- `.opencode/`，属于运行时侧车平面

所以：

- `.opencode/test_records.md` 可以存在
- 但它不算经验更新
- 它也不应决定经验是否合法

## 5. 对系统行为的影响

### diff
只看经验平面，不看 `.opencode/`

### rollback
只恢复经验平面，不删除 `.opencode/`

### snapshot
只记录经验平面，不记录 `.opencode/`

### propagation / git-tree
只传播经验平面，不传播 `.opencode/`

## 6. 一句话总结

`.opencode/` 现在被正式兼容为工作区里的运行时侧车层。

它可以存在，也可以写日志，但不会再污染专家经验系统本身。
