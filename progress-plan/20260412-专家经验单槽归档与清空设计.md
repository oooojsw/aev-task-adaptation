# 专家经验归档与清空设计

## 目标

- 在真正清空当前专家经验区之前，先保留一版可恢复快照。
- 保留机制每次保存一份历史版本，永不覆盖。
- 同时保留一个 `latest` 便捷恢复入口。
- 清空后仍保持经验工作区处于最小合法状态，而不是空目录或坏状态。
- 不把 `.opencode/**` 这类运行时侧车一起纳入归档。

## 设计

### 1. 历史归档 + 最新镜像

- 目录：
  - `auto-evolve/experience-archive/history/<archive-id>/`
  - `auto-evolve/experience-archive/latest/`
  - `auto-evolve/experience-archive/index.json`
- `history/` 中每次保存一份，永不覆盖。
- `latest/` 只镜像最新一版，方便恢复。
- `index.json` 记录所有归档条目。

### 2. 归档内容

- `metadata.json`
  - 归档时间
  - 说明 note
  - 源工作区根目录
  - 入口文件
  - 文件数
  - 文件列表
- `snapshot.json`
  - 受跟踪专家经验平面的完整快照
- `workspace/`
  - 物化后的专家经验文件，方便人和 agent 直接阅读

### 3. 清空方式

- 不直接把工作区变成空目录。
- 清空动作等价于：
  1. 先归档当前受跟踪经验平面
  2. 再把 live `knowledge-pack` 重置成最小种子
- 最小种子至少保留：
  - 单入口文件
  - `change_log.md`

### 4. 恢复方式

- 从 `experience-archive/latest/snapshot.json` 恢复回当前 live workspace。
- 恢复也只作用于受跟踪经验平面。
- sidecar 继续不参与 restore。

## 边界

- 这是工作区管理能力，不改变现有 judge / maintainer / propagation 主链。
- 当前只做“单槽归档 + 重置 + 恢复”。
- 未来如果需要多版本人工归档，可以在这个基础上再扩展，不影响本次实验路径。
