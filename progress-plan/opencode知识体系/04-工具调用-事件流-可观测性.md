# 工具调用、事件流与可观测性

## 1. OpenCode 的核心价值之一：它不是只会说话

OpenCode 最关键的一点，是它会调用工具。

这意味着一个 session 的执行路径，不只是：

- 用户输入
- assistant 输出

中间还可能包含：

- 读文件
- 列目录
- 搜索文本
- 编辑文件
- 写文件
- 跑 shell
- 调子任务
- 调技能

所以如果你要研究 OpenCode 的行为，必须看：

**工具调用轨迹。**

## 2. 当前常见工具有哪些

OpenCode 当前运行里最常见的工具包括：

- `read`
- `list`
- `glob`
- `grep`
- `edit`
- `write`
- `bash`
- `webfetch`
- `websearch`
- `codesearch`
- `task`
- `skill`
- `todowrite`

不同模型、不同任务、不同权限下，工具使用会有明显差异。

## 3. 事件流是什么

OpenCode 在 `--format json` 下，会持续往 stdout 输出 JSON 事件。

这就是我们后面能做：

- 记录运行轨迹
- 生成执行报告
- 做行为分析
- 构建 Judge

的根本原因。

## 4. 当前最重要的事件类型

### 4.1 `step_start`

表示：

- 一个 step 开始

### 4.2 `step_finish`

表示：

- 一个 step 结束
- 同时会带：
  - finish reason
  - cost
  - token 信息

### 4.3 `tool_use`

这是最重要的事件之一。

里面通常能看到：

- 调了哪个工具
- 当前状态
- 输入
- 输出
- 错误
- metadata

### 4.4 `text`

表示：

- assistant 输出的文本

### 4.5 `reasoning`

表示：

- provider 愿意暴露的 reasoning block

### 4.6 `error`

表示：

- session 级错误

## 5. 一个工具调用通常会经历什么状态

从处理器逻辑上看，一个工具调用大致可能经历：

- pending
- running
- completed
- error

所以你看到工具事件时，不要只看“有没有调这个工具”，还要看：

- 它是否真正完成
- 是否失败
- 输出是什么

## 6. 我们现在到底能看到多少

### 能稳定看到的

- 工具调用
- 工具输入
- 工具输出摘要
- 工具错误
- step 开始和结束
- assistant 文本输出
- session 错误
- token / cost / finish reason

### 部分可见的

- reasoning block

但要注意：

- 只有 provider 支持时才可能出现
- 还要运行时启用了相应展示
- 这也不是完整私有思维链

### 看不到的

- 模型完整私有思维链
- provider 内部隐藏决策
- 未暴露成 event 的内部上下文

所以最准确的说法是：

**我们能看到大部分外显行为，但不能完整看到模型脑内的全部过程。**

## 7. 我们现在如何把事件流变成可学习材料

当前项目里，最重要的一份整理产物是：

- `session_execution_report.md`

它把原始事件流整理成：

- Session Meta
- Path Inputs
- Final Outcome
- Tool Failure Summary
- Behavior Summary
- Ordered Timeline

这样你不用直接啃原始 `events.json`，也能理解一次 session 做了什么。

## 8. 为什么这个对经修和 Judge 都重要

因为后面如果要做：

- Judge
- 经修 Agent
- 行为分析
- 经验沉淀

你不能只知道“错了”，还得知道：

- 是怎么错的
- 调了什么工具
- 哪些工具失败了
- 哪些探索是空的
- 哪些行为是浪费的

这就是事件流和执行报告的意义。

## 9. 一句话总结

OpenCode 最有价值的不是只有最终答案，而是：

**它把 agent 的外显执行过程变成了一条可记录、可分析、可二次利用的事件流。**
