# 源码入口与学习路线

## 1. 这篇是做什么的

前面的文档主要讲“系统是什么”。

这一篇只解决一个问题：

**如果你后面要从知识文档继续走到源码，应该先看哪里。**

它不是代码详解，而是源码地图。

## 2. 最重要的源码入口

### 2.1 OpenCode 的 `run` 入口

文件：

- `packages/opencode/src/cli/cmd/run.ts`

建议你用它来理解：

- OpenCode 如何启动一次运行
- run 命令有哪些参数
- `--file` 是怎么变成附件的
- `--format json` 的事件输出是怎么来的

### 2.2 OpenCode 的 session 管理入口

文件：

- `packages/opencode/src/cli/cmd/session.ts`

建议你用它来理解：

- session list
- delete
- monitor
- dashboard
- 状态行是怎么整理出来的

### 2.3 OpenCode 的 session 状态定义

文件：

- `packages/opencode/src/session/status.ts`

建议你用它来理解：

- `idle`
- `busy`
- `retry`

这些状态最底层是怎么定义的。

### 2.4 OpenCode 的事件处理核心

文件：

- `packages/opencode/src/session/processor.ts`

建议你用它来理解：

- reasoning 事件怎么进入 session
- tool call 怎么进入 session
- text 怎么进入 session
- step 是怎么开始和结束的

这是“OpenCode 运行时到底发生了什么”的关键文件之一。

## 3. 我们自己和 OpenCode 的连接入口

### 3.1 `auto-evolve` 如何启动 OpenCode

文件：

- `auto-evolve/orchestrator/opencode.ts`

建议你用它来理解：

- 我们怎么调用 OpenCode
- 当前为什么是纯路径模式
- 当前模型、权限、限流是怎么传进去的
- 为什么当前每次运行会有独立 runtime config

### 3.2 我们怎么把一次 session 变成可读报告

文件：

- `auto-evolve/orchestrator/session-execution-report.ts`

建议你用它来理解：

- 为什么我们能看到时间顺序执行路径
- 为什么能做工具失败总结
- 为什么能做行为摘要

### 3.3 我们自己的外部监控是怎么接上的

文件：

- `auto-evolve/orchestrator/monitor.ts`
- `auto-evolve/monitor-server.ts`

建议你用它来理解：

- 为什么跑实验时可以自动拉起浏览器监控页
- 为什么监控可以复用

3. `auto-evolve/orchestrator/session-execution-report.ts`
4. `auto-evolve/monitor-server.ts`

## 8. 最建议的学习顺序

如果你是第一次认真学，最稳的顺序是：

1. 先把这套知识文档读完
2. 再看 `run.ts`
3. 再看 `session.ts`
4. 再看 `processor.ts`
5. 最后看 `auto-evolve/orchestrator/opencode.ts`

这样你会先建立系统视角，再进入实现细节。
