# 专业计划书：训练测试切分与基线层

时间：2026-04-09 04:48:33

状态：准备实施

## 1. 目标

本次改造聚焦两个问题：

1. 当前系统缺少固定测试集，无法验证泛化
2. 当前“基线思路”没有独立层，容易与系统方法定义发生混淆

本阶段目标是：

- 引入固定 train/test split
- 引入 `baseline.md`
- 在不推翻现有主链的前提下，把 baseline 从系统控制逻辑中解耦出来

## 2. 当前问题

### 2.1 缺少测试集

当前 `bootstrap` 与后续学习流程会读取全部 case。

问题：

- 全量样本参与学习
- 无法证明知识库对未学习案例的泛化

### 2.2 用户基线与系统方法边界不清

当前方法 prompt 已外置，但用户可编辑、可自由发挥的“基线内容”还没有单独层。

风险：

- 用户输入可能直接与方法模板混杂
- 后续方法比较会不干净
- 容易误把用户先验当成系统学习结果

## 3. 设计原则

### 原则 1：测试集只评估，不学习

测试集上的执行只能进入：

- solve
- evaluate

不得进入：

- refine
- knowledge update

### 原则 2：baseline 是输入材料，不是控制文件

`baseline.md` 的作用是：

- 提供用户起始思路
- 作为上下文材料被读取

它不应负责：

- phase 编排
- 权限控制
- 评估逻辑
- 知识分支逻辑

### 原则 3：现有系统保持兼容

当前基线方法 `sequential-refine` 必须保持可运行。

新能力应通过附加字段和附加文件接入，而不是重写现有执行链。

## 4. 目标结构

建议结构：

```text
auto-evolve/
  baseline.md
  dataset/
    SPLIT.md
    cases/
  methods/
    sequential-refine/
    adversarial-test/
  knowledge-pack/
```

## 5. 数据切分方案

当前先固定：

- Train: `case-001` ~ `case-005`
- Test: `case-006` ~ `case-010`

建议通过：

- `auto-evolve/dataset/SPLIT.md`

统一声明。

### SPLIT.md 的职责

- 明确 train case 列表
- 明确 test case 列表
- 作为可读、可审计的数据切分文件

### 系统应保证

- `bootstrap` 默认只读取 train
- 学习型 `run-round` 默认只跑 train
- 测试型 `run-round` 可明确指定 test

## 6. baseline.md 的角色

建议新增：

- `auto-evolve/baseline.md`

### baseline.md 的职责

- 保存用户主观思路、起始方向、附加约束
- 为 solve / bootstrap / refine 提供额外上下文

### baseline.md 的非职责

- 不决定 phase 顺序
- 不决定方法类型
- 不控制知识库写入边界
- 不充当知识库本身

## 7. Prompt 层重组

后续 prompt 组装时，应明确分层：

### 系统框架层

来自：

- 方法 prompt 文件

负责：

- 当前 phase 的任务定义
- 固定规则
- 文件职责

### 用户基线层

来自：

- `baseline.md`

负责：

- 用户主观输入
- 起始猜想
- 附加背景

### 学习知识层

来自：

- `knowledge-pack`

负责：

- 系统历史学习结果

## 8. 运行模式

建议正式区分 3 种模式。

### 8.1 Learn Mode

使用：

- train split

允许：

- refine
- 修改知识库

### 8.2 Eval Mode

使用：

- test split

允许：

- solve
- evaluate

禁止：

- refine
- 知识更新

### 8.3 Inference Mode

使用：

- 只有材料，没有标准答案

允许：

- solve

禁止：

- evaluate
- refine

本阶段先落 Learn + Eval，Inference 只保留概念。

## 9. 与现有代码的契合点

### 9.1 `schema.ts`

扩展配置：

- `baselineFile`
- `splitFile`

并验证：

- baseline 文件存在
- split 文件存在
- split 中的 case ID 合法

### 9.2 新增 split 解析层

新增独立模块，负责：

- 解析 `SPLIT.md`
- 输出 train/test 列表

### 9.3 `bootstrap.ts`

改为：

- 只读取 train split
- 附带 baseline.md

### 9.4 `prompts.ts`

改为：

- 在 bootstrap / solve / refine prompt 中显式暴露 baseline 文件
- 明确告知模型：
  - baseline 是用户输入
  - 可参考，但不是绝对真理

### 9.5 `case-runner.ts`

扩展运行模式：

- `learn`
- `eval`

在 `eval` 模式中：

- solve 后直接 stop
- 不触发 refine

### 9.6 `round-runner.ts`

扩展：

- `split`
- `mode`

并支持：

- `train` 默认学习
- `test` 默认只评估

## 10. 本阶段可接受范围

本阶段不做：

- Git-tree
- experiment config
- adversarial method runtime
- inference-only CLI

本阶段只做：

- train/test split
- baseline 层
- learn/eval 分流

## 11. 验收标准

完成后应满足：

1. `bootstrap` 默认只使用 train cases
2. `run-round --split test` 不会修改知识库
3. baseline 文件能稳定被附带到 bootstrap / solve / refine
4. baseline 文件内容再天马行空，也不会控制系统编排逻辑
5. 现有 `sequential-refine` 主链继续可运行

## 12. 结论

这一步不是扩功能的细节优化，而是建立后续所有实验的基础边界：

- 训练数据边界
- 测试数据边界
- 用户输入边界
- 系统学习结果边界

只有把这四个边界立住，后面的 Git-tree、对抗测试、双分支实验才会干净。
