# 变更接受层实施计划

时间：2026-04-09 16:17:14

## 目标

在不推翻现有 `sequential-refine` 基线方法的前提下，给系统增加一层“变更接受门”：

- 失败后仍然允许 refine
- 但 refine 产出的知识修改不能直接默认接受
- 系统要先检查这次修改是否改对了地方、是否修好了当前 case、是否破坏了少量回归样本
- 只有通过接受检查，知识库修改才保留
- 否则立即回滚到 refine 前的知识状态

## 为什么现在先做这个

当前系统已经具备：

- train / test 切分
- baseline 文件
- knowledge-pack 多文件结构
- solve / evaluate / refine 主循环

但还缺：

- 工具失败强制判错
- 按失败类型定向修改知识文件
- 小规模回归检查
- 拒绝坏修改并回滚

如果这层不先补上，后面的 Git-tree、双分支实验、对抗测试都会放大噪音，而不是放大学到的有效知识。

## 第一版范围

这一版只做最小可用能力：

1. 工具失败必须算失败
2. 对每次失败做简单分类
3. 给 refine 一个“允许修改的知识文件列表”
4. refine 后检查实际改动文件是否越界
5. 对当前 case 外，再抽少量 train case 做微型回归
6. 回归不过则回滚知识包

## 不在这一版做的内容

- Git-tree 分支管理
- 多实验并发
- 自动合并知识分支
- 新的 adversarial-test 方法
- 大规模回归集调度

## 失败分类思路

第一版先做保守启发式分类：

- 输出格式类失败
  - 优先允许修改：
    - `core/output_contract.md`
    - `core/execution_checklist.md`
    - `lessons/failure_lessons.md`

- 执行过程类失败（tool failure / 非 0 退出 / 空输出）
  - 优先允许修改：
    - `core/execution_checklist.md`
    - `lessons/failure_lessons.md`
    - `core/expert_rules.md`

- 规则推理类失败（结果不对，但不是纯格式问题）
  - 优先允许修改：
    - `patterns/general_rules.md`
    - `patterns/exceptions.md`
    - `core/expert_rules.md`
    - `lessons/failure_lessons.md`

## 微型回归规则

第一版采用固定小样本回归：

- 只从 train split 中抽样
- 排除当前 case
- 默认最多 3 个（由 `regressionSampleSize` 控制）
- 用 `eval` 模式运行，不允许 refine

接受条件：

- 当前 case 的下一次 solve 必须能通过
- 回归样本不能比 refine 前更差

如果不满足：

- 回滚整个 knowledge-pack 到 refine 前快照

## 产物记录

每次 refine 后，新增一组 acceptance 产物：

- `routing.json`
- `acceptance.json`
- `regression-summary.json`

这样后面做 Git-tree 时，可以只把“被接受的修改”当成有效知识节点。

## 预期结果

完成这一层后，系统会从“失败就改”升级为“失败后谨慎修改”：

- 更少把错误经验写进知识库
- 更容易比较不同方法
- 为后面的双分支实验打基础
