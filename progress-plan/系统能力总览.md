# 系统能力总览

状态：当前真实实现版

这份文档只描述：

- 系统现在已经具备什么能力
- 每个模块拿什么输入
- 每个模块输出什么结果
- 这些结果流向哪里

不展开代码细节。

---

## 1. 当前系统的总体目标

当前系统的目标是：

- 从案例中学习
- 形成专家经验工作区
- 用专家经验驱动 solve agent
- 在失败后通过 Judge 和 Maintainer 决定是否更新经验
- 在高层对经验版本做实验和治理

---

## 2. 当前已有的四层能力

### `Layer 1: Task Execution Layer（任务执行层）`

当前已经具备：

- `bootstrap`
- `run-case`
- `run-round`
- `run-baseline`
- 最小第三层委托执行

当前还支持两类执行方式：

- `sequential`
- `parallel-batch-5-light-shard`

### `Layer 2: Local Experience Maintenance Layer（局部经验维护层）`

当前已经具备：

- pre-judge
- maintainer
- verify
- regression
- post-judge
- accept / rollback

当前已落地的维护模块：

- `direct-rewrite`
- `add-only`

### `Layer 3: Version Governance Layer（版本治理层）`

当前已经具备最小底座：

- commit
- branch
- candidate
- campaign
- branch workspace

并且已经能：

- 直接复用第二层方法
- 直接复用新的 batch 局部学习内核

### `Layer 4: Generalization & Overfit Control Layer（泛化与过拟合控制层）`

当前还没有进入正式实现。

现状是：

- 设计边界已明确
- 真实优化器未落地
- augmentation / adversarial / purification 仍未实现

---

## 3. 当前可运行的方法

### `sequential-refine`

定位：

- 当前控制组方法
- 顺序单 case 学习链

输入来源：

- 单个 case
- 当前经验工作区
- baseline

输出去向：

- solve 结果
- judge 结果
- maintainer 结果
- verify / regression / post-judge
- 经验区更新或回滚

### `add-only`

定位：

- 第二种局部维护方法
- 以追加为主，不大改旧经验

输入来源：

- 单个 case
- 当前经验工作区
- baseline
- judge 结果

输出去向：

- 新增或轻量追加的经验更新
- verify / regression / post-judge
- 接受或回滚

### `parallel-batch-5-add-only`

定位：

- 当前 `V1` 批量局部学习内核的正式方法形态
- 第一层并行，第二层批次统一维护

输入来源：

- 一批 case
- 当前经验工作区
- baseline
- 每个 shard 的 solve / judge 结果

输出去向：

- `Batch Learning Packet`
- 1 次 batch maintainer 维护
- batch verify / regression / post-judge
- 接受或回滚

## 4. 当前可运行的任务入口

### `bootstrap`

作用：

- 从训练案例生成第一版经验工作区

输入来源：

- train split 案例
- 模板库
- baseline
- 最小种子工作区

输出去向：

- 初始化后的经验工作区
- bootstrap 任务记录

### `run-case`

作用：

- 跑单个 case

输入来源：

- 单个 case
- 当前方法
- 当前经验工作区

输出去向：

- case 独立运行目录
- solve / judge / maintain / acceptance 产物

### `run-round`

作用：

- 按 split 批量跑若干 case

输入来源：

- split
- method
- caseLimit
- 当前经验工作区

输出去向：

- round 目录
- 每个 case 的独立运行目录
- round 汇总

### `run-baseline`

作用：

- 一次完成：
  - bootstrap
  - train
  - test
  - scorecard

输入来源：

- method
- train/test limit
- 数据集切分

输出去向：

- baseline 目录
- scorecard
- 快照与轮次汇总

### `run-propagation`

作用：

- 第三层最小传播实验入口

输入来源：

- propagation method
- source ref / canonical
- 分支工作区

输出去向：

- campaign 目录
- candidate commit
- branch head 更新

## 6. 当前工作区模型

当前经验工作区已经是双平面模型。

### `Tracked Experience Plane（受跟踪经验平面）`

包含：

- 专家 Markdown
- 入口文件
- change log
- rules / lessons / contracts / tool guides
- 受控 helper assets

这些内容会进入：

- validation
- diff
- rollback
- snapshot
- propagation commit

### `Runtime Sidecar Plane（运行时侧车平面）`

当前代表：

- `.opencode/**`

这些内容：

- 允许存在
- 允许被 OpenCode 使用
- 不参与经验治理
- 不进入 diff / rollback / snapshot / commit

## 8. 当前 Judge 能力

### `Runtime Guards`

输入来源：

- 运行状态
- 必要文件
- 工作区状态

输出去向：

- 系统护栏
- 失败中止 / 回滚前提检查

### `Hard Judge`

当前已实现的本地 skills：

- `exact-output`
- `tool-failures`
- `session-behavior`

输入来源：

- evaluation
- tool failures
- session events / execution reports

输出去向：

- hard check artifacts
- Soft Judge

### `Soft Judge`

输入来源：

- execution report
- learning log
- task manifest
- hard check outputs
- evaluation

输出去向：

- `judge_summary.json`
- `judge_report.md`
- 是否启动 maintainer 的结论

### `Post-Judge`

输入来源：

- verify 结果
- regression 前后结果
- workspace 变更信息

输出去向：

- `post_judge_summary.json`
- `post_judge_report.md`
- acceptance 决策

## 11. 当前 batch V1 的真实能力边界

### 已经做到的

- 5 case 微批次并行
- light shard
- batch learning packet
- 单 batch maintainer
- batch post-judge
- 第三层可复用

### 还没做到的

- shard 本地 maintainer
- batch evidence enricher
- adversarial / augmentation suite
- batch compression / purification
- generalized optimization layer

也就是说，当前 `V1` 是：

**一个已经跑通的批量局部学习内核，而不是完整的高层优化系统。**

## 13. 当前第一版设计目标完成度

如果对照当前 `V1` 设计目标，可以这样判断：

### 已实现

- `Layer 1` 的 batch execution V1
- `Layer 2` 的 batch packetization V1
- 第三层对 batch kernel 的直接复用
- 保持旧顺序主链不被破坏

### 部分实现

- recipe 抽象已经开始落地，但还没有彻底从“方法名”提升为完整可自由组合的正式系统

### 尚未实现

- `Layer 4` 的正式接口对象
- `Optimization Candidate Package`
- `Optimization Outcome`
- `Optimizer Memory`

所以最准确的结论是：

**V1 的核心局部学习目标已经做成；V1 的完整四层接口目标还没有全部做完。**

---

## 14. 一句话总结

当前系统已经具备：

**顺序学习、追加式学习、批量局部学习、前后 Judge、双平面经验工作区、最小第三层传播实验底座。**

但它还没有进入：

**第四层全局优化器与完整版本治理阶段。**
