# 第三层与工作区双平面补充说明

## 1. 这份补充文档解决什么问题

第三层已经开始引入：

- snapshot
- branch
- candidate commit
- propagation campaign

但在实际运行里，工作区里不只有“专家经验”本身，还可能存在 OpenCode 运行时自己的侧车目录，例如：

- `.opencode/`

这份文档的目的，是把第三层与“工作区双平面模型”的边界讲清楚，避免后续 Git-tree、diff、rollback、promotion 被运行时日志污染。

---

## 2. 工作区双平面模型

第三层现在和前两层一样，统一采用双平面模型：

### 2.1 经验平面

这是第三层真正要追踪、快照、比较和晋升的内容。

包含：

- 专家经验 Markdown
- 受控 helper assets
- 入口文件
- 变更日志
- 规则模块
- 工具说明
- 技能说明

这些内容会进入：

- snapshot
- candidate commit
- branch diff
- rollback
- merge
- promotion

### 2.2 运行时侧车平面

这是运行过程中允许存在、但不进入经验治理的内容。

当前最重要的例子就是：

- `.opencode/**`

这些内容可以继续服务：

- OpenCode 自身运行
- 全局规则日志
- `test_records.md`
- 本地技能/工具运行痕迹

但它们不属于正式专家经验。

---

## 3. 第三层现在如何处理 `.opencode/`

第三层现在已经明确采用下面这条规则：

- `.opencode/` 允许出现在 branch workspace 中
- `.opencode/` 不会让工作区被判成非法经验区
- `.opencode/` 不进入 candidate commit
- `.opencode/` 不参与经验 diff
- `.opencode/` 不参与 rollback
- `.opencode/` 不参与后续 merge / promotion

也就是说：

**第三层兼容 `.opencode/`，但不把它当成经验的一部分。**

---

## 4. 这对 snapshot / commit / branch 分别意味着什么

### 4.1 snapshot

第三层做 snapshot 时，只记录经验平面。

因此：

- `.opencode/test_records.md` 不会进入 snapshot manifest
- sidecar 文件不会被存进 blob store

### 4.2 commit

candidate commit 只表达：

- 当前专家经验长什么样

而不表达：

- 运行时日志写了什么
- `.opencode/` 里发生了什么

### 4.3 branch workspace

branch workspace 是第三层实际运行方法的地方。

这里可以同时存在：

- 被第三层追踪的经验文件
- 本地运行时 sidecar 文件

所以 branch workspace 是“混合存在”的，但第三层只治理其中的经验平面。

---

## 5. 为什么这个边界很重要

如果第三层不把 sidecar 平面剥离出去，后面会出现几个问题：

- branch 之间的 diff 会被日志文件污染
- rollback 会误删 `.opencode/test_records.md`
- candidate commit 会被本地运行痕迹污染
- merge 会把运行时噪音误当成经验变更
- promotion 会把临时副产物带入 canonical

所以这不是一个“实现细节”，而是第三层必须具备的基础边界。

---

## 6. 当前第三层元数据现在会记录什么

为了让第三层更可观察，campaign 现在会额外记录：

- 初始 branch workspace 的经验文档列表
- 初始 helper assets 列表
- 初始 runtime sidecar 文件列表
- 最终 branch workspace 的经验文档列表
- 最终 helper assets 列表
- 最终 runtime sidecar 文件列表

这样做的目的不是让 sidecar 进入治理，而是：

- 让我们知道它存在
- 让我们确认它被正确隔离

---

## 7. 当前阶段的设计原则

第三层当前对 sidecar 平面的处理原则是：

1. 允许存在
2. 不纳入经验治理
3. 不污染版本树
4. 保持可观察
5. 不额外影响前两层主逻辑

---

## 8. 一句话总结

第三层现在已经正式支持工作区双平面模型：

**branch workspace 允许同时存在专家经验和平行运行时 sidecar；但 snapshot、candidate commit、diff、rollback、merge、promotion 只面向经验平面，不把 `.opencode/` 这类运行时目录纳入版本治理。**
