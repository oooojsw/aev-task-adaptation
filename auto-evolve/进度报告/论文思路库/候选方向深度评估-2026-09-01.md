# Auto-Evolve 论文方向深度评估

日期：2026-09-01
范围：`E:\auto prompt` 本地论文库、582 份单篇审计档案、Auto-Evolve 现有 OfficeQA/SpreadsheetBench 实验记录，以及 2026 年最新 arXiv 相邻工作。

## 1. 先给结论

目前最适合少补实验、最大化复用现有结果的方向是：

> **长程文件任务中的 Skill 生产者—消费者匹配：效用、回归与产物接地的实证研究**

英文工作题目：

> **Producer–Consumer Compatibility in Long-Horizon Agent Skills: Utility, Regression, and Artifact Grounding**

这不是“我们发明了 Skill”，也不是“AEV 全面优于 SkillOpt”。论文要回答的是：

> 同一份冻结 Skill 在不同消费者模型和运行环境上为什么会产生增益、无效、负迁移或回归？在 Office/Spreadsheet 这类真实文件产物任务中，最终分数、逐题修复、逐题回归、产物接地和运行时故障应该如何一起报告？

这个方向最能复用已有矩阵，所需重训最少；代价是方法创新强度低于“验证计算补偿”路线，因此不能保证二区录用。若要冲中国计算机研究生通常要求的二区，必须把论文写成严谨的实证方法研究，而不是实验流水账。

## 2. 为什么不能继续使用原来的几个题目

### 2.1 “一种新的任务轨迹生成方法”不准确

AEV 没有改变原始任务执行器如何生成轨迹，主要改变的是执行后验证、失败归因、经验筛选、组织和合并前准入。继续使用“新的轨迹生成方法”会造成方法定义错误。

### 2.2 “首次做经验治理”已有明显重叠

SkillGen 已经用成功/失败轨迹做对比归纳，并把 Skill 当作干预，在同一批任务上同时测有 Skill 和无 Skill 的修复与回归。[SkillGen 原文](https://arxiv.org/abs/2605.10999)

SkillCoach 已经把 Skill 选择、遵循、组合和反思转成过程级评价，并用过程 rubric 筛选训练轨迹。[SkillCoach 原文](https://arxiv.org/abs/2607.01874)

Rethinking Self-Evolving Agent Skills 已经在固定执行器、优化器、验证规则和轮数下比较 Normal、Fail-only、Success-only，并指出自进化是稀疏且验证过滤的搜索过程。[Rethinking 原文](https://arxiv.org/abs/2608.02636)

因此不能把“成功/失败反馈”“验证后再合并”“失败轨迹治理”重新包装成完全原创。

### 2.3 “Skill 可能造成负迁移”也已有直接研究

The Regression Tax 在约 6,000 次运行中拆分了 Skill 修复 baseline failure 与破坏 baseline success 的回归，并分析了 description osmosis、grounding displacement 和 verification displacement。[Regression Tax 原文](https://arxiv.org/abs/2607.22520)

Agent Skills Can Be Harmful 进一步使用成对对照分析 Skill 引起的功能失败和效率回归。[Agent Skills Can Be Harmful 原文](https://arxiv.org/abs/2608.11888)

所以我们的贡献不能是“首次发现负迁移”，而应是把这个问题放到真实长程文件产物和多运行时实验中，并提供完整的可审计证据。

## 3. 本地论文库给出的新边界

本地 582 篇档案和对应 PDF 中，最接近的研究簇可以归纳为：

| 研究簇 | 代表工作 | 已经覆盖 | 我们不能再说什么 |
|---|---|---|---|
| Skill 效用干预 | SkillGen | 同题有/无 Skill、gain、regression | 不能说首次做净效用评估 |
| 过程评价 | SkillCoach | Skill 选择、遵循、组合、反思 | 不能说最终分数不足以评价 Skill 是新发现 |
| 经验反馈动力学 | Rethinking | Normal、Fail-only、Success-only、多轮控制 | 不能说成功/失败消融是原创 |
| 负迁移与回归 | Regression Tax、Agent Skills Can Be Harmful | 回归、残余失败、功能和成本伤害 | 不能只凭多模型矩阵宣称发现负迁移 |
| 持续评价与可复现 | ACES、AEVAL | paired trials、Skill Lift、executor/grader 分离、运行时 CI | 不能说可重复 Skill 评测协议首创 |
| 生产者—消费者生命周期 | From Raw Experience to Skill Consumption | extractor 与 consumer 不一致、跨模型效用、负迁移 | 不能说生产者和消费者错配此前无人研究 |
| 可验证 Skill artifact | ContractSkill、Skills as Verifiable Artifacts | 契约、后置条件、repair、trust schema | 不能说 Skill 是可验证 artifact 首次提出 |
| 计算投入与临时 Skill | SkillTTA | test-time compute-to-capability conversion | 不能把额外 token 换性能直接称为新 scaling law |

## 4. 现有实验能提供什么证据

根据当前运行记录，已有材料包括：

- OfficeQA 官方 172 题的多条件 Skill 矩阵；
- SpreadsheetBench 官方 test280 的多模型和多 Skill 条件；
- GPT-5.4-mini、GPT-5.4、GPT-5.5、MiniMax M2.7、Qwen、DeepSeek、Gemini 等消费者结果；
- 无 Skill、AEV merge-as-old、optMiniMax M2.7、AEV merge-as-opt、官方 Skill 等条件；
- 正收益、无收益和负收益同时存在；
- 逐题结果、基础设施失败归档、validator crash、provider 错误、上下文长度和运行时变化记录；
- AEV 训练和合并过程中的 token、调用次数和部分角色成本记录；
- Blank Eval、硬验证、Direct Chat、Skill hash、split UID、配置隔离和实验血统记录。

这些材料可以支撑“Skill 效果依赖消费者和运行协议”以及“单一平均成功率不足以描述 Skill 效用”的研究观察。但它们还不能自动支撑“AEV 是新的 Skill 算法”或“AEV 比所有已有方法更有效”。

## 5. 推荐主线的论文因果链

论文应尽量固定下面的逻辑：

```text
相同任务与相同冻结 Skill
        |
        +--> 不同消费者模型/运行环境
        |
        +--> paired no-skill / with-skill execution
        |
        +--> gain: Skill 修复原本失败的题
        +--> regression: Skill 破坏原本成功的题
        +--> persistent failure: 两种条件都失败
        +--> artifact grounding / verification evidence
        +--> provider / validator / runtime failures separately audited
        |
        +--> producer-consumer compatibility map
```

这里的主变量不是“哪个模型最强”，而是“同一个 Skill 在不同消费者上的净效用结构”。模型名称只是实验条件，不能把跨模型排名写成科学结论。

## 6. 最小补实验包

为了尽量少烧额度，建议不重新训练全部条件，而只补以下内容：

### 实验 A：固定运行时的核心矩阵复测

在一套明确冻结的运行时、同一评分器、同一上下文规则下，选择 OfficeQA 和 SpreadsheetBench 各一组代表性消费者，至少完成：

- no-skill；
- AEV merge-as-old；
- AEV merge-as-opt；
- optMiniMax M2.7 Skill。

重点不是重新追求最高分，而是确保四个条件的运行时、分母、失败重试和输出上限完全一致。

### 实验 B：逐题效用分解

对已有完整逐题结果计算：

- `gain`：无 Skill 失败、有 Skill 成功；
- `regression`：无 Skill 成功、有 Skill 失败；
- `persistent failure`：两者都失败；
- `unchanged success`：两者都成功；
- hard accuracy、soft accuracy、有效分母和基础设施失败数。

必须保留所有题目，不能只挑正收益题。

### 实验 C：少量证据审计

从 gain、regression 和 persistent failure 中各抽取少量案例，核对：

- 实际发送给消费者的 Skill 内容和长度；
- 输入材料是否完整；
- 是否发生截断或 OCR/上下文问题；
- 最终产物或答案；
- 验证器实际输入、标准答案和 stdout/stderr；
- 是否应归类为模型错误、Skill 诱导错误、验证器错误或平台故障。

### 实验 D：一个长度/上下文控制

只做一个轻量控制即可：比较完整 Skill 与长度匹配截断 Skill，或者比较完整 Skill 与 procedure-only Skill。该实验用于排除“Skill 更长所以分数不同”的主要质疑，不建议一开始做大量内容消融。

## 7. 其他方向的取舍

| 方向 | 现有结果复用度 | 额外实验量 | 文献重叠 | 当前建议 |
|---|---:|---:|---:|---|
| 生产者—消费者匹配与效用分解 | 高 | 低到中 | 中高 | 当前首选 |
| 长程文件任务的证据接地 | 中高 | 中 | 中高 | 作为机制章节或第二选择 |
| 验证计算补偿弱生产者 | 中 | 高 | 中 | 高潜力，但另开实验线 |
| Skill 生产 Scaling Law | 低 | 很高 | 中 | 暂停 |
| merge-as-long-task 新算法 | 低 | 高 | 高 | 保留负结果，不作主线 |
| 运行时漂移与可复现评测 | 高 | 低 | 高 | 作为方法学支撑，不单独作主线 |
| AEV 全面优于 SkillOpt | 高 | 低 | 高 | 仅作对照结果 |

## 8. 论文贡献应如何写

### 可以写

1. 提出一个面向长程文件产物任务的 Skill 效用分析协议，统一报告净增益、回归、持续失败和运行时故障。
2. 用同一冻结 Skill 的多消费者矩阵，展示生产者—消费者匹配具有明显的非单调性，Skill 质量不能由生产者分数或平均成功率单独预测。
3. 将硬产物验证、模型失败、validator/provider/runtime 故障和上下文截断分开，给出可复核的案例证据。
4. 对 AEV、SkillOpt 和不同合并路径的结果提供完整正负结果，而不是只报告最高分。

### 不要写

- “首次提出 Skill 经验治理”；
- “首次提出成功/失败轨迹筛选”；
- “AEV 全面优于 SkillOpt”；
- “MiniMax M2.7 等价于 GPT-5.5”；
- “建立了 Skill 生产 Scaling Law”；
- “一定达到二区”。

## 9. 二区可行性判断

客观判断：**当前已有材料接近一篇有价值的实证系统论文，但还不能证明已经达到二区标准。**

主要原因不是结果少，而是创新类型从“新算法”转成了“严格的场景化实证协议”。这类论文能否达到二区，取决于目标期刊是否接受 agent system evaluation/empirical study，以及文章是否做到：

- 问题定义窄而清楚；
- 与 SkillGen、SkillCoach、Regression Tax、ACES、AEVAL、From Raw Experience to Skill Consumption 等工作正面比较；
- 两个数据集使用统一有效口径；
- 逐题 paired analysis 和置信区间完整；
- 运行时漂移和基础设施失败不混入模型结果；
- 正收益、负收益和失败案例均保留；
- 限制部分主动承认文献重叠和因果识别边界。

如果不补实验，最多可以写成“已有系统实证观察”；完成 A--D 后，才可以写成“长程文件任务中 Skill 效用与生产者—消费者匹配的系统研究”。这比继续堆更多模型或重复挑最高分更能提高投稿可信度。

## 10. 最终决策

当前推荐顺序不是“哪个分数最高”，而是：

1. 以候选方向 17 为主线：生产者—消费者匹配与 Skill 效用分解；
2. 用方向 18 的 artifact grounding 解释部分 gain/regression；
3. 用方向 19 的运行时审计保证结果可信；
4. 把方向 5/20 的验证计算补偿作为后续高成本论文，而不是混入当前低成本稿件；
5. 保留 AEV vs SkillOpt、merge-as-old vs merge-as-opt 和跨模型矩阵作为对照证据，不再把它们单独包装成创新。

这条路线最诚实的论文定位是：**不是重新发明 Skill，而是揭示并测量长程文件任务中 Skill 效用的生产者—消费者匹配、回归结构和证据接地边界。**

## 11. 对“长程任务、少量训练集条件下的 Skill 生成与泛化控制”的第三轮核验

本轮针对另一份分析中最容易过度表述的部分做了原文核验，并补查了 2026 年 8 月新增的相邻工作。

### 11.1 已确认的直接重叠

1. `SkillGen (2605.10999)` 已经把 Skill 作为干预来评测，在同一批实例上比较有 Skill 与无 Skill，并显式区分 baseline failure 被修复和 baseline success 被破坏；因此“验证 Skill 的净效果”不是我们首次提出。[原文](https://arxiv.org/abs/2605.10999)
2. `Trace2Skill (2603.25158)` 已经研究长轨迹、并行经验分析、层级合并、跨模型和 OOD 泛化；因此“长程轨迹生成可迁移 Skill”不能单独作为创新点。[原文](https://arxiv.org/abs/2603.25158)
3. `Rethinking Self-Evolving Agent Skills (2608.02636)` 已经在固定执行器、优化器、验证规则和轮数的条件下比较 Normal、Fail-only、Success-only，并报告了多轮演化的稀疏改进、饱和与回退；因此“少量成功/失败反馈影响泛化”不是空白。[原文](https://arxiv.org/abs/2608.02636)
4. `SKILL.state (2608.26263)` 从长程执行的上下文增长、状态压缩和 context poisoning 角度研究 Skill runtime；因此“长程导致上下文问题”需要作为控制变量，而不是未经验证的 AEV 机制解释。[原文](https://arxiv.org/abs/2608.26263)
5. `Long-Horizon Agent Trajectory Attribution (2608.06909)` 已把长程轨迹归因、组件级贡献和归因链恢复定义为独立评测问题；因此“失败归因”也不能笼统声称是新的研究问题。[原文](https://arxiv.org/abs/2608.06909)
6. `SkillGate (2608.18852)` 研究长程任务中的 Skill 选择信用分配和同预算对照；因此任何“长程 Skill 选择更难”或“增加计算能改善长程 Skill 使用”的叙述都要与选择问题区分开。[原文](https://arxiv.org/abs/2608.18852)

### 11.2 对另一份回答的具体修正

- 不能断言 `SkillGen` 只处理 3--5 步短程工具调用；其原文摘要明确称覆盖多个 agent 和数据集，并没有支持这个限定。
- 不能断言现有方法普遍把局部特例固化成通用 Skill；这可以作为待检验假设，不能作为文献事实。
- 不能使用未经实验得到的 `[48,52,55,57,57]` 等曲线；它们只能是图形示例，不能进入论文、摘要或实验结论。
- “顶会极度推崇”“极易发表”“必然抗过拟合”都不是证据结论。当前最多能说存在一个可检验的、部分重叠的实证问题。
- `Rethinking` 的正确 arXiv 编号是 `2608.02636`，不能写成 `2607.26643`。

### 11.3 这个方向仍然可能成立的最窄版本

不建议题目写成“新的长程任务轨迹生成方法”。我们没有改变任务执行器本身的轨迹采样策略，主要改变的是经验组织、验证、筛选与 Skill 生成流程。更准确的研究命题是：

> 在可验证的长程文件任务中，当 Skill 生产只允许使用少量训练任务时，经验池规模和生产流程如何影响冻结 Skill 的 held-out 泛化、结果方差、回归率与生成成本？

这里的创新不是“首次提出 Skill 生成”，而是把三个变量放在同一个受控实验里：训练任务数量、经验生产流程、冻结 Skill 的未见任务表现。`OfficeQA` 和 `SpreadsheetBench` 可以提供真实文件任务场景，但“长程”只能作为场景条件，不能单独作为新颖性证明。

### 11.4 必须防止的实验混淆

| 混淆 | 错误做法 | 正确做法 |
|---|---|---|
| 小样本定义 | 从已有 69/80 条成熟 Skill 中抽 5 条就叫 5-shot 训练 | 把它明确叫“经验池抽样/合并规模实验”；真正的小样本生成需从 5 个任务重新生产轨迹 |
| 数据泄漏 | 用训练任务调参、再把同一题放进 held-out 结论 | 固定任务 split，测试 UID 在整个 Skill 生产过程中不可见 |
| 预算混淆 | 小样本组调用更多轮次或生成更长 Skill | 固定或报告 rollout、验证、合并调用数和 token 上限 |
| 长度混淆 | AEV Skill 更长，直接把得分差当生成质量 | 至少增加长度匹配或截断敏感性控制 |
| 随机性 | 每个规模只跑一次并挑最高分 | 每个规模固定多个随机子集/重复，报告均值、区间和全部结果 |
| 评测污染 | 用验证集反复选 Skill，再把验证分数当泛化 | 用独立 held-out test，验证集只用于选择，测试只在最后一次使用 |
| 运行时漂移 | 混合 2026-08-12 前后的 evaluator/runtime 结果 | 锁定模型、推理模式、上下文、工具、评分器和 provider 版本 |

### 11.5 比原回答更稳的最低可行设计

建议分两级，不要直接承诺完整曲线：

**一级：低成本经验池规模实验。** 从同一批已经验证过的源经验中构造 `N=5,10,20,40` 的多个固定子集，使用完全相同的合并器、Skill 长度预算和测试协议。它只能回答“已有经验在不同池规模下如何被组织”，不能回答端到端 Skill 生产是否更数据高效。

**二级：小规模端到端确认。** 如果一级出现稳定趋势，再选择一个规模，例如 `N=10` 或 `N=20`，从原始任务执行开始重新跑 AEV 与对照流程，并保留独立验证/测试划分。这一步才可以把结论升级为“少样本 Skill 生成”。

### 11.6 本轮最终判定

该方向**不是没有价值，也不是现成的全新算法方向**。它可以成为一篇以实验为中心的研究，前提是题目改为“数据规模受限下长程文件任务的 Skill 生成与泛化评估”，主贡献写成受控实证发现，而不是宣称首次提出轨迹、验证、归因或泛化机制。若只使用现有最终分数，证据不足；若完成多规模、重复、预算和长度控制，才有可能形成比“AEV vs SkillOpt”更稳的论文主线。
