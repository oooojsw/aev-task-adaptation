# 思路二：成为独立论文前必须补的实验

## 目标

把“一个追平观察”变成“在固定预算设计下可重复检验的计算替代关系”。

## 最小实验矩阵

固定 OfficeQA 训练题、验证题、测试题、Skill 初始版本、合并器和测试 harness，只改变生产模型与训练预算：

| 条件 | 生产模型 | 经验生产方式 | token 预算 | 目的 |
|---|---|---|---:|---|
| A | MiniMax M2.7 | 原生 SkillOpt rollout | 低/中/高三档 | 建立弱生产者预算曲线。 |
| B | MiniMax M2.7 | AEV 长程验证经验 | 低/中/高三档 | 检验长程验证是否比单纯增加 rollout 更有效。 |
| C | GPT-5.5 或明确强生产者 | 原生 SkillOpt rollout | 至少一档 | 建立强生产者基准。 |
| D | 无 Skill | 不训练 | 0 | 确认所有部署端自身 baseline。 |

每格至少 3 个独立训练种子；同一冻结消费者上统一测试。部署指标包括 hard accuracy、有效题数、失败率和配对差异。

## 必须记录

- 生产模型与准确版本；
- 训练/验证/测试 UID 清单和 seed；
- prompt、completion、cache-read token；
- 墙钟时间、调用数、失败和重试；
- 每个经验包是否通过验证、被合并或被拒绝；
- Skill hash 与最终冻结评测结果。

## 可回答的问题

完成后可回答：同一弱生产模型多花计算，是否能稳定缩小与强生产者的部署差距；以及 AEV 的验证计算是否优于“同模型、同预算、只增加普通 rollout”。

## 普通二区的精简路线

如果目标是普通二区，而不是证明严格的通用缩放规律，本篇应收紧成一篇**系统比较论文**：

> 在相同 MiniMax M2.7 生产来源下，AEV 的长程验证式经验生产，是否比 SkillOpt 原生训练更能产出可跨 GPT 消费者迁移的 Skill？

官方 GPT-5.5 Skill 只作为外部性能参照，不再承担公平强生产者因果对照。这样不需要重新用 GPT-5.5 做完整可审计训练，也不需要做 1x/2x/4x/8x 缩放曲线。

### 必做，不能删

1. 冻结并公开 OfficeQA 的 train/validation/test UID hash、最终 Skill hash、评测 config hash；自动确认最终 Skill 不含 test UID/答案片段。
2. 只对两个核心条件各做 3 次独立训练：`MiniMax + SkillOpt 原生训练` 与 `MiniMax + AEV + merge-as-opt`。不挑最好一次；报告均值、标准差和全部 run。
3. 对每个最终 Skill，统一使用现有 OfficeQA 官方 172 题和至少 GPT-5.4、GPT-5.5 两个消费者评测；SpreadsheetBench 现有完整结果作为第二任务支撑。
4. 报告 Skill 长度、实际 prompt token、截断率和已知训练 token/调用/时间；成本缺失项明确标为未知，不做成本更低的主张。
5. 保留 MiniMax 作为消费者无稳定收益、SpreadsheetBench 运行时变更、合并高方差等负结果。

### 建议做，但资源紧张可删

1. 只做一个最小机制消融：把 AEV 的“只保留通过验证的经验”关掉，其余流程不变，跑 1--3 次。它比拆五个模块划算，足以说明验证门并非装饰。
2. 对 OfficeQA 的改善/退化样本做 20--40 题人工盲审，检查 judge 与答案抽取是否合理。
3. 将四种 Skill 统一裁到一个较宽松的长度上重测一小个代表性消费者，排除“只是提示词更长”。

### 可以明确不做

- 不做第三个完全不同的大型数据集；OfficeQA 与 SpreadsheetBench 已足以构成两类任务证据。
- 不做 MiniMax 的 1x/2x/4x/8x 预算缩放曲线；那是思路三的工作。
- 不做重新训练的 GPT-5.5 公平控制组；官方 GPT-5.5 Skill 仅作为外部效果锚点。
- 不做完整碳排放、真实美元成本或“每提升一点成本”排名；现有账本不足，且这不是本篇主张。
- 不扩展到大量 Qwen、Gemini、DeepSeek 消费者；它们可留附录或后续工作，主文只保留最干净的 GPT 消费者结果。
- 不拆解所有 worker、lead、reviewer 的单独贡献；这会把系统论文变成昂贵且难收敛的机制论文。
