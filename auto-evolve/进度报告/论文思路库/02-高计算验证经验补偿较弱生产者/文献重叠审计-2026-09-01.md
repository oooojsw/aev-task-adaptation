# 文献重叠审计：生产者能力—验证计算替代

最后核验：2026-09-01

## 这篇潜在论文真正要问的问题

不是“弱模型能不能生成 Skill”，也不是“多花 token 是否有效”。问题应严格限定为：

> 固定同一 Skill 生产模型、训练任务、Skill 长度和部署评测时，将训练预算从普通 rollout 转投到长程执行、产物验证、失败诊断和经验合并，是否能以可测方式缩小该生产者与更强生产者所产出 Skill 的部署差距？

这里的计算发生在 **Skill 生产期**，最终产物是一个冻结、可部署的静态 Skill；不是测试时临时多采样，也不是给消费者模型增加工具轮次。

## 初步新颖性判断

这不是一个已被完全占据的命题，但只有在以下限定下才可能成立：

1. **生产期而非测试期**：预算用于离线制造可复用、冻结的 Skill，而不是每道测试题额外搜索或临时合成。
2. **能力—计算替代而非单点胜负**：比较同一 MiniMax 生产者在不同预算和机制下的曲线，并用可审计强生产者作为锚点；不是挑一个 GPT-5.5 消费者上的最高分。
3. **同预算机制对照**：普通 rollout 与完整 AEV 必须在训练 UID、初始 Skill、调用/token 上限、最终 Skill 长度和消费者评测上对齐。
4. **部署而非训练内分数**：报告冻结 Skill 在未见测试题、多个固定消费者上的表现，同时完整保留负迁移。

缺掉任意一条，这篇文章会退化为已有论文的一个工程复现或单次案例。

## 现有数据能支持什么

OfficeQA 现有结果可以作为 pilot：同由 MiniMax M2.7 生产的 AEV merge-as-opt 在 GPT-5.4-mini、GPT-5.4、GPT-5.5 消费者上优于现有 optMiniMax M2.7 Skill；其中 GPT-5.5 消费者的 66.86% 高于官方 GPT-5.5 Skill 的 65.12%。

它只能支持：**存在值得检验的能力补偿信号。**

它不能支持：

- AEV 已证明用 token 替代模型能力；
- MiniMax 已与 GPT-5.5 等价；
- AEV 比 SkillOpt 高效或便宜；
- 该现象对所有消费者、所有任务或所有运行时成立。

## 投稿前的最小实验

所有条件固定训练 UID、selection UID、test UID、初始 Skill、最终 Skill token 上限、消费者、单轮无工具 Oracle 输入、评分器和运行时版本。

| 生产者 | 经验机制 | 预算档 | 独立训练数 | 作用 |
|---|---|---:|---:|---|
| MiniMax M2.7 | 原生 SkillOpt 或普通 rollout+同一合并器 | 1x, 2x, 4x | 3 | 普通计算曲线 |
| MiniMax M2.7 | 完整 AEV | 1x, 2x, 4x | 3 | 验证计算曲线 |
| MiniMax M2.7 | 去验证 / 去失败诊断 AEV | 至少 2x | 3 | 机制归因 |
| 可审计强生产者 | 对齐的普通生产流程 | 至少 1 个预算档 | 3 或明确不可得 | 强生产者效果锚点 |

每个训练点必须保存：输入/输出/缓存 token、调用数、墙钟时间、验证通过经验数、被排除的基础设施记录数、Skill hash、Skill token 数和全部逐题结果。正式论文报告均值、标准差、最差一次和每个消费者的配对差异；不能以“三次取最高”作为科研主分数。

## 推荐标题与一句话贡献

候选标题：**Can Verified Experience Compute Substitute for Skill Producer Capability?**

中文工作标题：**验证式经验计算能否部分替代 Skill 生产模型能力？**

若实验成功，允许的核心表述是：

> 在受控的离线 Skill 生产设置中，验证式经验计算比同预算普通 rollout 更有效地提升由固定生产者生成的冻结 Skill，并在若干消费者上缩小其与强生产者 Skill 的部署差距。

“部分替代”“受控设置”“若干消费者”缺一不可。
