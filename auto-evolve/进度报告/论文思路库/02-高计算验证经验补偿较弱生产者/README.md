# 思路二：生产者能力—验证计算替代

## 候选标题

**Can Long-Horizon Verified Experience Compensate for a Weaker Skill Producer?**

中文工作标题：**高计算验证经验能否补偿较弱的 Skill 生产者？**

文献重叠、精确问题与最低实验门槛见：[文献重叠审计-2026-09-01.md](./文献重叠审计-2026-09-01.md)。

## 一句话假设

与其把较低能力的生产模型直接当作强模型的廉价替身，不如给它更长程的执行、验证、失败诊断与合并预算；由此生成的 Skill 可能在固定部署测试中接近强生产模型生成的 Skill。

## 当前最强观察

在 OfficeQA 的固定单轮、无工具、Oracle 文本测试中：

- AEV 使用 MiniMax M2.7 作为经验生产者，并经 `merge-as-opt` 形成 Skill；
- 当测试消费者是 GPT-5.5 时，该 Skill 得到 `66.86%`；
- SkillOpt 官方 GPT-5.5 Skill 在相同测试口径下得到 `65.12%`。

这是一条值得进一步验证的观察，不是“弱模型已经等价于强模型”的证明。

## 允许的表述

> 在一个固定任务和固定消费者条件下，更长程的验证式经验生产，使 MiniMax M2.7 产出的 AEV Skill 达到与官方 GPT-5.5 Skill 相当的部署分数。

## 禁止的表述

- 不说“弱模型只靠堆 token 一定追平强模型”。
- 不说“AEV 更省 token”或“性价比更高”。
- 不说所有测试消费者、所有任务或所有合并路径都能追平。
- 不说 GPT-5.5 是客观意义上的“最强模型”；当前只知道它是本实验中的强生产者对照。

## 必须与思路一分开

思路一强调经验的可审计性与迁移边界；本思路只研究“生产者能力”和“长程验证计算”之间的替代关系。

## 论文要真正回答的问题

这里的“弱”和“强”，不是直接比较聊天能力，也不是比较最终做题的消费者模型。它们只指 **谁来生产经验和 Skill**：

- 强生产者对照：SkillOpt 官方流程中用于产出官方 OfficeQA Skill 的 GPT-5.5；
- 弱生产者：MiniMax M2.7；
- 固定部署消费者：分别用 GPT-5.4-mini、GPT-5.4、GPT-5.5 在同一冻结测试集上读取最终 Skill 后答题。

论文的准确问题是：

> 在相同训练任务、相同最终评测和固定部署设置下，能否把较弱生产者节省下来的模型能力，部分替换为更长程、可验证、会保留失败证据的经验生产过程，并让最终 Skill 缩小与强生产者产物之间的差距？

这不是“多花 token 是否有效”的问题。AEV 所额外投入的，是会改变经验质量的闭环：执行、验证、失败归因、证据留档、拒绝无效修改和合并。因而论文应把它称为 **verified experience compute（验证式经验计算）**，而不是普通 token 扩容。

## 现有结果应如何读

OfficeQA 的三行结果可以支持一个清楚但克制的图景：

| 固定测试消费者 | MiniMax 原生 SkillOpt Skill | 官方 GPT-5.5 Skill | MiniMax AEV merge-as-opt Skill | 对官方差距的弥合比例 |
|---|---:|---:|---:|---:|
| GPT-5.4-mini | 39.53% | 50.58% | 48.26% | 79.0% |
| GPT-5.4 | 29.65% | 59.88% | 56.98% | 90.4% |
| GPT-5.5 | 56.98% | 65.12% | 66.86% | 121.4% |

弥合比例定义为 `(AEV - MiniMax 原生) / (官方 GPT-5.5 Skill - MiniMax 原生)`。当官方分数不高于 MiniMax 原生时，此指标不适用；它不是一个普适能力分数。

这张表的正确结论是：在 OfficeQA 的这组受控条件下，MiniMax 的 AEV 经验生产在三个消费者上都明显优于 MiniMax 的原生 SkillOpt 训练产物，并把它与官方 GPT-5.5 Skill 的部署差距大幅缩小；GPT-5.5 消费者上出现了略高于官方 Skill 的一次观察。

它不能推出 MiniMax 在所有数据集或所有消费者上都更好。现有 MiniMax、Qwen 等消费者的异质结果必须保留为负例或边界条件，而不能挑掉。

## 论文的因果链

要避免把“更长程”误写成唯一原因，正文应明确区分四层：

1. **生产者能力**：产出初始执行方案、诊断和经验文本的模型。
2. **经验计算机制**：普通单次/多次 rollout，或 AEV 的执行-验证-诊断-筛选-合并闭环。
3. **最终 Skill**：冻结、哈希并在评测前固定的经验包。
4. **消费者部署效果**：固定测试模型在冻结 OfficeQA `valid-unseen` 172 题上的正确率。

我们的主张只落在第 2 层改变后，第 4 层出现的差异；不能把消费者强弱、不同 runtime、不同上下文长度或不同工具权限混进同一结论。

## 最小可发表实验矩阵

现有表适合作为 pilot，不足以单独承担主结论。最低限度需要补齐以下受控矩阵：

| 对照 | 生产者 | 机制 | 预算 | 重复 | 目的 |
|---|---|---|---|---:|---|
| A | MiniMax M2.7 | 原生 SkillOpt rollout | 低/中/高 | 3 | 普通经验的预算曲线 |
| B | MiniMax M2.7 | AEV 验证式经验 | 低/中/高 | 3 | 验证闭环的预算曲线 |
| C | 强生产者 | 原生或官方可复现流程 | 对齐预算 | 3 或可审计固定产物 | 强生产者锚点 |
| D | MiniMax M2.7 | AEV 去除验证/去除失败诊断 | 对齐预算 | 3 | 证明收益不只是更多生成 |

所有格子必须固定：训练 split、验证 split、最终测试 split、消费者、Oracle 文本输入、单轮无工具、输出上限、并发、评分器版本。每次训练还要保存模型版本、seed、Skill hash、原始/缓存 token、调用数、墙钟时间、验证通过的经验包数和失败包数。

## 建议的论文骨架

1. **问题**：强模型能产出较好 Skill，但不总是可用或可承受；较弱生产者能否通过验证式经验计算获得可部署的 Skill。
2. **方法**：定义 AEV 的闭环和它产生的可审计经验，而不是把系统写成一个“更多 agent”的堆叠。
3. **实验设置**：严格冻结训练、Skill、消费者和评测；解释生产者与消费者的区别。
4. **主要结果**：差距弥合表、每个消费者的配对差异与置信区间。
5. **机制消融**：移除验证、失败诊断、合并/回撤后的变化；并报告 token、时间和有效经验数。
6. **边界与失败案例**：MiniMax/Qwen 的负迁移、跨 runtime 不可比的历史结果，以及不声称成本优势。
7. **结论**：验证式经验计算是可能的能力补偿通道，强度与边界仍需通过预算曲线验证。

## 审稿人最可能追问的点

- **“只是多花了 token。”** 回答需要同预算普通 rollout 对照和移除验证/诊断的消融。
- **“官方 Skill 的来源与成本不透明。”** 不能比较成本；把官方 Skill 定义为效果锚点，并补可审计强生产者对照。
- **“只是在 GPT-5.5 上偶然更高。”** 需要三次独立训练、置信区间、逐题配对检验，并如实报告负迁移。
- **“消费者模型泄露或测试条件变了。”** 每个 run 保存完整 config、Skill hash、数据 UID 清单、runtime 指纹和评分器版本。
- **“这是 scaling law 吗？”** 不是。本篇只报告能力补偿现象；预算-能力可预测规律属于思路三。
