## B. 共同流程、模块与验收边界

共同路径：任务输入 → 方案解释及能力核对 → 冻结 Plan 与协议 → Campaign 内规划执行 → 证据汇集及候选修订 → 所选检查及可选独立执行 → 正式判定 → 反馈、继续或冻结交付。

| 部分 | 精确职责 | 当前代码入口 |
| --- | --- | --- |
| 批量调度器 | 多任务启动、观察、恢复及阶段衔接 | `scripts/run-benchmark-orchestrator.ts`、project-batch |
| 任务演化控制器 | 单项任务跨轮、验收次、候选及停止 | `long-task-campaign/runner.ts` |
| 轮内任务调度器 | 工作单元执行、局部重试及重规划 | `long-task/runner.ts` |
| Planner / Executor | 规划、执行和形成工作证据 | 原角色入口与 `task-adaptation/context.ts` |
| Workers / Lead | 分析证据、统筹和修订候选 | 角色窗口、`invocation.ts`、advice |
| Reviewer / 失败诊断 | 审阅与失败分析，不产生正式通过判定 | review/diagnostician 入口、feedback |
| 独立执行模块 | 使用候选产生真实应用结果；按协议可省略 | protocol executor、Blank Eval、Direct Chat |
| Checker | 针对候选或产物，按脚本、裁判等机制检查 | `protocol-plugins`、validation-engine |
| 版本选择与交付 | 保存合格版本，按 first_pass/best_pass 规则冻结 | `selection.ts`、`delivery.ts` |

“空白执行 Agent”是执行角色，“空白执行模块”管理实际执行，“Skill 独立验收”包含规定检查、执行及判定。检查对象和检查方式分别配置。Skill 内容的泛化器功能与答卷的验证器功能分开；模型裁判或脚本均可承担各自允许的检查。Reviewer 建议、诊断结论不能替代 Checker 的真实判定。

候选版本、当前探索版本、最好合格版本和最终交付须对应实际文件和证据。通过一次验收不自动等于稳定通过或泛化；不得保证每轮收益增加。标准、权限与预算在运行前绑定，训练侧不能自行放宽标准。

### C1. 当前 Consolidation 实例

- 输入：冻结的来源 Skill 与任务材料；来源数量、实际 UID、通过标签及指纹由运行清单证明。本树不把合成50题当成真实50份已验收来源。
- 交付物：单份 `DIRECT_CHAT.md`。当前 Profile 为不超过 5000 个 NFC 规范化非空白 Unicode 码点；这是该适配的约束，不是系统级字节或 token 上限。
- 应用检验：冻结50个用例，各自独立单轮、无工具答题；受信脚本判定实际答卷。
- 修订：发布允许披露的完整逐题训练反馈，Workers / Lead 按权限分页读取；不将私有答案、判题脚本或账本当作训练资源。
- 选优：只比较正式合格候选的可信 `pass_rate`，按 `best_pass` 保留所选版本；盲测另行冻结，训练回测不代替泛化评价。
- 入口：[归纳优化原始设计](../进度记录/2026-10-17-多Skill归纳优化任务改造计划.md)、[配置说明](../orchestrator/task-adaptation/consolidation/README.md)、[当前代码审计及入口](../进度记录/2026-10-19-真实代码审计与50题合并入口说明.md)。原计划状态是历史状态，当前完成度看下节。

## F. 防止持续局部修补的候选策略（2026-10-19）

用户提出增加防局部最优策略。本轮核对现有源码，并读取Karpathy autoresearch、AIDE、AI Scientist-v2和ShinkaEvolve的官方仓库与部分源码。

当前已具备最好合格交付版本、探索记忆、分析角色和停滞停止；尚未接通通用的历史父候选选择、新分支工作区及停滞后受控再探索。探索树不据此称MCTS，禁重复提示不据此称物理封禁，不能承诺逃离所有局部最优。

候选决定：采用轻量候选档案、显式父选择及新分支实例化，优先借鉴AIDE的草拟/调试/改进操作与ShinkaEvolve的多起点档案；保留当前Campaign、正式验收、全局预算和交付规则。提高温度、完整MCTS、并行种群及交叉不作为首版必需项。**本轮仅调研和设计，待后续实施指令；没有改变运行行为或启动API。**

验收要求：探索与交付分离、硬预算不重置、旧成果不覆盖、反馈绑定真实候选、故障不误判停滞、切换和恢复幂等、Skill与报告规则分别生效。正式方案与来源均在上方链接文档中。
