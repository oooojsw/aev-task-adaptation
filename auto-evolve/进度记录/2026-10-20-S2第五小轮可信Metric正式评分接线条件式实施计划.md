## 0. 总目标和准确完成状态：严守证据边界

**用户想看到的最终行为**：某个冻结 Plan 原路线运行多次，真实独立执行得到结构化产物、Checker 按完整协议验收合格、正式 `best_pass` 指标成为可比较的连续数据。AEV 不要求额外评分模型；它以固定 `minimumDelta / minimumObservations / patience` 判断是否在原路线停滞；达到真实停滞且满足 `f` 和资源准入时，真正激活一次已有备用路线，继续执行、选择正式最优候选并交付。未达到停滞的任务继续原路，到 `h` 才依 `window_exhausted` 考虑换路。

## 3. B1 / 任务卡 B：可信 Metric 的“同一评分协议身份”接入正式关闭 Round

**主生产文件**：`auto-evolve/orchestrator/task-adaptation/exploration/evaluation.ts::archiveRound`，`exploration/lifecycle.ts::closeTaskExplorationRound`。  
**目标**：继续复用 `archiveRound` 的正式验收和选优证据，不改变 V1 `Observation`，只在 V2 metric 关闭时将真实值及可比身份交给现有 `decideV2`。

### B.1 先验清现有数据，不能造一份假的“模型评分”

`evaluation.ts::archiveRound` 当前已经使用：
- `round.finalAcceptanceSignal`、`round.roundClosure`、`verifyCompletedCampaignAcceptance` / `readCompletedRejectedCampaignPass`；
- `taskFeedback(bound,...)` 获得 `actual.view.status`、`actual.view.protocolFingerprint`、`actual.view.receiptFingerprint`；
- `taskSelectionSource(spec, root, feedback)` 只在正式 passed 且 `best_pass` 时从**签过 hash 的实际产品 JSON**取数值；
- `return immutable({candidate,observation,receipt})`；原 V1 `observation.metric` 是标量。

所以本轮必须保持：**正常 rejected 没有 metric，仍算正常关闭 Round；正式 passed 必须具有由选优器读取的有限数值；平台/数据/评分故障不能伪造成 rejected + score=0。**

### B.2 推荐最短代码

1. 在 `evaluation.ts` 做一个**只读且无 I/O 的小 helper**（也可放同文件内），只为 `cfg.schema==="aev.exploration-policy.v2" && cfg.trigger.kind==="metric"` 生成稳定 `comparison`，例如：
   
   ```ts
   const comparison = fingerprint({
     schema: "aev.exploration-metric-comparison.v1",
     boundPlan: bound.fingerprint,             // 冻结原任务/材料，不是当前候选 hash
     protocol: actual.view.protocolFingerprint, // 冻结 Checker/Executor 绑定与实现
     task: entry.taskID,
     phase: entry.phase,
     metric: bound.plan.selection.metric,
     direction: bound.plan.selection.direction,
   })
   ```
   
   这个结构是推荐最小基线，不是证明所有任意协议一定可比。**B1 A 已限制固定脚本执行和冻结材料**；如代码审查发现实际输入中存在不受该 fingerprint 约束的评分用例、模型推理配置或协议变量，必须把该真实冻结条件加入 comparison，或者继续拒绝相关 Host 模式。**候选正文、每轮 answer、round、sourceRunID、receipt、当前产品 hash 都不能进 comparison**，否则不同 Round 永远无法比较。
2. 不要为了 comparison 新读用户私有材料正文，也不要持久化私有答案。`bound.fingerprint` 本身已包含冻结 `Plan`、资源路径和源材料初始 SHA；`actual.view.protocolFingerprint` 来自冻结的 `protocol.snapshot.json`，包含协议 Check / Executor 绑定及实现。
3. `archiveRound` 返回原有数据之外只加一个**可选** `comparison` 字段（只有合法的 V2 metric 且 passed 有正式 metric 才加）；**V1 返回值/Observation 持久化形状与指纹不变**，V2 window 仍只传无分数的 ClosedRound。不得把 V2 新字段写入旧 `aev.exploration-campaign.v1` state。
4. `lifecycle.ts::closeTaskExplorationRound` 已经有 V2 构造：
   
   ```ts
   const closedRound: ClosedRoundV2 = {
     campaign: scope.campaign,
     round,
     branch: input.generation === 1 ? "alternative" : "original",
     closure: observed.observation.closure,
     receipt: observed.receipt,
     verdict: observed.observation.verdict,
   }
   ```
   
   在此处**仅当 V2 metric 且真实 observed.observation.metric 与 observed.comparison 都存在**时追加：
   
   ```ts
   metric: { value: observed.observation.metric, comparison: observed.comparison }
   ```
   
   不得调用其它评分模型补分、不得用 Checker 摘要或当前 round 编号填 comparison。删掉原 `lifecycle.ts` 对 metric 的“尚未实现”拒绝，**但前提是 B1 A 的实际 Host 资格已经完成**。
5. `decideV2` 的 `window/metric` 阈值、`patience`、`firstPass`、`remaining`、`receipt` 去重规则**不修改**；生命周期仍存 `StateV2.rounds`、`decision.identity`、原 `scope`、候选归档和激活文件。`best_pass` 正式排序仍由 `selection.ts::chooseTaskVersion` 决定。
6. **评分缺失与比较身份漂移的结果必须诚实分类**：已经进入决定器的完整 passed 闭轮缺 `metric`，它应返回 `hold/metric_missing`；若正式选优器在读取缺失指标时就抛出错误，则由现有 Campaign 故障处理为失败/阻断，**不得绕过它改成常规 rejected 或另启一次模型请求**。旧正式版本仍然保留。两种实现都不能继续 activate。
7. 只复用已归档正式证据。**恢复**时若第 n 轮已经提交 `StateV2` 决定，原 `findTaskExplorationDecision` 返回已存结果；不通过重新运行模型或重新评分覆盖 identity。
