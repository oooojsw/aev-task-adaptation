## 1. 明确目标与反目标

核心需求：AEV 仍沿用原 Task-Adaptation Campaign 的 Planner／Workers／Lead／Independent／Checker 及 best_pass。对 50 个独立 Direct Chat 训练用例，每次真实评测后，获授权的 Lead 和 Worker 均可以**自主定位、反复按需阅读全部 50 题的所有获准公开内容**，包括题目材料、实际模型回答、判题结果和可披露诊断；不能被“最多 3 个样例”或一个固定上下文长度人为截断。每轮优化仍只写单一 DIRECT_CHAT.md，沿用原 <=5000 NFC 非空白字符限制。训练用例不等于私有 oracle/盲测，严禁泄漏私有标准答案、评分脚本与凭证。

同时为长远复用建立一套统一的授权模型：**Principal（Agent、Host Service、Checker 等主体） × Logical Resource（具身份、版本的资源） × Action（读／写／搜索／执行／发布） × Context（Campaign、Task、阶段、轮次、Worker ID、数据目的）**。Role 是默认策略，运行身份等属性进一步约束；结果编译为各执行端能实际落实的 grant，而不是 Prompt 里的倡议。

明确不做：不新建优化 Agent／第二个训练循环；不把所有旧角色改成能读私有 Oracle；不替换 Checker 正式判题、预算账本、OpenCode restricted ACL 或 OS 沙盒；不在本任务重写整个 Validation Engine；不要求 50 个 case = 50 个物理文件；不把 Agent 拥有可读路径误写成实际工具读取已验证；不因长文自动省略 case、只保留前三题或复制私有 trace。

## 3. 最小架构：统一控制面，不统一重造所有执行机制

~~~text
宿主冻结 Task Plan / Campaign / Profile / Policy（唯一身份来源）
                        |
                  Resource Registry
           逻辑资源 -> 安全副本 / 版本 / manifest
                        |
          Access Policy + Authorize/Compile
     Principal + Action + ResourceID + Runtime Context
                        |
             不可变、可审计的 AccessGrant
                /            |             \
       OpenCode restricted   Scoped Reader   Protocol/Host
       read/list/edit ACL   分块读取/搜索     发布/评测权限
~~~

**一个权限决策中心，多个既有执行端。** Policy 只决定谁可以访问什么；Renderer/Publisher 只决定哪些字段是可披露数据；Tool ACL 及 Runtime 负责真正阻断访问；原子预算账本与模型请求幂等保持独立，不能靠矩阵代替。

### 3.1 统一主体与上下文（Host 填写，模型无法自报）

Principal：kind = agent | host_service | checker | independent_runner | audit_service，roleID，instanceID，workerID（可选）。Context：taskPlanFingerprint，campaignID，taskID，phase，round，pass/attempt，stage，protocolFingerprint，profileID，candidateSHA，datasetSHA，policySHA。主体种类与角色不能混用；独立执行器和 Checker 分开，Host 也没有给模型直接使用的“万能角色”。

### 3.2 统一资源登记

ResourceDescriptor：resourceID（逻辑身份，不是绝对路径）、ownerCampaign/task、kind（source_skill | candidate | training_case_feedback | private_oracle | score_summary | budget_ledger | runtime_advice 等）、sensitivity（public | training | internal | private_oracle）、allowedPurpose、immutableVersion/sha256、storageBinding、accessMode 与 provenance。未来提供版本化、只读 logical collection，其中 case 以稳定 caseID 寻址，不按物理文件个数做权限规则。

基础 role policy 可由 profile_v2 的 RoleAccessPolicy / InformationViewDescriptor 扩展成共享接口，而不是平行复制。**不能只靠 sensitivity=training 决定放行**，它只描述资源属性；必须同时校验 Task Plan runtime.feedback 与用户/Host 批准的披露 Policy、任务所属和身份。读取的对象必须是经过 sanitization 的发布资源，而不是原始判题目录。

### 3.3 单一决策与编译契约

~~~ts
type AccessRequest = {
  principal: { kind: string; roleID: string; instanceID: string; workerID?: string };
  context: { planSHA: string; campaignID: string; taskID: string; phase: string;
    round: number; pass: string; stage: string; policySHA: string };
  resourceID: string;
  action: "read" | "write" | "search" | "execute" | "publish";
};
type AccessDecision = { allowed: boolean; reasonCode: string; policySHA: string;
  resourceVersion?: string; grant?: AccessGrant };
~~~

仅为接口设计草案，不要求照抄具体字段名称。无规则／身份不完整／版本漂移时 deny-by-default。grant 只允许所选资源的指定操作；grant 绑定调用身份、资源版本、Campaign、round/pass、生成时的 policy，具有单次 invocation/session 生命周期。新旧 profile_v2 共享规范化与安全路径验证（含 lstat/realpath/link/overlap），不依赖模型送入的 path。

**两条实现路径（不可错接）**：
- 对普通大小的受控文件，统一授权器编译为具体 canonical read/edit 路径，再由 OpenCode restricted read/list/edit 执行。
- 对超大文字或多模态资料，统一授权器为一个注册的逻辑资源颁发 scoped_reader 能力，Host 受控读取并返回小块；原始大文件路径不进入模型 ACL。该能力是完整授权的另一种执行端，不是绕过 File ACL 的后门。

第一期将 profile_v2 的工具函数提取/包装成通用能力并**不改变旧 schema 对外语义**。不要求所有老路径同时调用新中心；建立 feature flag 和差异审计，逐步迁移。

## 5. 超大题目：不丢数据的发布与检索协议（关键）

### 5.1 完整数据与模型上下文彻底分离

**完整保存 ≠ 一次性塞进模型上下文**。受控 publisher 必须保存每个已完成用例的**完整获授权公开语义内容**：caseID、可公开题面／材料／引用素材、实际提交给模型的获准请求视图、真实模型回答（不以摘要替代）、passed/score/errorCategory 与允许公开的 validator 诊断。50/50 元信息必须可枚举，失败题和成功题均可按需访问；不要宿主代选 3 题。

不会擅自披露的内容：privateOracle、正确答案或判题脚本/路径、validator 内部 raw JSON、模型凭证、内部日志、原始未筛查 stdout、系统绝对路径、盲测数据。字段由**显式白名单 schema + host policy**映射得到，绝不把 raw audit 对象解构扩展进训练文件。对于题目确实依赖合法训练标准答案、特殊元数据的情况，必须先有独立的明确披露策略，不能靠猜测自动公开。

**不是所有材料都能无损地表示为文本**。原题若含图像、PDF、二进制素材或超长表格，发布训练视图应保留原始获许可内容的 bytes/sha/媒体类型和完整对象引用；文本检索提供按需阅读、搜索，非文本通过专用受控资产访问接口获取，不把它们假装变成已经被模型全文理解。检查当前 DirectChatDatasetBundle 的 materials/message content 来源，不能只复制简化过的 audit 文本而误称“原题完整”。

### 5.2 逻辑索引与存储组织不耦合

向 Agent 暴露：一个 compact index（exactly 50 case IDs、score、总量、可公开字段类型、资源版本、可按需读取的 API）；实际保存可为每 case 独立文件、内容寻址块、压缩存储或其他已验收后端。**禁止固定“每 10 题一个文件”或“每题单文件必须小于 8 MiB”的设计假设**。物理分片大小由 host 根据安全的最大请求、I/O 和索引开销决定；即使某一题非常大，也能通过可验证的 offset/chunk 持续读取。50 题枚举不需要把它们的内容都加载到单个 Prompt。

索引字段至少：schema/policySHA、campaign/task/phase/round/pass/run、candidateSHA、datasetSHA、modelID、expectedCaseCount=50、完整 caseID 唯一清单、每 case 真实评分、public payload manifest/bytes/content SHA、segment/chunk 索引、source-material mime/bytes/hash、publisher fingerprint、完成标记。Manifest 对存储块 hash 与组合顺序有确定定义；所有资料不可变、按 attempt/version 隔离；原子提交 marker 最后写入。宿主生成公开副本与 manifest 并检查完成后，才允许读。

容量边界：不要静默截断、丢最后几页或输出“50/50 已发布”而实际缺块。设置**可配置的合理存储额度、单次读取额度、每次会话总成本额度、最大并发请求以及数据源预检**。若真实源过大超过已批准储存/服务预算，进入明确的 unsupported/needs_budget 或 data_error 状态，完整记录缺失原因，不假装该题已被发布，也不降级只给 3 题；不自动消耗付费模型 API。

### 5.3 分页读取 API（建议新 scoped tool，复用当前工具注册机制）

建议新增通用而非 consolidation 特有的 aev_read_resource 功能，复用现有 aev_local_search 类似的 restricted host custom-tool 注册、环境绑定及证据路径（具体先查 host plugin 入口）。第一次只为 training_case_feedback 开启，后续可复用到大型项目资料。

~~~ts
listResourceCases(resourceID, pageSize, cursor?): { items, nextCursor, total: 50, version };
readResourceChunk({ resourceID, caseID, field, cursor?, maxOutputBytes? }):
  { contentType, dataOrAssetReference, chunkSHA256,
    resourceVersion, nextCursor, eof, returnedBytes };
~~~

两个动作也可合并成一个读取工具，接口是示意。重要不变量：
- grant 绑定确切 Principal/session、Campaign、role/stage/workerID、report SHA 和允许字段；Host 通过自身可信会话绑定主体而不是相信模型请求里填写的身份。
- 每次实际读取复核资源版本、策略、caseID 属于索引、field 白名单、cursor 的完整性与范围；cursor 绑定版本和逻辑位置，旧版本/伪造/跨主体 cursor 拒绝，不使用任意路径作为参数。
- 单次返回严格按 **字节与 token 提示上限**有界，保持 UTF-8 码点安全与结构化内容边界；每块显示序号／精确字节跨度／EOF／nextCursor 和 sha，Agent 可重复逐页读取。单页有界不意味着总可读内容被截断；允许按需覆盖全量合法字节。
- 大 JSON 不能默认整份 JSON.parse 或 readFile 入内存；以流式/分段校验及内容索引读取，读取内容时校验块 hash（必要时重新验证上层 manifest）；防 TOCTOU、符号链接、硬链接和跨目录别名。发布对原始 case 与答案采取流式审计和界限，不把完整大数据复制进模型 Prompt 或工具 scope 文件。
- 对多模态素材返回经过授权、带 mediaType/hash 的安全资源视图；如果目前 OpenCode 工具确实不能消费某种类型，必须返回明确 unsupported_media，不可默默只给图像文件名然后声称读了题目。
- 单次 read 的 event/receipt 记调用身份、报告版本、caseID、字段、offset/长度、chunkSHA、授权 policy、结果；不记录私有内容本身。提供 audit 可证明 Agent 实际请求并读到了哪几段，但不夸称 Agent 必然理解或遍历所有段。
- 分页标志、末页 EOF、按 case 可复原的内容 hash 以及可选择的“coverage 计数”均可测；优化阶段允许 Agent 自主选择阅读顺序，不应由 Host 强迫它必须一次读完所有页才可作出策略建议。

兼容路径：小型发布报告可继续通过现有 exact-file restricted readPaths 供读取；**大型报告不授予原始存储目录的任意读取权**，只授权受限逻辑 Reader。两种方式必须经过同一个授权决策与资源视图，不能因为工具适配产生更高权限。

### 5.4 Search 是可选加速，不是读权限的替代

现有 aev_local_search 8 MiB / 64 MiB / 512 资源上限保留，不为了本任务盲目扩大到无界。超大报告的检索要么走逐段 reader（先完成），要么未来增加由同一 AccessGrant 约束的流式/索引 search API；该搜索应返回 caseID、offset、可追溯引用和 page cursor，索引不能包含未披露字段。命中/输出截断必须显式标注，绝不可把搜索 top-N 当成“只允许看到 N 个训练题”。

## 6. 动态反馈如何流过真实调用链

~~~text
Direct Chat Executor -> Validator traces -> Checker 全量核验
     -> Host-only sanitizing publisher -> versioned FeedbackResource
     -> protocol.training-feedback.json 中可选资源 descriptor
     -> feedback-evidence / taskFeedback 复核身份
     -> authorizeAccess(role, action, resourceID, campaign/round/policy)
     -> authorizeInvocation 以最终 grant 生成 Agent scope
     -> [OpenCode exact read ACL | scoped reader tool] -> Lead / Workers
~~~

**最关键改动点：task-adaptation/invocation.ts。** 它会覆盖 runner 的路径，所以不要只改 long-task-campaign/runner.ts。统一授权器必须在它生成最终 request/scope 之前参与决策并将获准资源合并进 view。小文件生成 read/reference path；大型 case 生成可信 reader 的调用 scope，而不是把原始文件路径写进 readPaths。依旧 allowShell=false、restricted、isolateHostRuntime=true、无继承附件/内联越权、原 task-window 与预算约束保留。空授权不得落回 OpenCode 的 open mode；工具注册与 permissionExternalPaths 不能间接扩大访问。

同轮 pass-02 的 Lead 使用刚完成的 pass-01 反馈；跨轮 N+1 的 Lead/Worker 使用轮 N 最终有效反馈；首轮没有过去的报告，不授予不存在的 runtime resource。防交叉 Campaign、task/phase、candidate、dataset、model、round、pass、策略变更、遗留 report 的混用；旧历史存档恢复时重新核验 manifest 和 policy，但不要发起重评测或追加付费调用。

注意：当前 worker 在 runner.ts 使用 access-profile 生成外部 paths，lead 有 protocolFeedbackEvidence；都可能在真正 authorizeInvocation 时被覆盖。本计划要求通过**统一的调用时 grant**修复两者；仅改 worker 外部 basePaths 不计完成。

## 7. 统一权限矩阵的迁移原则与边界

A. 把 profile_v2 的 InformationViewDescriptor、RoleAccessPolicy、CompiledRoleAccess 与路径安全检查提取/包装成可复用的 policy 和 path adapter，保留旧调用契约、旧 manifest schema 不变。不要复制两份判定代码再声称统一。

B. 注册 resource 与 principal 的 Host API。动态 runtime_feedback 是 frozen task Plan 授权的运行时信息，不修改 plan.resources 或其 hash；Plan 必须显式允许对应 role/stage runtime.feedback、Worker 来源范围与 action.read，禁止把源权限扩大为任意新资源。旧 frozen Plan 无此授权时 fail closed／要求新批准，不能热修改。

C. 新增统一的 compileInvocationGrant；输出要同时覆盖 reference/read/edit/tools/readerScope/audit scope；对每条 grant 要有允许来源和 reasonCode。拒绝要有可审计 reasonCode，但不能将敏感真实路径泄漏给 Agent。局部错误 fail closed，不回退旧 open_book。

D. 第一期 profile_v2 为“策略模型提供者”，Task-Adaptation 为第一个执行适配器，protocol evidence 为一个新资源提供者。旧 AccessProfile、Validation Engine、旧 multi_skill_merge_v2 保留旧执行与判定，先做 shadow diff：同场景生成新旧结果，仅告警和比较，不做联合授权、不扩大读取。后续逐个 Profile 的迁移单独批准、分别测试，再决定是否删除旧代码。若新中心未覆盖全部旧路径，不得宣称“所有权限已迁移”。

E. 权限中心不重新设计 OS sandbox；保持独立执行器只接收被 protocol.selection.executionInputs 批准的公开源、候选；Checker 必须独立持有显式 privateInputs。任何 future arbitrary code/shell 需要独立 OS 级隔离评估，本计划不批准开放。

F. 所有策略按 least privilege 默认拒绝，拒绝不因 Prompt、模型建议、运行时材料、重定向路径或符号链接而放宽。授权对象即使可读取，内容仍被视为不可信数据；拒绝其内嵌“更改权限”“输出秘密”等注入指令。预算账本、host metadata、raw evaluator files 永远不作为作者资源注册。

## 9. 分阶段执行与暂停条件

**P0 审计基线与单一权限模型（优先）**
- 本地 fetch 最新 main；记录 SHA、当前开放 PR、已合并 G2/G3/预算修复；检查本文是否有被后续 Commit 覆盖的断言。
- 确认未来是否只能使用 OpenCode custom tools，检查实际注册接口和 supported media；冻结新 Consolidation 的 Host 披露 policy（哪些训练材料字段可公开，什么属于私有）。
- 仅增加新 policy/registry/decision 的最小抽象与单元测试；对旧 Profile 做 shadow comparison，不接管旧路径。禁止此阶段改旧行为。

**P1 完整训练报告安全出版**
- 在实际 Checker 可信核验后生成冻结索引与全量 50 case 视图；发布源码隔离、流式构建/校验大文件、原子完成标志、版本与散列；对非法字段 fail closed。
- 继续保留 G4 轻量文本摘要，但其 3 个例子**不是全量阅读权限的上限**；独立评测结果不能变成模型提出的伪造分数。
- 用可控 mock 产生 0/50、43/50、50/50，均应有完整索引且可读；validator crash/dataset drift 不能发布虚假 50-case success。

**P2 实际读取工具和最终权限落地**
- 小体量先以 exact-file grants 做 E2E 快速通路；大型题通过 scoped reader 实现 bounded pages + cursor/version/hashes，至少一份超过当前 local-search 单文件 8 MiB 上限的真实合成材料能够完整按页复原。
- 最终 authorizeInvocation 与受限 OpenCode Tool 一致授权，Worker、Lead 读取同一个逻辑反馈资源而非复制另套权限。
- 在同轮和跨轮反馈接力、恢复路径进行数据身份验证；无报告、错报告 fail closed。

**P3 性能、容量和逆向权限验证**
- 多媒体、极长单题、跨页 Unicode、部分下载、断点恢复、非法 cursor、并发两个 Campaign、内存峰值、错误显式可见性。
- 用真实受限 tool call 检查正反权限。固定模型回复只能证明工具边界，不是实际模型能进行优质优化的证明。
- 与旧角色运行日志 diff，禁止未授权改变旧任务权限；保留 feature flag 与快速回退到旧流程的能力（回退时不开放有缺陷的报告读权）。

**P4 其他权限体系按需迁移（本次不作为完成门槛）**
- 经用户另行批准后按一个 Profile 一个 Profile 的顺序迁移旧 access-profile、Validation Engine、Merge Profile；权限集合等价比对、灰度、负例门禁都通过后才删除旧分散决策代码。避免本次为解决 50 题需求而大范围改写全部系统。

## 11. 本地 Agent 交接、风险与决策点

本地编码 Agent 接受方案之前，优先报告三项工程事实：(a) OpenCode 当前 custom tool 的注册及运行时校验如何复用；(b) Direct Chat 训练材料含哪些文本和二进制格式、实际可信原文从哪里取得；(c) Reader 可以先作为读取虚拟资源实现，还是已有合适的精确文件访问通路。若这三项证明建议接口不适用，应保持“完整可读／统一授权／不泄密”的不变量，选择改动更小的适配方式，记录理由即可，**不机械照抄工具 API**。

预计风险：数据副本预检不足会造成显存/内存放大；数据发布混入私有 verdict 字段会泄密；Cursor 被旧会话重用会越权；文件变更与软链接竞态；schema 版本不兼容历史恢复；没有真正经过 restricted 工具的 Mock 会产生假阳性。用文件范围绑定、Host 身份校验、流式 IO、原子写、内容哈希、策略指纹、限额/审计及阴性测试处理。OS 权限不是由矩阵替代。

用户决策权：是否批准本地实施、付费模型实验、生产迁移、扩大权限、合并 PR，均另行确认。本计划为 GitHub 文档交接，云端不修改业务代码、不运行本地测试、不合并 PR。
