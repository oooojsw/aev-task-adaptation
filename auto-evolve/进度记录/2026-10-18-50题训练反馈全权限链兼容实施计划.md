## 0. 目标与系统边界

50 道训练题每轮独立测试并保留完整、可信的逐题结果。Lead 与 Worker 是实际分析者：他们可自主查看 50 题中的任意题目，读取可公开原题/材料、实际模型回答、每题得分与可披露诊断，自行分工、提炼可复用规则、修改 DIRECT_CHAT.md。绝不由 Checker 强制挑选“最重要的 3 个错误”。

保留一个普通 Task-Adaptation Campaign、原 Planner/Lead/Worker/Checker、auto/manual_decision/manual_plan、单一 Skill 文件 <=5000 NFC Unicode 非空白字符、独立 Direct Chat 评测与 best_pass。不要创建另一个 Skill 改写 Agent、第二套学习循环或旧式后置 Merge。

权限必须同时满足：宿主冻结披露策略、冻结 Plan 的 role/stage/worker 权限、当前真实评分及报告身份、受限 OpenCode read/list ACL。Prompt 中有文件路径不代表真正读得到；给目录读权限又过宽。按需读取的精确文件白名单是目标。未批准的原始评分器输入、oracle 脚本/答案、密钥、最终盲测数据必须排除。

## 1. 已确认的关键权限断点

1. task-adaptation/plan.ts 的 roleWindow 基于 windows 的 role/stage/reads/writes/actions/runtime 和 plan.workers 的 workerID/resources/actions 决定可用资源；runtime 已有 feedback/analysis/review。
2. task-adaptation/binding.ts 的 boundWindow 返回最小权限文件列表，冻结 Plan 不允许跨轮随意塞入新资源。
3. task-adaptation/invocation.ts 的 authorizeInvocation 会覆盖原 Campaign 传来的 prompt、referencePaths、permissionReadPaths、permissionEditPaths，启用 restricted 并清空附件。**只在 long-task-campaign/runner.ts 的 basePaths 增加 50 个结果文件，不会让 Task-Adaptation Agent 真正读到它们。**
4. protocol-plugins/feedback-evidence.ts 现能从 protocol.training-feedback.json 提供训练视图和执行 product，验证实际路径、字节数和 SHA；尚无受控导出 50 个逐题文件。
5. protocol-plugins/consolidation.ts 现核验逐题 trace 后返回 aggregate product；Checker 消息约为 Verified X/50。训练侧还不能直接读取完整 50 题报告。
6. long-task-campaign/runner.ts 的 worker、lead、同轮 pass-02、跨轮 N+1 都有反馈入口，但要经 taskInvocation/authorizeInvocation 的最终重新授权。
7. task-profile-access/compiler.ts 的 profile_v2 information view 是单独的权限体系，不能与旧 open_book AccessProfile 或 Task-Adaptation 动态窗口互相代替。
8. orchestrator/opencode.ts 实际 read/list/edit 是独立的白名单，external_directory 也需要验证；最终测试必须进入真实受限工具层。

## 2. L1：来源数据与 Profile/Intake

文件：task-adaptation/consolidation/profile.ts、source-manifest.ts、catalogue.ts。

保留 50 个只读 source Skill 资源、只读源索引、一个可编辑 merged_skill 交付条目。修复作者可读 sources.json 可能包含 caseID 映射的问题：公开索引只保存源 Skill ID/路径/摘要或散列；来源 Skill 到隐藏测试题、oracle 的对应关系单独存 host-only 映射，不进入训练 source_index。

宿主对 multi_skill_consolidation_v1 冻结显式 disclosurePolicy：policy version/hash、允许公开的 case 字段、是否展示题目原文或标准答案、报告 maxBytes、获授权角色/阶段、dataset/model 身份。默认其他 Profile 禁用。题目属于优化训练集不等于判题器内部材料可公开；公开规则由明确政策决定，不由模型要求或未验证的原始 JSON 决定。

## 3. L2：Task Plan 角色窗口、Worker 细分和冻结约束

文件：task-adaptation/plan.ts、binding.ts、context.ts。

Plan 仍以 frozen windows 控制资源访问：worker:explore 和 lead:revise 需同时有 actions.read 及 runtime.feedback；需要诊断的 diagnostician:revise、reviewer:accept 可按批准配置单独开启；planner:explore 默认只接触来源 Skill；independent/blank_agent/executor 默认不授予这份训练结果。

新增的逐题反馈是“后生成的运行时证据”，不能修改 plan.resources 或其 fingerprint。host 按 roleWindow 的 runtime.feedback、真实 workerID、stage、disclosurePolicy 联合签发只读 runtime:feedback grants；与 worker 源资源读权限分别求交，不借此放宽 worker.resources。所有授权 Worker 均可获得完整 50 题的只读结果，不再由宿主预选最多 3 题。

新任务配置必须显式允许该动态反馈；当前 frozen Plan 缺少 runtime.feedback 时禁止悄悄补权限，应重新批准新任务方案而非变更恢复中的 Campaign。

## 4. L3：真实受控评分与公开副本

文件：protocol-plugins/consolidation.ts、runtime.ts、direct-chat/runner.ts。

先由可信 Executor/Checker 核对 exactly 50 unique cases、candidateSHA、datasetSHA、modelID、完整 Skill、50 个真实答案、Validator 结构化 verdict、score/pass_rate、每题 evidence。可信度不够时是 infrastructure/data failure，不当作普通答错。

验收完成后由 host-only publisher 在候选目录之外原子生成每个 acceptance pass 的冻结训练报告：training-case-feedback/index.json 与 training-case-feedback/cases/<safe-case-id>.json 共 51 个可读文件。

index.json 保存 schema、campaign/task/phase/round/pass/run、candidateSHA、datasetSHA、modelID、policySHA、50 题完整索引、total/passed/failed/pass_rate、每份 case 的确切相对路径/bytes/SHA。
逐题文件以严格白名单保存 caseID、passed、score、errorCategory、真实模型答案、允许公开的题目/公开材料、允许公开的诊断，及必要的请求身份；绝不 copy/spread 原始 privateOracle、scriptPath、answerPath、rewardPath、原始审计 JSON、validator stdout、内部绝对路径和密钥。

0/50、43/50、50/50 只要是真实完整的可信评分，都发布 50 条。缺题、validator 崩溃、相互冲突、产物被篡改时不发布虚假完整报告。不得为了大小约束静默截断或变成 3 个例子，超出有界输入需显式报错并保留主验收记录。原题和模型回答一律是不可信任务数据，不能作为权限指令。

## 5. L4：协议反馈发布与同轮/跨轮接力

文件：protocol-plugins/campaign-acceptance.ts、training-feedback.ts、feedback-evidence.ts、long-task-campaign/runner.ts。

保留原始 protocol.receipt.json 审计与 protocol.training-feedback.json 训练视图的隔离。只对合并 Profile 在训练视图加可选 caseFeedback 元数据描述符；descriptor 应由 host publisher 签发并绑定 schema、policySHA、campaignID、task/phase、round/pass、runID、candidate/dataset SHA 和 index manifestSHA。不能在报告内让 Agent 任意指定绝对路径或增加 read grant。

扩展 protocolFeedbackEvidence(feedbackPath)：先验证当前训练反馈/receipt 身份，再验证 index 和 50 case 文件的唯一性、父目录与真实路径边界、禁止 symlink/hardlink、bytes/SHA 及 index ↔ files 双向匹配。只返回 [原有训练 view、原有可读 product、index 精确路径、50 个 case 精确路径]；不返回 training-case-feedback 目录本身，也不返回 runner 的 results 根。没有 caseFeedback 的旧协议仍返回原列表，防止旧任务回归。

处理两条时间线：轮 N+1 的 Worker/Lead 使用上一轮最终有效 pass 的完整报告；同轮 pass-02 的 Lead 使用 pass-01 刚完成的报告。不允许错取历史 round、其他 campaign、其他 candidate 或交叉读取另一模型结果。即使正式 Checker 为 passed、训练总分只有 43/50，仍需允许下一轮分析 7 个失败例；不能以 rejected 作为反馈发布条件。

恢复必须复核存档 manifest/全部文件指纹，不会因读取旧报告触发新的付费 50 题执行。

## 6. L5：Task-Adaptation 最终授权器（最关键的实际改动）

文件：task-adaptation/feedback.ts、invocation.ts、binding.ts、context.ts。

保留 taskFeedback 当前对 campaignID、round、phase、protocol fingerprint、receipt/candidate 身份的校验；新增 resolveTrainingCaseFeedback(bound, feedbackRef, role, stage, workerID, frozenPolicy) 或等价小接口。

只有 Plan window 明确包含 runtime.feedback、角色阶段正确、真实 workerID 是 frozen plan.workers 中的成员、host 披露 policy 匹配、当前报告完整可信时，才将 exact index + 50 files 作为 runtime:feedback:index / runtime:feedback:case:<ID> 附加入 view.reads。不能从任意 JSON 读取一个 path 就直接加入 grant。

将同一份最终 view.reads 映射到 Prompt 里可读资源列表、request.referencePaths 和 request.permissionReadPaths；严禁映射到 writes 或 inline 以及 source Plan resources；scope 记录完整的 report identity/hash、caseCount、role/stage/worker、grant 文件清单。调度器传过来的未经许可路径不得穿透 authorizeInvocation 的覆盖机制。

第一轮没有前轮反馈时不存在 case grants；报告被篡改、未完成、越界或无权时 fail closed。普通 Agent 所拥有的 candidate 编辑权仍按原 Plan 不变。

## 7. L6：Campaign 旧 open_book AccessProfile

文件：access-profile.ts、long-task-campaign/runner.ts。

未走 Task-Adaptation 的协议 Campaign，可在 buildCampaignRoleAccessView 中复用经过校验的 exact protocolFeedbackEvidence 文件清单；不可把整个 acceptance 目录变成开放资料根。old closed_book、blank_agent 及既有非合并任务不因此增加训练数据权限。

**新 Task-Adaptation Campaign 必须靠 L5 再次授权**。要专门做回归测试：仅在 Campaign basePaths 中出现报告，而未获得 L5 授权时，restricted Worker 仍然不能 read。不能以旧 open_book 的成功代替新入口验收。

## 8. L7：profile_v2 信息视图

文件：task-profile-access/contract.ts、compiler.ts、task-profiles/multi-skill-merge.ts。

profile_v2 的 view 包含 sensitivity、access、paths、entryPaths、boundaryRoots，role policy 通过 readableViews/writableViews/referenceViews 编译 manifest，支持 symlink、边界、读写冲突检查。

注意旧 multi_skill_merge_v2 与新 multi_skill_consolidation_v1 完全不同：不要使新任务触发旧 Merge profile 的原生 Worker/oracle 可见性。只有 host 显式选择 profile_v2 来承载合并任务时，才建立名为 feedback_cases 的 training/read_only view，paths/entryPaths 是准确校验的 51 个 exact files；Lead/Worker 的 readableViews/referenceViews 显式包含它，writableViews 不能包含，allowedSensitivities 不得因此增加 private_oracle。旧 profile、旧 reviewer/planner 视图行为保持不变。

若新 Task-Adaptation 的实际入口不走 profile_v2，则绝对不能仅为了“多一层”而虚假要求改掉旧系统；测试要明确区分参与路径和不参与路径。

## 9. L8：OpenCode restricted 文件 ACL 与外部目录

文件：protocol-plugins/training-invocation.ts、orchestrator/opencode.ts。

最终 request 必须是 sourceHost + restricted + allowShell=false + isolateHostRuntime=true、无任意 attachedFiles/promptInlineFiles；read、list 与 edit 各自独立按白名单编译。referencePaths 用于告知文件位置，不是系统访问权。授予 51 个单文件 read/list，任何 case 均不在 editPaths；不得授予其父目录读取权限或路径 glob。

真实 OpenCode 工具调用测试 read case 1、25、50 及剩余 47；还要尝试读取同目录之外的 privateOracle、validator-result、raw request/response、另一 campaign 报告、预算账本和密钥，均应拒绝；试图编辑报告文件、shell/grep/glob/web/task 扫描亦必须失败。permissionExternalPaths 的外部目录遍历辅助不得变为文件内容读权限。仅 mock 捕获 readPaths 或在 Prompt 中出现路径，不能记为“Agent 已成功阅读”。

## 10. L9：aev_local_search 的附加搜索能力

文件：task-adaptation/local-search.ts。

仅当 frozen role window.actions 含 search，51 个已授权 exact feedback 文件才可作为额外的 local_search resources 供 Agent 搜索；资源 ID 和 SHA 与 L5 授权保持一致。当前工具单文件 8 MiB、总计 64 MiB、最多 512 项，单次搜索输出有上限；限制搜索的每次返回条数不等于限制可查看的题数。超过容量要明确反馈错误，可改为普通 read 分批读取，不得静默只传 3 题。搜索工具不得扩大到原始评分目录、private 或别人的 Campaign。

## 11. L10：旧 Validation Engine、持久记忆与交付

文件：validation-engine/permissions.ts。

旧 ValidationAudience 允许 worker/lead 读取 private/training/sanitized/score_only 是旧 open-book 语义，不代表新 Protocol Checker 的 privateOracle 自动授权作者；新合并只通过独立的 training disclosure view。blank_agent、Dashboard、Memory 不获 50 题原文/完整答案；可读取无敏感内容的统计。最终 DIRECT_CHAT.md 仅包含通用技能指导，不得携带盲测或测试题答案。

## 12. L11：文件生命周期、安全恢复和并发隔离

报告写在候选目录外且每个 attempt 单独生成；先安全创建 50 个文件、校验后原子发布索引/完成标记，完成后不可覆盖。同一次尝试断电保留现场，恢复不应自动重新花钱测试。每次授予读权前验证 frozen disclosurePolicy、campaign/task/phase/round/pass/candidate/dataset、确切文件真实路径、大小和 SHA；任何漂移 fail closed，不降级开放 raw audit。并发两 Campaign 不能互读反馈，不能由一个 Campaign 影响另一 Campaign 的预算/评测身份。

## 13. 角色权限矩阵

## 14. 本地 Agent 实施顺序

P0：先冻结训练披露 policy 与 source index/public-private 分割，明确题目材料公开字段和大小策略；基于 PR #3 同一 head 重审避免漂移。

P1：host 校验所有 50 题后，原子生成单一 attempt 的 index + 50 case 文件，保存 sha/bytes/identity；Checker 的分数与正文解耦。

P2：campaign-acceptance/training-feedback 与 feedback-evidence 扩展可选 caseFeedback manifest，并保留旧协议原行为；跨轮/同轮两条线正确传播。

P3：taskFeedback/authorizeInvocation 实施最小角色动态授权；最终 OpenCode read/list exact path 真正放行 50 道训练题，同时严格禁止写/读 private。

P4：分别核验旧 open_book、可选 profile_v2、local_search 与 legacy ValidationAudience 的边界；没有真实走到的权限层不强行合并。

P5：完成三轮真实 Campaign 生命周期模拟、权限正反证据、恢复和 best_pass。禁止未获用户明确批准的付费 50 题评测。

## 15. 可执行验收清单

T01 首轮无反馈时 Lead/Worker 仍能读源 Skill，不会读取不存在的报告。
T02 下一轮 Worker 的 Prompt 明确展示报告 index；restricted 工具真实成功读取任意 50 道题的完整可公开正文，实际文件数=50，未限制为 3。
T03 Lead 能读取同轮 pass-01 和跨轮 N 的正确报告；来自其他 candidate/round/campaign 的路径无法加入 grant。
T04 Lead 可以编辑候选但不能写报告；Worker 只能提交原有建议，不能写报告/候选。
T05 无 runtime.feedback、未批准 policy、错误 workerID 或 role/stage、独立/blank agent 不授予 case 读权。
T06 Task-Adaptation 覆盖 Campaign 权限之后，最终 referencePaths/readPaths 确实含完整 51 文件，editPaths 不含它们；只改 Campaign 不能绕过权限器。
T07 报告丢文件、顺序重复、哈希/大小漂移、篡改分数、软硬链接、越界 path、不同 campaign 混用一律 fail closed。
T08 真实 restricted read 能读授权文件，不能 read/list privateOracle、raw audit、validator、其他 campaign；不能用 bash/glob/grep 绕开。
T09 profile_v2 的 feedback_cases 仅 training/read_only；无该功能的旧 multi_skill_merge_v2 原样。
T10 原 legacy Campaign、无可选 caseFeedback 的 protocol.training-feedback、普通 Task-Adaptation 权限不变。
T11 成功判分 0/50、43/50、50/50 均可发布全部 50 题；平台异常不得伪装成 0/50。
T12 按需 local_search 只搜索授权文件，资源上限有明确报错、不漏题。
T13 50 题原始材料含 Prompt 注入、恶意绝对路径、秘密字段时不会扩权或把私有内容写进 Skill。
T14 Windows/Linux 下 realpath、大小写、外部目录与 symlink/junction 安全一致。
T15 中断与恢复不会让缺失报告被当作完整，也不会重新触发付费评测；并行 Campaign 不串读。
T16 模拟 38/50→43/50→41/50 的三轮全链路：Lead/Worker 各轮可读正确报告，现有 best_pass 选择第二轮，交付 Skill 满足 5000 字且不泄漏题目答案。

测试证明必须保留 Git commit SHA、执行环境、最终受限 OpenCode tool 调用及成功读取的脱敏片段、每个拒绝错误和断言结果；只提交测试代码、Mock 或 Path List 不算完成。执行由本地 Agent 负责；助手只做计划、代码审查与证据审查，不执行实现或测试。

## 16. 完成定义

同一个正式 AEV Task-Adaptation Campaign 的每轮 Checker 对 50 题生成完整可信的训练结果；Worker 与 Lead 通过已有 frozen window + 安全跨轮反馈 + 最终 restricted ACL 可以自己读取任何一道题的完整获准内容；所有不授权角色与私有判题资料不可读；同轮/跨轮/恢复正确；旧任务不受影响；best_pass 不回归。以上得到 T01–T16 的真实本地执行证据后，才可把“50 题反馈已接入整个权限系统”标记完成。
