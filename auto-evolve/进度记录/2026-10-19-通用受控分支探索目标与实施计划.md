## 1. 最终要实现什么

在同一个任务、冻结验收协议和全局资源预算内，AEV既能沿当前方案持续改进，也能在有证据的停滞后，从历史候选或允许的原始材料建立新方案。旧方案、最好合格成果及真实证据保留；新路线可暂时退步，但最终交付仍按原有正式验收和选优规则确定。

这是通用Campaign的可选探索能力。Skill、报告、软件和策略共享控制机制，各用自己的验收协议。50题归纳合并是首个完整接入实例，不是所有任务的统一评分器，更不是新增一套独立演化引擎。

工程目标是增加有限预算下尝试不同有效路线的机会；成功率和泛化是否提高，要由后续真实对照判断。不得承诺跳出所有局部最优，也不把该机制称为已具备强化学习或MCTS内核。

## 2. 对两份参考建议的取舍

| 建议 | 决定 | 理由及实施边界 |
| --- | --- | --- |
| AIDE式轻调度与ShinkaEvolve式候选档案 | 采用 | 参考草拟、调试、改进和多起点档案；在原Campaign内接入，不搬整个平台 |
| 不展示旧候选全文，以免只会打补丁 | 有条件采用 | 只适用于明确的独立重建动作；普通改进仍读取父候选，历史全文可被隔离但不能删除 |
| 清空current后重建 | 不采用 | 改为新候选目录加受控激活；保留唯一工作版、快照和中断证据 |
| 同一个out便自动共用预算 | 修正 | 必须复用冻结的budget root、scope、上限及真实调用准入，目录相同本身不是证明 |
| 挑选错题不同的候选 | 采用为辅助规则 | 只比较同协议、同用例集合和有效完整判定；先满足质量下限，再看能补回多少当前失败 |
| 新分支重置停滞计数 | 有条件采用 | 新增分支局部计数；不重置总轮数、调用、token、时限及停止请求 |
| blocking_issue/package_gap全局保留 | 修正 | 不能凭字段名决定效力；按事实证据、环境与候选作用域分层 |
| 所有候选统一送50题consolidation-direct-chat | 不采用 | 违反通用任务定位；统一的是协议接口，不是题数、模型或pass_rate |
| 对50题反馈反复优化便证明泛化 | 不采用 | 可反复反馈的用例是优化用例；冻结后的未参与选优评价另计 |
| 互补分支交叉融合 | 第二阶段可选 | 两份有效候选仍可能冲突；必须重新执行原验收，不取通过集合的并集作为新成绩 |
| 通过集合震荡探测 | 采用为路由信号 | 集合变化不必然是坏事；至少检查回摆、净进展与可比性，不新增终局失败结论 |
| 蒸馏失败经验为永久硬禁令 | 不采用 | 模型可能诊断错误；只有可信规则及权限本身是硬约束，路径假设留作带来源的建议 |
| 用token替代次数的UCB1且保证最优分配 | 首版不采用 | 非标准UCB1，token单位会影响数值；分支持续变化也不满足普通固定臂假设 |
| 停滞时提高温度、并行种群、完整MCTS | 首版不做 | 增加变量和消耗，且各后端支持不同；先完成可恢复的串行小规模探索 |

公开依据为2026-10-19可读的官方源文件，不是冻结依赖：[AIDE搜索策略](https://github.com/WecoAI/aideml/blob/main/aide/agent.py)、[ShinkaEvolve候选档案与配置](https://github.com/SakanaAI/ShinkaEvolve)。上表“适合AEV”的评价是本计划的工程判断。

UCB1的原始分析围绕有界随机奖励、经验平均与拉取次数建立；直接改成token投入的公式，不自动继承其结论。参考[Auer等原始论文](https://people.eecs.berkeley.edu/~russell/classes/cs294/s11/readings/Auer%2Bal%3A2002.pdf)。反复适应性使用评价数据也可能过拟合，参考[Reusable Holdout作者说明](https://research.google/blog/the-reusable-holdout-preserving-validity-in-adaptive-data-analysis/)。

## 4. 在整体流程中的位置

```text
任务目标、材料、交付物、验收标准和能力
  → 冻结Plan、协议、权限、选择规则、全局预算及可选探索策略
  → 原Campaign：规划、工作单元执行、分析、Lead修订
  → 原正式检查及可选独立执行，保存实际输入、输出和判定
  → 冻结本候选及证据，更新合格交付版本
  → 【新增：统一探索决策，仅在本轮关闭的安全边界】
      ├─ 人工停止 / 硬预算耗尽 / 身份不一致：停止或暂停
      ├─ 平台故障 / 判分故障 / 未知调用：保留现场，走原恢复
      ├─ first_pass已有合格版本：按原语义交付
      ├─ 当前路线有效进步：沿当前路线继续
      ├─ 软停滞且有探索额度：选择起点，在新目录建立分支
      └─ 无法继续探索：按原规则选择已有合格版本或报告未达标
  → 原正式验收、冻结交付；需要时另做独立泛化评价
```

轮内规划执行、原验收、合并算法及独立执行后端不被探索策略替换。旧任务未选择该能力时，继续原来路径。

## 5. 三类状态必须分开

| 对象 | 保存什么 | 允许做什么 |
| --- | --- | --- |
| 探索候选档案 | 候选全量文件清单与原始字节、父版本、动作、假设、实际反馈和消耗引用 | 保存已评估但未达标的候选，帮助选新起点；不是交付许可 |
| 分支运行状态 | 当前父节点、局部最好进展、有效评估次数、耐心额度、激活事务 | 决定继续哪条路线及何时停止投入；不直接改正式分数 |
| 合格版本与最终交付 | 原`versions`中的正式通过快照、可信回执及冻结选择结果 | 继续按first_pass/best_pass处理；违规或证据不全的高观察分不能交付 |

拟新增目录为`task-adaptation/exploration/`，与`task-adaptation/versions/`分开；名称是设计建议，尚非已有实现。每条记录至少绑定task/campaign/plan/protocol、candidateID/branchID/parentID、候选文件清单哈希、动作、round/pass/receipt、评估身份、成本账本引用与完成标记。

候选ID不单用一个正文哈希代替：同样正文在不同来源、协议或评估条件下不能混为一个候选身份。保存文件字节哈希用于查重，保存回执身份用于成绩复核。历史证据不能被改绑成新分支的实际成绩。

正常内容/结构拒绝与应用不通过均可进入探索档案，但作为父候选使用前必须满足该操作的准入规则和安全检查。权限越界、指纹漂移、平台错误和未完整判分另存故障证据，不生成可比较的质量分。

## 6. 首版策略：少量串行分支，三种动作

| 动作 | 起点及角色输入 | 何时使用 |
| --- | --- | --- |
| 改进当前方案 | 当前候选全文、对应反馈、允许材料 | 尚有有效进展，或处于新分支有限完善期 |
| 从历史候选分叉 | 经核对的父候选、父版本成绩和历史经验 | 当前路线停滞，另一个候选具有质量或互补优势 |
| 独立重建 | 允许的原始材料、交付结构、必要规则及带来源的精简经验 | 长期只是局部补丁，且冻结权限允许重构 |

Planner在已有工作步骤中说明：本次改变哪个关键假设、准备用什么不同结构、如何按原验收判断。Lead执行该动作。首版不增加一个每轮必跑的“变异Agent”或“记忆蒸馏Agent”，避免为调度引入固定模型开销。

独立重建不只是Prompt说“别看旧正文”：新建角色可见输入视图，移除旧候选正文及可绕回历史全文的工具路径，保留受权材料与证据引用。历史全文仍完整存档。如果只改内联文本但工具仍可读全部旧正文，只能称减少上下文，不得称物理隔离。

新候选工作区从空白模板或选定父版本建立；只写本分支允许的可变文件，不删除current、验收证据或材料。候选入口保持原逻辑资源ID，由受信绑定映射到新实例；不得让Agent改冻结Plan。原协议如果要求尾部追加或保护固定正文，分支仍必须遵守，不以“重建”为由绕过。

首版策略参数显式冻结，未配置默认关闭。建议首个离线实例串行执行，最多3条路线（含原路线），新路线最多给予2次有效完善评估后再决定继续或退场；这是待批准的保守实例配置，不是所有任务默认值。轮次或预算不足时减少可开分支，不保证把名义额度全部用完。

## 7. 进展、停滞与互补如何判断

**有数值指标的任务：** 读取冻结指标及方向，使用预先声明的改善阈值，避免浮点抖动自动刷新耐心。探索评分和正式交付评分不能混用；正式选择规则不变。

**没有数值指标的任务：** 使用正式检查项和有证据的未解缺口变化，不临时捏造pass_rate。first_pass通过即按原规则停止；未通过时才可能在允许预算内换路线。

**两层耐心：** 保留全局最好合格版本；分支另有局部进展计数，新路线虽未超过全局最好，也可在有限额度内完善。相同候选重复生成不刷新耐心；正常格式拒绝也消耗尝试额度，不能无限要求“先生成一个可评分版本”。平台故障不计作能力停滞，但其真实调用仍按原预算与恢复规则处理。

**互补候选：** 对同一完整用例集合，令最好候选通过集合为B，候选通过集合为C，统计`|C-B|`（补回）、`|B-C|`（失去）及总质量。先满足预设质量下限，再优先考虑补回数量、较少失去及尚未探索的路线，确定性打破平局。不单纯最小化失败交集，否则可能选到总体很差的候选。互补只影响探索父选择，不把两者成绩并集计作任何单份候选的分数。

**可比性门禁：** 用例ID集合、协议、执行模型、材料、推理与工具模式、单题预算、评分器及重复策略必须一致；未完整判分或含基础设施故障，不按错题填零。读取发布清单前验证manifest及逐题文件哈希，并通过caseID对齐，不能靠文件顺序。训练侧只得到协议允许披露的反馈，私有答案或盲测表现不进入选择。

**震荡信号：** 至少3份可比的有效结果，除分数接近和相邻得失外，还要看特定用例是否反复通过/失败、是否回到早期得失模式、窗口净收益是否很小。单纯对称差大可能是有益互补；随机模型噪声也可能产生回摆。首版将其作为建议换路线的信号，不新增`Oscillation_Failure`终局状态，不宣称已证明逻辑到达极限。阈值随任务显式冻结，没有逐项结果时禁用。

## 8. 记忆如何保留而不绑死新路线

| 层次 | 内容 | 新分支如何使用 |
| --- | --- | --- |
| 全局不可放宽约束 | 冻结任务、权限、安全和交付要求 | 必须继承；不能由诊断Agent自行新增或删除 |
| 有证据的环境事实 | 文件存在、工具能力、明确版本条件等 | 附证据、环境指纹和适用范围；条件变化后复核 |
| 分支局部经验 | 某种算法失败、特定补丁冲突、方法假设 | 标注分支与候选，可参考、可质疑，不自动封禁新路线 |

原始记忆、分析与失败记录不删除。为新分支生成受限的摘要视图，并重算局部blockedBy和待办，不把旧状态原封不动搬成当前事实。字段叫blocking_issue、package_gap或validated_method，并不能证明其全局有效。

模型声称“坐标解析不可用”只能是待核诊断；工具故障更不能被蒸馏成“永远禁止某算法”。新增硬限制需来自可信协议规则或明确审核决定。摘要也要保存来源和失效条件，不假装经过总结便成为事实。

## 9. 预算、激活与恢复

所有分支共用冻结任务的总调用、token、轮数、时限及预算根/scope。新分支ID不代表新预算。分叉、重建、额外诊断或后续可选融合涉及的所有模型调用都必须走已有准入与结算；不能靠同out推断已覆盖所有角色。

停止优先级：人工停止、身份/完整性问题、硬资源上限和未知请求先处理；first_pass成功保持原停止语义；只有剩余资源可承受下一次工作与正式验收时，才考虑软停滞后的分支。不承诺在`rounds=3`中额外塞入两条各两轮的新路线。

激活使用可恢复事务：记录决定及来源 → 在新目录准备候选和角色视图 → 校验完整性与权限 → 标记准备完成 → 更新受信的活动候选映射 → 下一轮开始。任何一步中断都能识别已完成阶段；不采用先删current再拷贝的做法，不用软链接绕过现有路径约束。

激活事务还必须说明候选相关工作区、探索状态、路由和会话如何处理，避免正文换了但工作区/会话残留仍绑旧路线。只在旧角色执行已结束的边界切换；不杀无法证明归属的进程。角色新会话不继承旧全文，全球任务记忆继续按权限提供。

原已有调用完成回执可以按原策略复用；已发请求但响应不完整时先走恢复核查，不能用“换分支”作为自动重发理由。相同字节候选的随机重测、缓存复用及重复次数预先冻结，不因重测高分只留最好一次。

首版用确定性顺序：当前路线优先 → 新路线获得有限完善机会 → 再按质量与互补性选择，所有选择记录原因。不实现token-UCB调度，不声称数学最优。

| P1 配置和探索档案 | `plan.ts`及加载/指纹兼容；新增exploration档案、分支记录、进展适配接口 | 旧Plan未配置探索仍是原身份及原行为；有效拒绝也可存档；档案不能越权进入交付 |
| P2 决策与安全激活 | 共享探索决策函数、候选实例化和事务；接入Campaign启动/恢复两条轮末路径 | 可分叉及独立重建，局部耐心有效；旧最好不丢、硬预算不重置；中断可恢复 |
| P3 反馈与角色视图 | 已验证逐题清单/检查项适配；Planner/Lead新动作；带作用域记忆 | 互补和震荡均有真实证据；无逐项能力正常降级；训练侧不读取盲测或私有答案 |
| P4 离线全链与兼容 | 原路径、Skill合并、无执行报告、软件脚本任务；异常注入与恢复 | 覆盖下节测试；首次启动与恢复语义一致，未启用时请求内容及调用顺序不变 |
| P5 有界真实验收 | 先查已有资产并冻结协议、预算；通一条真实链，再做同总预算对照 | 真实运行、成本与恢复可审计；效果依据真实结果，不用离线夹具宣布成功率提升 |

探索代码建议集中到`task-adaptation/exploration/`，避免继续膨胀Campaign runner。选择与交付模块仍负责正式资格；底层OpenCode、原沙盒、评分模块和合并策略原则上不改，若资源映射必须适配则单独评审测试，不能承诺只动两个文件便闭环。

P0单独提交；P1至P4分阶段提交并保留回滚点。实施时从本设计提交建立独立功能分支，未启用探索的旧任务不被迁移。新配置先定schema及哈希兼容方案，禁止给已冻结运行原地追加探索字段后强行续跑。正式主链同步和部署分别验收，不因开发分支提交便替换生产系统。

## 11. 必须通过的测试

1. 旧路径等价：探索关闭，原提示、允许资源、执行/检查顺序、停止和交付与基线一致；不承诺真实随机模型每次字面回答相同。
2. 基本分叉：父候选不变，新候选确实独立；正文、辅助文件、路由及角色视图对应同一候选，不发生陈旧快照覆盖。
3. 白纸重建：角色不能沿工具路径看到旧全文；只允许的材料和全局规则可见；原始历史仍保留。
4. 暂时退步：用合成指标验证新分支低于全局最好仍能有限完善，最终不覆盖更好合格版本。
5. 无合格起点：有效拒绝能触发有界探索；结构失败不能无限刷新耐心，未合格候选不能交付。
6. 互补与震荡：逐ID算得失；同数量不同题、无循环变化、随机回摆、缺题和协议不同分别测试，不乱触发。
7. 记忆边界：旧分支假设不会变全局禁令；新分支不能放宽原权限与内容约束；报告不套Skill禁答案规则。
8. 硬预算：跨分支调用与token累计；额外动作也计费；预算不足、人工停止、超时不能被分支重置。
9. 故障恢复：激活各步、反馈发布及版本保存处硬中断；从原run恢复，不重复完整请求、不覆盖原失败证据。
10. 身份与路径：候选/材料/协议/评分器漂移阻断；Windows路径、UTF-8、锁竞争、原子写和进程强身份继续满足原纪律。
11. first_pass与best_pass：前者正式通过即停止；后者仅在正式合格集合按冻结指标择优；同分按原确定性规则处理。
12. 跨任务及双入口：50题合并、报告直接检查、软件脚本检查使用相同探索决策；首次执行与恢复均走真实接线而非手动注入替身。

离线采用真实实现及可控的小型确定性夹具，覆盖状态机制，不依赖真实大模型取得指定分数。真实效果验证时固定总预算比较原连续修订与受控探索，分别报告质量、成本、时间和未完成状态；50题选优分与冻结后的泛化评价分开。真实模型噪声和独立重复需求按消耗与主张另行冻结，不把一次改善宣布普遍有效。

## 12. 第二阶段与本次状态

首版闭环稳定且真实证据显示互补价值后，再评估多父融合。融合生成的是一个新候选，记录全部父ID；在同一总预算内重新执行完整正式协议，不能把两个父版本的最好答卷拼成结果。没有观察到增益便不扩大复杂度。

更复杂的成本感知调度、并行候选、调温和MCTS暂缓。它们不是接入通用任务或完成50题合并的前置条件。

本次只形成实施目标与计划，并同步架构探索树；运行模块未改，既有任务未恢复，未新增API请求。后续编码按P0到P4推进，真实耗用按P5另做资产复核和预算冻结。最终要得到的是“能有界换路线、不中断旧链、不丢合格成果”的通用机制，而不是把所有任务硬塞进50题评测。

## 13. 可实现性复核：收敛为受控重启底座（2026-10-19追加）

### 13.1 对通用设计模式描述的判断

“可冻结候选、按协议检查、在预算内搜索”的抽象成立；由此推出“任意任务无缝接入且极大提升泛化”不成立。机制可复用、任务已适配、实际产生增益是三件不同的事。评估反馈不是数学梯度；一个有版本和预算的控制器也不因此拥有已验证的元认知或强化学习能力。

不能以“自回归模型只预测token”为由，断言它没有全局检查能力、必然依赖错误上下文或一定发生模式坍塌。相关研究报告特定条件下的失败或改善，不证明所有模型和任务的必然缺陷。采用这些策略的理由应是可观察的重复、停滞和对照结果，而不是以上绝对化机制故事。

| 外部描述 | 修正后的精确含义 |
| --- | --- |
| 白纸重建就是删除历史 | 原始历史保留；新角色会话和工作区只获得规定起点及允许的历史摘要。压缩、从父候选改进、独立重建是不同操作 |
| 哈希或AST往复就证明架构错误 | 哈希只发现字节重复；AST归一化须任务适配且可能掩盖实质差异。错误来回出现只构成诊断线索 |
| 给新路线耐心便能越过性能低谷 | 能保证有限探索机会，不能保证存在可达的更好方案或每次重建有效 |
| 互补分叉等于MoE或路由部署 | 首先只是父候选选择；训练路由器、保留多专家和按题选版本是另外的方法与成本口径 |
| 每次模型输出都是搜索节点 | 节点是可复现的候选状态及其证据身份；规划、诊断和工具消息不是同等的交付候选 |
| 有标准、可迭代、能保存文本便足够 | 还须知道标准是否可信可比、候选依赖是否可还原、操作是否有不可逆副作用，以及实际执行与反馈预算 |

### 13.3 先解决三个真正的接口问题

**候选状态是否闭合。** 快照不能只保存正文而遗漏依赖它的辅助脚本、可变参数或工作区状态。适配器须明确候选入口、可变依赖、只读材料及环境身份。旧稿和新稿之间如果仍共享可变辅助文件，所谓分支就不独立。依赖无法完整识别或恢复时，禁用该任务的自动分支，不假装复制一个Markdown即完成重建。

**正式判定和进展观察是否分开。** 正式通过决定能否交付；进展观察决定是否值得继续。当前`selection.ts`只让正式通过候选进入交付，且`best_pass`从实际执行产物读取数值指标。`acceptance.execution=none`的报告不能直接套该数值路径，首版沿用`first_pass`，不增加“模型随手给总分”的隐式排名。

**重启是否安全。** `invocation.ts`已有候选入口重定位，但只迁移已声明交付文件；它不等于全工作区和所有上下文已实现分支。该文件还会明确拒绝未适配的`execute`动作，不能宣称复杂API和软硬件任务已无缝支持。外部写入若不可隔离、不可幂等或不可核对执行结果，首版不开放自动重启，只优化可安全重做的草稿/模拟部分。

### 13.4 分层能力，而非所有任务硬套全部策略

以下能力名称仅表达拟定合同，不是声称代码已有字段。能力由受信适配器和预检证明，不能让作者Agent自报“支持”。

| 任务已具备的能力 | 可以启用 | 缺少时如何处理 |
| --- | --- | --- |
| 候选完整快照、合法起始模板/候选、隔离可重做工作区 | 受控重启 | 不启用重启；继续原流程或报告缺项 |
| 相同条件下可比较的正式数值指标 | 数值停滞提示、按原规则选优 | 使用冻结检查结果和有限次数，不伪造数值进展 |
| 有稳定ID的完整逐项结果 | 行为互补和回摆分析 | 关闭该增强项；不由诊断文本猜逐题向量 |
| 经过约定重复/复核的可靠评价 | 更可信的进展判断 | 保留不确定性；不临时反复重测直到得到高分 |
| 幂等操作、沙盒或可确认的外部提交边界 | 在相应范围内安全恢复/重做 | 不把文件回滚当外部回滚；不可逆提交另设关口 |

对只给“通过/拒绝”的任务，有限重启仍有意义，但不自动存在全序的“最好未通过版本”。首版保持正式first_pass选择；如果需要主观报告多稿排名，应另行冻结评价比较规则并验证后再接入，不借探索模块偷偷更换验收。

### 13.5 当前推荐的最小首版

将首版从“多起点加互补、震荡与记忆蒸馏”收敛为“候选档案加一次受控重启”。原路线加一条备用路线，串行；重启次数、触发点及新路线最多可用轮数在开跑前冻结，仍服从原总预算。数量是首版范围限制，不是未经批准的新运行默认值。

首版只完成四件事：

1. 在轮末冻结当前候选及真实判定，正式合格版本仍进入原交付档案。
2. 正常修订；有可靠数值时参考停滞，无可靠进展信号时按预先冻结的分支尝试额度决定是否使用唯一重启机会，不宣称检测到了语义局部最优。
3. 在新工作区、新会话从一个明确起点重新开始。初期每个任务只声明一种安全重启方式：固定起始模板/初始候选，或一个确定的合法历史父版本，不同时实现通用父选择器。独立重建与历史父改进的可见正文规则分别检验。
4. 原协议重新验收；新路线有有限完善机会。总预算到达上限即结束，从已有正式合格版本按原规则交付；没有合格版本就报告未达标。

不额外增加Architect Agent、强制蒸馏Agent、自动调温或候选融合。对精确重复正文可记录和限制重复生成次数；首版不建设AST/自然语言语义死锁检测器。不自动创建路由器或多专家部署。

停滞分支决策只能延后可选择的软停止，不能覆盖人工停止、硬轮数/资源限制、身份漂移、未知请求和正式first_pass成功。分支局部耐心重置一次，全局预算计数永不清零。

实现只依赖明确的模块接口：候选冻结/实例化、受信评估引用、预算状态、有限决策、激活事务及角色视图。父候选文件、当前角色输入和实际验收候选必须指向同一身份。恢复到旧父候选时，不能把旧分数伪装成新候选刚刚取得的成绩。

### 13.6 如何判断实现确实自洽

机械层应证明：探索关闭时旧路径不变；备用路线的文件、会话及必要依赖不混用；切换中断可以原地恢复；原最好合格版本不丢；所有新调用进入同一预算；first_pass/best_pass语义不变；外部副作用不会因分支被静默重复执行。

质量层只能通过后续真实结果判断。档案能保证保留某次观察的最好成绩和对应文件，不能保证随机模型下次仍取得同样成绩。若评价器偏向长文本或漂亮措辞，更多搜索可能只会更迎合评价器，因此没有可信评价不能承诺搜索必然改善实际质量。

先完成P0前置修复，再实现上述最小首版和离线恢复回归；50题合并使用真实共享接线，无执行报告验证binary/first_pass路径，软件小夹具验证候选依赖与可重做环境。不能把任一离线夹具等同真实成功率证明。

真实对照仍先查重与复用。在固定总预算下，至少区分“沿原路线继续修订”与“允许一次受控重启”；若要证明复杂调度优于简单多试一次，还需加入预定时点的简单重启对照，不能把增加尝试次数的收益全归给智能探索。首版不以完成全部该对照为写代码前提，也不因此自动启动付费实验。

互补、行为震荡和多父融合继续保留为后续能力；只在已有可信逐项证据、明确收益问题和剩余资源时逐个增加。此次修改仅更新计划及架构树，不实现运行功能，也不将“改善泛化”从研究目标提前写成结论。

## 14. 从真实AEV出发的首版条件与状态机补充

### 14.1 调研后的最终取舍

目标不是实现某个外部框架，也不是令所有任务白纸重建，而是让原Campaign在明确条件下，能安全地尝试另一条路线。默认继续原有流程；新能力必须显式启用并在启动时冻结。首版串行、最多一次备用路线，不引入新的总调度器。

这次新增的外部核对及工程判断：

| 公开一手材料 | 原文支持的事实 | 本方案的判断，不冒充原文结论 |
| --- | --- | --- |
| [Anthropic长程Harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) | 跨会话增量工作依赖环境初始化、进度记录、版本历史与实际测试；示例主要面向软件 | 累积任务优先保留已验证里程碑，换路线不能等于全部清空；新会话与白纸重写不是同一动作 |
| [AIDE搜索源码](https://github.com/WecoAI/aideml/blob/main/aide/agent.py) | 分别处理新草稿、可调试失败叶节点与已有好节点改进 | AEV也应区分改计划、修候选、换父版本、从合法起点重建；不把它们混称回滚 |

| [Temporal确定性约束](https://docs.temporal.io/workflow-definition#deterministic-constraints) | 可恢复调度应保持重放顺序，模型/API等非确定性动作与调度逻辑分开 | 恢复重放已记录的分支决定，不重新询问模型决定走哪条路；不照搬其自动重试策略 |
| [MAP-Elites原论文](https://arxiv.org/abs/1504.04909) | 多样性档案建立在指定的行为变化维度上 | 没有可信行为描述时，不能用文本新颖度假称行为互补或泛化收益 |
| [Agent评测说明](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | 任务、试次、评分与运行环境共同决定评价；随机执行需要注意可靠性 | 通过数量变化是观察，不自动证明路线改善；环境/评分故障先修平台，不能靠换路线解决 |

本方案不引入Temporal、MAP-Elites等新依赖。网页为2026-10-19可读版本，不是AEV冻结依赖；落地时外部源码不能替代本项目测试。

### 14.2 真实源码给首版设定的限制

| 已核对源码 | 当前行为 | 必须遵守的设计条件 |
| --- | --- | --- |
| `task-adaptation/selection.ts`的source/readTaskVersions/recordTaskVersion | 仅正式passed候选入交付档案；best_pass从受信实际产物读取指标 | 另建探索档案容纳正常拒绝版本；不放宽交付档案，不让未通过版本参与正式交付 |
| 同文件chooseTaskVersion | first_pass成功立即停止；stagnant依赖全局最好合格版本轮次 | 新决策必须在最终状态落盘前处理允许延后的软停；不能在已有终局状态之后偷偷复活任务 |
| `long-task-campaign/runner.ts`两处轮末流程 | 初次运行与恢复分别调用recordTaskVersion、计算nextStatus和保存状态 | 提取共同轮末决策，两个入口同测；不另写一个只在新启动时生效的探索循环 |
| `protocol-plugins/candidate.ts`的copyCandidate | 读取、复制并校验声明文件；不删除目标目录其他文件 | 新起点使用全新受控目录；不能用复制到旧目录宣称完成整份工作区回滚 |
| `task-adaptation/context.ts`的seedTaskCandidate | 从冻结资源初始化；遇到不同现存正文拒绝 | 不能把该初始化函数直接当“重置当前版本”接口；新分支实例化需单独职责 |
| `task-adaptation/invocation.ts`及context.ts | 可按候选根映射声明入口，角色视图带反馈/建议引用 | 候选路径重映射不等于完整依赖与会话隔离；必须核对旁文件、工具工作目录和历史读取入口 |
| `task-adaptation/request-budget.ts` | 已准入计数不归零，unknown/overrun阻断后续请求；reserved占用预留 | 不因切换释放未知消耗；轮末仍有reserved必须先判断是否在途或中断，不带悬账重开 |
| `long-task/runner.ts`的shouldStopForBudgets | 轮内尝试、validator调用上限和无进展检查独立存在 | 分支耐心不覆盖轮内硬限额，也不将工具卡死伪装成跨轮质量停滞 |
| `task-adaptation/plan.ts` | 严格字段校验，尚无探索配置 | 下文是待实现契约，不是可直接粘贴到现有Plan的配置；须同步schema、指纹、绑定与恢复兼容 |

结论：当前代码具备若干底座，但本节描述的分支机制尚不存在。复制文件和保存最好版本都不足以证明已有可恢复搜索。

### 14.3 冻结哪些条件，哪些允许运行时决定

启动时冻结以下语义；字段名在编码时统一确定，不能误当现行API：

| 条件 | 必须明确的内容 | 未提供或不满足时 |
| --- | --- | --- |
| 启用与范围 | 是否启用；允许替换哪些候选文件/子目录；哪些里程碑必须保留 | 默认关闭；已运行任务不热加策略 |
| 允许动作 | 继续修订；可选的历史父改进或合法初始模板重建，首版只选择一种备用方式 | 不自动猜测或临时扩大权限 |
| 起点来源 | 初始模板或指定父候选的标识、文件清单、哈希、依赖和适用协议 | 不存在、漂移或不完整则不激活 |
| 改写约束 | 可改/只追加/不可改范围，是否允许从旧版本建立新候选 | 追加约束下不得以新分支名绕过保护；不允许重写则只修订 |
| 触发条件 | 最少完整观察轮次、局部耐心、有效提升阈值及单位，或预定尝试额度 | 没有可信指标时只允许预定有界重试，不声称检测到局部最优 |
| 结束条件 | 总round/call/token上限、已有时限、停止请求、最大重启数、备用路线额度 | 任一硬限制优先；不以局部耐心重置总预算 |
| 评价能力 | binary/数值指标/完整逐项结果；指标方向、可比身份、重复评价规则 | 缺哪项就关闭相应数值或互补能力，不编造分数 |
| 环境可重做性 | 所需工作区/依赖能否复原；外部动作幂等键、沙盒或审批边界 | 不可逆或无法确定安全性时禁用自动重建 |
| 资源余量 | 下一轮作者侧和正式验收所需的可执行上界，以及预留的交付整理资源 | 不足就不启动新路线；不能只预算一次Lead而漏掉验收 |
| 可见性与经验 | 新路线可读哪些事实/反馈；哪些旧候选全文不提供；来源与作用域 | 按现有权限收紧；“提示不看旧文”不算权限隔离 |

运行时只能在冻结范围内选择继续或激活备用路线、追加真实观察与消耗。不能改变验收题、评分器、模型预算或通过标准来让新路线看起来有提升。任务类型可以帮助选择模板，但LLM建议不能授权资源、放宽约束或改写判分。

### 14.4 路由决策表：先排故障，再考虑探索

下表按优先级执行；“停止/暂停”保留原状态分类和证据，不统一伪装成任务解答失败。

| 当前情况 | 首版动作 | 不能做什么 |
| --- | --- | --- |
| 人工停止、安全边界违规、协议/材料身份漂移 | 停止或暂停核查，保持现场 | 不能用新分支绕开 |
| 在途请求未结束、计费未知、评分缺失、基础设施/数据故障 | 先等待或按既有恢复机制核查原attempt | 不能判为候选无进展，也不能自动重复发送 |
| 正式first_pass已取得合格候选 | 按原规则交付 | 不为了“探索”继续烧额度 |
| 总轮数/资源/已冻结时限已到 | 结束搜索；仅按原规则选择已合格版本 | 不因备用分支尚未尝试而延长 |
| 未启用探索或任务不可安全复原 | 原流程继续或原规则停止 | 不强制白纸重写 |
| 正常内容拒绝，仍有局部改进且未到触发额度 | 保持当前路线修订 | 不把每次拒绝都当成需换架构 |
| 数值进展不足且达到冻结耐心，或binary任务达到冻结尝试额度 | 检查备用起点、剩余完整周期预算和安全条件 | 不把binary拒绝自动叫“低分平台期” |
| 全部准入条件成立且唯一重启机会未使用 | 事务式激活备用路线，新会话继续原Campaign | 不删除旧current，不新建预算，不改变协议 |
| 条件不成立或重启机会用完 | 按原流程继续或按已冻结软停止结束 | 不强行创造第三条路线或额外Agent |

无进展信号只决定是否考虑换路线，不是候选验收结果，也不新增Oscillation_Failure终局状态。首版不实现语义震荡自动检测。软件已通过的模块、报告已核实的资料等累积成果，只能在声明可替换范围内变更。

### 14.5 同一Campaign内的闭环与事务

```text
原轮内计划/执行/分析/Lead修订
  → 按冻结协议检查候选、可选独立执行、判定真实产物
  → 关闭本轮；冻结实际候选及反馈，更新正式合格版本
  → 共同轮末决策（初次与恢复使用同一函数）
      → 继续当前路线
      → 条件全部成立：准备备用路线 → 核验 → 激活 → 下一正常轮
      → 按原规则停止与交付 / 暂停核查
```

所有角色仍按原职责工作。探索只接管“下一轮从哪里开始、可见哪些经验、还有多少尝试机会”；不替代规划、执行、Skill统筹、审阅、泛化器、独立执行或产物验证器。

激活状态拟为`prepared → verified → committed`，异常时可标记`blocked`。这些是新事务的内部状态，不是擅自替换现有Campaign状态枚举。

1. **准备：** 在独占Campaign写权限下关闭旧轮，确认无活跃作者/验收子任务；记录决定、旧状态代次、父候选、策略指纹和同一预算身份。新建独立目标目录，不修改原current或旧档案。
2. **核验：** 复制指定起点及允许的依赖，校验哈希、声明集合、路径与硬约束；生成角色视图和新会话输入。旧工作区中的旁文件不得悄悄进入新路线；可复用缓存须满足输入/环境指纹，不把全目录搬运当安全复原。
3. **提交：** 原子发布唯一激活记录。若原代码依赖固定current路径，则在禁止并发读写的激活窗口内物化并核验，再提交代次；不能宣称一次rename已使多目录同步原子化。具体方案由离线故障注入验证后确定。
4. **恢复：** 读已存决定，不重新调用模型选路。未提交时不得从新目录执行；提交后核对所有当前路径与代次一致。中间状态先完成或撤销同一激活，不再消耗一次重启机会，也不覆盖旧候选。
5. **下一轮：** 继续原先Lead同步屏障和验收流程；保证Executor、Lead草稿及实际送验对应同一分支代次，防止此前陈旧草稿覆盖问题复发。

原有`current`固定路径、角色反馈路径和round快照的关系是落地重点；不能仅给目录起branch名称就认为已隔离。

### 14.6 分开保存四类状态

| 状态 | 保存什么 | 不允许承担什么职责 |
| --- | --- | --- |
| 正式交付档案 | 现有已通过候选、正式receipt、受信指标 | 不接收正常拒绝/故障候选 |
| 探索候选档案 | 内容指纹、父关系、分支/轮/验收次、依赖、实际评价引用及状态 | 不用作者自报分替代正式验收，不把fault计0分 |
| 激活与预算账本 | 决策、代次、事务状态、真实预算root/scope及计量引用 | 不因恢复或切换清零，不把同out当共享预算证明 |
| 经验与建议 | 事实来源、候选/环境作用域、可信程度、是否被后续反证 | 不把失败诊断升级成永久硬禁令，不让私有判题信息越权 |

同一正文可产生不同执行结果：内容哈希不是评测ID。复用正式结果必须同时满足协议、材料、环境、模型/参数、评分器和试次策略的身份要求；不满足就不能借旧分数免验。是否发新请求仍遵守实验查重和授权门禁。

进展判断与正式交付排序也分开：正常拒绝但有可信优化指标的候选可以提供路由线索，不代表获得交付资格；只有binary时没有“最好未通过”的数值排序。当前best_pass要求实际执行产物，无执行的报告首版沿用first_pass，不为支持搜索暗加一个模型总分。

### 14.7 预算、两层耐心和评价可靠性

**两层耐心不是两套预算。** 全局总轮次与实际调用一直递增；备用路线只获得提前冻结、且被总余量截断的局部尝试额度。数值任务的新路线相对自己的起点判断局部进展，交付仍看全局合格档案。binary任务只计算有效内容拒绝的尝试额度，评分/网络故障不冒充一次“质量观察”，但已发请求照实计费。

“够跑一轮”不能用平均token承诺。首版应有可执行的有限作者侧调用/输出上界，以及固定验收工作量的上界；没有上界时不声称完成了整轮预算保证，只能采用更保守的准入或禁用备用路线。还要保护交付阶段的必要资源。轮级资源安排与现有逐请求reserve/settle必须避免重复计费、重复扣额度；现行预算模块尚无整轮预留接口，属于待实现事项。

评价中的微小变化是否算提升，由启动时冻结的容差/最小变化与重复策略决定。没有重复证据时只报告观测值，不宣称真实质量严格递增。模型裁判保持rubric、后端和输入结构一致；不能通过不停重评直到出现高分来选优。改变评价规则必须建立新的比较身份，不能混入原路线历史。

多目标任务先满足硬约束，再按冻结排序规则比较；没有事先定义权重/优先级就不临时拼总分。多样性、互补及震荡留给增强阶段；完整逐项向量只是必要条件，还须处理随机噪声与环境一致性。

### 14.8 不同任务如何落地，而非万能套用

| 任务 | 第一层候选 | 可选第二层实际产物 | 首版探索边界 |
| --- | --- | --- | --- |
| 单例Skill | Skill正文/包 | 空白执行的答案或文件 | 保留原内容约束和独立验收；binary拒绝按有界额度，不强求数值排名 |
| 多Skill归纳合并 | 全局Skill | 协议指定用例答卷与受信判定 | 用例数量由Profile定；50题是优化集实例，不是通用标准或盲测 |
| 研究报告 | 报告及许可的来源文件 | 需执行时的复算/来源核验产物；也可无执行 | 保留核实事实，替换指定论证/结构；不把报告结论本身自动当第二次执行产物 |
| 软件 | 声明源码和可恢复依赖 | 固定环境里的测试/性能结果 | 可重建模块或合法父版本；数据库迁移、上线、支付等外部动作不随文件自动回滚 |
| 策略 | 策略文件/脚本 | 固定模拟器/回测输出 | 固定随机种子与环境是比较条件之一；不能用训练反馈直接宣称真实泛化 |

任务类型并不决定安全性。代码生成也可能有不可逆副作用，报告任务也可能读取可变外部网页。首版由显式能力与协议约束决定可用动作，不由文件后缀或LLM自称“这是安全任务”决定。

### 14.9 实施顺序、验收条件与暂不做事项

1. **前置可靠性：** 完成E01授权期限、E02硬中断发布恢复，保留owner/独占接管校验；明确现有类型检查诊断。未满足前不启动真实长时验证。
2. **契约与档案：** 可选策略默认关闭，校验并冻结；只新增探索档案，不改变正式交付资格。旧无探索配置保持旧指纹/原路径，恢复不热迁移。
3. **共同决策与激活：** 初次运行和resume共用轮末函数，接入一个备用方式、一次机会和串行激活事务。先验证安全，后谈智能选父。
4. **视图与资源：** 重建声明范围、必要依赖、角色会话与经验作用域；维持Lead同步屏障，不新增必需模型角色。控制档案磁盘上限，空间不足停止准备而非删旧证据。
5. **离线覆盖：** 关闭探索旧流程一致；正常内容拒绝后重启；first_pass立即交付；best_pass保持历史合格版本；binary无伪指标；预算不足不重启；unknown/在途请求阻断；逐激活阶段硬中断恢复；并发第二owner拒绝；旁文件与旧正文不可越权；只追加保护不绕过；不可逆任务拒绝；初次/resume一致。合并、无执行报告、可重做软件夹具分别覆盖。
6. **真实验证另批：** 审计已有资产后安排有限耗用验收；检验工程闭环和效果分开。效果实验比较同总预算的连续修订、预定一次重启、条件触发重启，不能把多花调用的收益归给调度策略。

首版不实现UCB、复杂种群、自动温度、语义震荡裁决、多父融合、永久经验禁令或通用外部环境回滚。也不把新方案直接替换生产系统。可实现性判断为：**在以上能力约束下可分阶段实现；目前是有条件的工程设计，不是已验证的普遍成功率/泛化提升。**
