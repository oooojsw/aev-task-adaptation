## 3. B1：任务卡 A——仅实现独立 V2 Policy 合同验证

### A.1 仅新增一个生产文件，先不要动 V1 和 Plan

**新增文件**：`auto-evolve/orchestrator/task-adaptation/exploration/policy-v2.ts`。  
**新接口（推荐原样实现）**：
- `export interface ExplorationPolicyV2`：V2 冻结策略精确 TypeScript 结构；
- `export function validateExplorationPolicyV2(value: unknown, plan: Readonly<Plan>): Readonly<ExplorationPolicyV2>`：同步纯函数，校验并深冻结克隆；不读写文件、不调用模型、不发请求、不生成 run 状态。

**现状**：`exploration/policy.ts` 的 `ExplorationPolicy` 目前只接受 `schema:"aev.exploration-policy.v1"`，且被 `plan.ts`、`lifecycle.ts`、`entry.ts` 等大量运行时文件引用。本轮不为几行 Schema 加入而重写整条使用链。

**推荐新增类型定义**（根据当前 V1 接口复用只读字段类型，不复制另写巨大结构）：

```ts
import type { Plan } from "../plan"
import { explorationPolicy, type ExplorationPolicy } from "./policy"
import { immutable } from "../../protocol-plugins/identity"

export interface ExplorationPolicyV2 {
  schema: "aev.exploration-policy.v2"
  origin: ExplorationPolicy["origin"]
  replace: ExplorationPolicy["replace"]
  preserve: ExplorationPolicy["preserve"]
  dependencies: ExplorationPolicy["dependencies"]
  window: { minimumRounds: number; maximumRounds: number }
  trigger:
    | { kind: "window" }
    | {
        kind: "metric"
        name: string
        direction: "min" | "max"
        minimumDelta: number
        minimumObservations: number
        patience: number
      }
  allowance: ExplorationPolicy["allowance"]
  budget: { mode: "best_effort" }
  bounds: ExplorationPolicy["bounds"]
  safety: ExplorationPolicy["safety"]
}
```

**不能直接修改 V1 的 `ExplorationPolicy`**，因为 V1 的 `trigger.kind="attempts"` 与 V2 的 `window` 不同。V2 作为独立导出的、尚未注册运行时的合同，避免本轮引起十多个类型错误。

### A.2 按下面顺序写函数（每一步都是要求，不自行改语义）

**步骤 A1：严格对象形状。** 新模块写一个小的 `exact(value, requiredKeys, label)` 局部纯 helper（可参照 V1 `policy.ts` 第 31—42 行）。顶层必须**恰好**拥有：
`schema, origin, replace, preserve, dependencies, window, trigger, allowance, budget, bounds, safety`；
不允许 `stagnant`、`attempts`、`reserved` 之类未知字段或缺字段。必须 `schema === "aev.exploration-policy.v2"`。

**步骤 A2：校验窗口 `window`。** 必须精确只有 `minimumRounds`、`maximumRounds`，令 `f=minimumRounds,h=maximumRounds`，均为正的安全整数，且 `f<=h`；不能把 observations、run pass 数量、API 次数当作这里的“轮数”。实际执行到达这些窗口的条件将在 S2-2/S2-3 根据正常关闭轮次产生，此处只做静态校验。

**步骤 A3：校验触发。**
- `{kind:"window"}` 必须**只有** `kind`，不能携带 `patience`/metric 等字段；
- `{kind:"metric",name,direction,minimumDelta,minimumObservations,patience}` 必须恰好是这些字段；`name`、`direction` 与现有 `plan.selection` 的 `best_pass` 可信 metric 一致，`minimumDelta` 有限、`>=0`，`patience` 和 `minimumObservations` 为正安全整数；
- `first_pass`、无评分或不一致的指标不得采用 metric；**不新增模型评分器**，也不允许 rejected 候选的自报分数当正式测量。
- 注释中要说明“V2 metric 的**实际比较身份/缺分规则由下一轮决定器和真实评估回执实现**，本函数只确认静态合法性，不表示动态测量已经接通”。

**步骤 A4：预算模式。** `budget` 对象必须精确等于 `{mode:"best_effort"}`，`reserved`、空对象、未声明模式、额外字段均拒绝。阶段 3 以前不接受预留预算，不自动降级 reserved 到 best_effort。

**步骤 A5：计算 N/f/h/m/b 静态约束。**
- `N=plan.stop.rounds`，`f/h=window.minimumRounds/maximumRounds`；
- `m=allowance.minimumRounds`，`b=allowance.rounds`；
- 都是正安全整数，必须满足 **`1<=f<=h`, `1<=m<=b`, `h+m<=N`, `b<=N-f`**。计算 `h+m` 前需确认不会超出 `Number.MAX_SAFE_INTEGER`；禁止在拒绝后偷偷修改轮数使其“变合法”。
- 注意：运行时另取 `min(Plan.stop.rounds, Campaign.maxRounds)` 作为实际 N，**此轮静态编译并没有 Campaign 对象**，所以只能以已冻结 Plan 的上限为准。S2-3 负责在真正激活/恢复入口执行运行时交叉核验，不能在本轮伪造 Campaign 数据。
- `f=h=k` 是固定第 k 轮选择；例如 `N=9,f=h=7,m=b=2` 合法，`N=7,f=h=7,m=b=2` 必须拒绝。`N=7,f=h=5,m=b=2` 合法；`N=7,f=4,h=5,m=2,b=4` 必须因为 `b>N-f` 拒绝（即使 `h+m<=N`）。
- 和现有 S1 `after + minimumRounds <= N` 不同，这里 V2 新增 `b<=N-f`，**不要回改 V1**；这是全新 V2 冻结合同，按上层蓝图执行。

**步骤 A6：完整复用现有 V1 共用安全合同。**

不要复制重写 V1 对 `origin` 历史来源、`replace/preserve` 文件分区、`dependencies` 不得引用 private/可变文件、`allowance` 调用/Token 上界、`bounds/safety` 的几十行检查。最小方法是在**仅内存临时**构造一份供 **V1 结构验证使用的投影对象**：

```ts
const forValidation = {
  schema: "aev.exploration-policy.v1",
  origin: raw.origin,
  replace: raw.replace,
  preserve: raw.preserve,
  dependencies: raw.dependencies,
  // 纯结构复核；window 不是 V1 attempts 的同义转换
  trigger: raw.trigger.kind === "metric"
    ? {
        kind: "metric",
        name: raw.trigger.name,
        direction: raw.trigger.direction,
        minimumDelta: raw.trigger.minimumDelta,
        patience: raw.trigger.patience,
        minimumObservations: raw.trigger.minimumObservations,
      }
    : { kind: "attempts", observations: 1 },
  allowance: raw.allowance,
  bounds: raw.bounds,
  safety: raw.safety,
}
explorationPolicy(forValidation, plan)
```

这里必须先经过 A1/A2/A3 等**严格的 V2 校验**才使用上述投影；否则 TypeScript 不能安全访问 raw 字段。该投影**绝不写盘、绝不计算对外指纹、绝不作为 Plan.exploration、绝不传给 Campaign**，只是调用现成 V1 的资源/上界校验；返回时 `immutable(structuredClone(validatedV2))`，保持 V2 的**原字段和值**，绝不把 `window` 存成 `attempts:1`。

如果由于复用投影出现与设计无关的 V1 限制冲突，先找出准确输入与冲突路径；不要为了通过测试而改 V1 的 `explorationPolicy`。报告后等待云端判定是本轮 validator 约束还是上层设计应修订。

**步骤 A7：身份与副作用。** `validateExplorationPolicyV2()` 不改变传入的 `value`、`plan`，返回新的不可变 V2 克隆；同一输入重复验证结果 canonical 相同；不修改 `Plan.schema`，不把 `V1 policy` 自动转成 V2；本轮**不允许让 `validatePlan({exploration:V2})` 成功**。

### A.3 本卡必须保持不变的行为

V1 调用方继续调用原 `explorationPolicy`；原 V1 policy 和 Plan 的 fingerprint、预算公式、第一次通过停止、旧任务重启决策均不变。你可以在新模块写局部 5～15 行 helper，但**禁止为复用几行校验而引入“通用策略注册表”或修改每一个现有读取者**。

### A.4 本卡完成标准

必须能直接在新的测试文件中调用 `validateExplorationPolicyV2(raw, plan)` 成功或按约定抛错；不修改任何生产执行入口；源码静态搜索原生产路径中仍没有“运行中的 V2 已支持”的错误说明；新增模块不得产生 IO 和模型费用。
