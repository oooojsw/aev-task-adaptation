## 2. 固定安全不变量（改代码前写成断言）

1. frozen Task Plan 权限是上限：Lead:revise 和真实 Worker:explore 必须原窗口有 actions.read 和 runtime.feedback；Worker ID 必须存在于冻结 plan.workers 中。缺失必须 deny，不得将未声明权限热补到旧 Plan。
2. Host 必须从 **taskAdaptationCampaignRoot／真实运行阶段／正式 acceptance receipt** 提取身份，不能信任来自模型、feedbackResource.metadata、prompt、任意文件路径的 Campaign/round/role。
3. 每个训练报告属于唯一的 campaignID/taskID/phase/round/pass/attempt/runID/candidateSHA/datasetSHA/modelID/policySHA。一次授权只能访问明确这一个版本，跨 Campaign 或不同候选绝不混用。
4. Reviewer、Planner、Independent、blank-agent、Dashboard/Memory 默认不获逐题训练正文；Checker 访问 private oracle 走现有可信评分机制，不把私有读权共享给优化角色。
5. 公开训练结果是独立**白名单投影**，不是 raw audit 的复制／正则替换。原始资料中包含的任意字符串都当不可信任务数据，不因其内容扩权。
6. 50/50、43/50、0/50 都应发布全部 **50 道已完成可信评分**；基础设施故障、缺题、非法评审不可“补 0 分”伪装成普通错误。G4 最多 3 样例的摘要可保留用于概览，但不能限制可阅读的完整案例。
7. 逻辑资源名不等于物理文件目录 grant。超大题用受限专用 Reader；不能向 Agent 授予私有评分文件夹或整个 results 根。
8. 已完成报告不可覆盖。失败/部分完成仍保留 claim 与证据，恢复先复核，不能为修复权限组件重新发起可能计费的 Direct Chat 请求。
9. 原始模型调用预算 G2/G3 的 request ledger、frozen dependency、单次尝试 ID、现有 best_pass 均继续保留。
10. 任何无法证明成功的步骤只能标记“已提交代码／测试待执行”，不能冒充生产可用。

## 3. R0：先修统一授权器；使其真正成为一次调用的唯一授权决策（P0）

类型只是说明必需字段；具体名称按现有 contract 决定，但**不能**继续让调用者手工捏一个 LogicalResource.metadata.campaignID 就获得授权。TrustedAccessContext 由 Host 在现有 taskInvocation / Campaign 状态构建；VerifiedFeedbackResource 必须来自读取并核验真实 manifest + protocol receipt 的服务，不能由模型输入或单个未认证 JSON 直接构造。

不要把全部安全决策塞进一个巨大函数。复用已有 profile_v2 的 normalizeView/compileRoleAccess 里的 boundary、overlap、sensitivities 校验；如需共享静态 helper，先导出可复用纯函数或小 wrapper，避免另写一个不一致的 realpath 校验器。旧调用签名不变。

### 3.2 authorizeResourceAccess 一律 deny by default

务必逐项校验（缺字段即拒绝）：

- role/stage 合法且与 frozen roleWindow 对齐；worker 另核验 id、actions、Plan worker 列表；runtime 明确 includes("feedback")；禁止原先 ?? true。
- action read/search 且目标 sensitivity=training，access=read_only；训练 Agent 不获得 write/publish；所有其他主体依专用 Host 规则，不得给角色字符串为 checker 的模型自动全能权限。
- resource.kind、预期 task/profile、policy、当前 campaign、sourceRound/sourcePassID、正式 receipt、candidate/dataset/model、完整 manifest SHA 与可见字段策略一致。
- sourceRound 的时间规则：轮 N+1 用 N 的最终有效报告，同轮 pass-02 用 pass-01；不得从未来、其他模型、任意旧 attempt 继承。
- 文件不可缺失、不得 symlink/junction/hardlink；只认证 boundaryRoots 中的 exact files；对报告内容需要依据哈希验证，不能只做 lexical path.isWithin。
- 授权成功返回不可变 CompiledInvocationGrant：授予的 resourceID/version/policy、actor/session、allowedActions、smallReportReadPaths（可选）、readerScope（大体量）、reasonCode；拒绝有原因码，但不给作者返回敏感绝对路径。

**不要**在授权函数里临时从 resource.metadata 推导 campaignID，再拿它与同一 metadata 比较，这是假验证。可信身份应独立来自 Campaign 状态和 frozen feedback receipt。

### 3.3 精确文件与大题 Reader 分流

授权结果不是“把所有 case 文件总是加到 view.reads”：
- 小报告按 Host 配置可选 exact-file read ACL。
- 大报告只向模型给 compact index 的精确可读文件及 readerScope；原始 case 数据文件留在 Host 私有区，不加 OpenCode readPaths。
- 不因启用 aev_local_search，把 >8 MiB 报告全部加入 local-search scope；若原 Task 有 search action，搜索限制仍按现有资源生效，超大报告由新 Reader 提供检索/阅读能力。
- 不要把 50 个文件路径及含绝对私有存储位置的 manifest 整份内联到 Prompt。

### 3.4 R0 必须新增单元测试

在原 feedback-permissions.test.ts 外新增 unified-access.test.ts 或同主题分组，逐项测试：
- runtime undefined/null/[] 皆 deny；
- worker without frozen ID、未允许 action.read、错误 role/stage deny；
- 故意把 Campaign A 的 descriptor 传 Campaign B deny；
- sourceRound、pass、candidate/dataset/model/policy/plan 任一漂移 deny；
- 伪造 metadata 的 owner 不能改变可信上下文；
- 软链接、硬链接、失踪文件、边界穿越 deny；
- 合法 Lead 和真实 Worker 各自读取授权成功，Lead 仅能写候选；
- 旧 profile_v2 原样编译，旧 Validation Engine 的原有行为不在此阶段被改写。

**退出门槛：** 真正调用 authorizeInvocation 时的 grant 来自 Host verified resource；没有“空 runtime 默认 allow”、没有自证归属、没有将超大 case 原始目录开放给 Agent。

## 4. R1：修发布器的可信来源、哈希、完整性与容量（P0）

**主要文件：** task-adaptation/consolidation/feedback-publisher.ts；关联 consolidation.ts / contract.ts / direct-chat/runner.ts。先把发布器做正确，再接正式流程。

### 4.1 正确的输入来源

不要在正式运行流程中公开接受一个任意 RawTestCaseResult[] 就发布。保留它作为受限测试 fixture API 可以，但生产入口必须接收受信的 VerifiedConsolidationEvidence：

- 源自已完成的 protocol receipt 和 consolidation product.runID；只从 Host 校验过的 Direct Chat summary/results、frozen dataset、真实 response.txt/answer/validator verdict 等确定数据来源。
- 重用 consolidation.ts :: score()、verifyTraces()、caseDependencies() 和数据快照身份核验，不另编一套“看起来差不多”的判分器。
- 本次任务 configured expectedCases=50；生产实际结果必须恰好 50 条、caseID 唯一、处于完整预期集合，无 missing/duplicate/额外结果。0/50 是完全合法且已评分的集合，不是 API 失败。
- 不能从不可信材料取得 validator 脚本／私有文件的直接公开路径；审核“真正送入模型的题面/附件”的安全来源。DirectChatCaseBundle.question、materials、DirectChatCaseResult.answer 和 runner caseDir/response.txt 是现有事实字段。responseAuditPath 对应的 provider-response.json 存 raw provider body，**不能直接复制它**。privateOracle 永远留在 Host 端。
- 输出所能包含的字段由显式 disclosurePolicy 控制，如 caseID、question.text、outputInstruction、允许公开的 material 文本/媒体、实际发送的 model answer、passed/score/errorCategory、白名单诊断；引用的数据如果原有脱敏不足，要在源字段层面 fail closed，不能用任意 diagnostics/stdout/raw JSON 直接跨域拷贝。

### 4.2 类型与身份不变量

修改生产 Publisher Input 至少增加 campaignID、taskID、phase、round、passID、runID、candidateSHA、datasetSHA、modelID、protocolFingerprint、receiptFingerprint、policyFingerprint、expectedCaseIDs 或其冻结摘要。所有字段都来自 Host 可信上下文；验证读取的 source 与其完全一致。

具体校验：
- caseID 只接受安全 ID，建议 /^[A-Za-z0-9][A-Za-z0-9._-]*$/，另限长度，不允许路径分隔符、../、盘符、Unicode 路径别名、空名、重复及 Windows 保留名；物理文件路径不可由未经约束的 caseID 直接 path.join。
- score 必须是合法有限数值，与该 Checker 明确规定的布尔 passed/score(0|1) 一致；拒绝 NaN、字符串数字、null、空对象，不得 Number(x)||0、Boolean(x)。
- text/material/output 允许大，但字段类型和媒体类别必须显式有效；不支持的图片/PDF/二进制必须报告 unsupported_media 或通过获准资源引用保存；不能把空文本当作“公开了全部原题”。
- 每个 case 正确绑定当前 source+model answer 与 validator 判决；禁止拼接不同数据集、不同候选、不同轮次的 case。
- 保留每题与总报告的真实 score、pass_rate；不要把成功评分和 Skill 是否足够好混成一回事。

### 4.3 纠正实际落盘字节 SHA 与恢复

当前写入 bug 必须修：先计算不含自引用 sha256 字段的稳定 payload，再序列化成**最终字节流**，写入并保存 **该最终字节流**的 SHA256/length。建议彻底移除 case JSON 的 sha256 自引用字段，仅在上层 manifest.cases 存文件的 bytes 与 sha256；若保留内部字段，必须清晰区分 payloadDigest 与 fileDigest，不能混淆。

注意 writeJsonAtomic 实际写 JSON.stringify(..., null, 2) + 换行；不要对另一个不同的 JSON.stringify 字符串计算 manifest 长度。建议 publisher 使用 writeFileAtomic(file, finalBytes)，在 rename 后可选 open/read-back 复核；每个 manifest 项必须对应**文件物理实际 bytes**。manifest 自身使用 canonical body hash，不自引用；其完整文件 hash 另放 durable completion claim。测试应使用 readFile(file) 的 SHA 与长度逐文件对比，而不是只比较内存对象。

先写入唯一 attempt 的 staging 目录（专用 claim/exclusive create，不允许重入覆盖），输出完整 50 case 和资产并全部验证，再原子发布 immutable manifest + 最后的 completed marker。不存在“运行两次 Date.now() 版本不同，却把旧报告覆盖掉”的行为：同身份重复发布应核验后复用，漂移时报错保留现场；旧 attempt 不能静默覆盖。Windows rename/断电恢复策略必须避免完成标记比文件先出现。

针对报告很大：**发布端与读取端均使用有界 IO**，不要创建巨大的 JSON 字符串或一口气在内存中拼 50 个超大内容。可在保持单 case 逻辑资源的前提下采用内容寻址分块、chunk manifest、流式序列化/写入；具体物理布局由本地 Agent 按真实媒体内容选择。必须保留全量、可核验 bytes，不能仅保存首尾样例。

### 4.4 R1 单测必须覆盖

- 0/50、43/50、50/50，逐题完整可公开字段，强制 50 unique IDs；
- duplicate/path traversal/bad score/bad passed/缺题/额外题/未完成 validator 不能发布；
- 包含 privateOracle、validatorScript、私有 trace、内部 path 诱饵时都不出现在 published view；
- 所有文件真正落盘 bytes/SHA 与 manifest 一致；改一个字节、删一块、替换 symlink/hardlink、改 score、缺 completion marker 均拒绝；
- 同一 attempt 重入不覆盖；中断后不能假装成功；恢复不触发模型执行；
- 至少一题 9 MiB 以上和更大受控压力样本，发布期间内存峰值有界，非文本资产如不支持必须明确报错。

**退出门槛：** 不存在任何 case SHA/bytes 对不上，且 publisher 只接受可信完整证据，绝不自行臆测 50 题“成功发布”。

## 5. R2：把报告接到正式 Checker → Campaign → Worker/Lead（P0）

这是当前最关键的“缺失连线”，必须按真实数据流做，不可只让测试手工调用 publishTrainingFeedbackResource()。

### 5.1 插件评分端：consolidation.ts

已核实真实流程：

1. execute() 调 runDirectChatEvaluation 并保存独立 runID、summary.json、trace；返回 schema=aev.consolidation-eval.v1 的 product，含 candidate_sha256、dataset_sha256、model_id、total/passed/pass_rate/evidence_sha256。
2. evaluate() 对该 product、frozen dataset 和 snapshot 校验，通过 score() 与 verifyTraces() 核验真实 50 道题，最后目前只返回短 message（最多 3 条摘要）。
3. 普通 protocol runtime 会把 Checker result/status 与 product 信息纳入正式 receipt。

**推荐最小改法：** 在 consolidation.ts 中提取一个 Host-only verifyConsolidationEvidence(product, expectedSettings) 或 readVerifiedConsolidationEvidence() 辅助接口，把 evaluate() 正在使用的可信校验复用出来，并返回 Host-only 的受验证 run identity / dataset / summary / case 数据源。此函数不是普通 Agent 工具，也不把 raw trace 加入公开 product。evaluate() 仍走此函数并只输出 status/message，不改变既有判题与 best_pass metric。

不要假定 Checker 收到正确但得分为 0/50 就是 scoring_error；评分器按原逻辑确认测试完整之后，仍是合法的 scored product。不要允许未完成、坏身份或 validator 崩溃发布报告。

### 5.2 正式发布点：campaign-acceptance.ts

在 campaignAcceptance() 中 runEntry() 返回正式 receipt、prepareEntry() 返回冻结 protocol 后，**只针对真实选中了 consolidation-direct-chat + consolidation-checker 的明确 Profile**启动 Host publisher。建议实现独立 publishConsolidationFeedbackForAcceptedAttempt(...)，输入为：prepared.protocol、entry、receipt、product bytes / runID、attemptRoot、campaignRoot、campaignID、roundNumber、runID 及 Host frozen disclosure policy。

- 先确认 receipt 的 task/phase/protocol fingerprint、必需 checker identity/status、正式 product SHA、对应执行 runID；再经上节可信验证器取得 50 题内容。
- release 位置位于一个 attempt 专属只读训练目录，与 private checker 文件物理隔离。发布成功后，在 protocol.training-feedback.json 的允许 schema 增加 **可选** caseFeedback descriptor（不直接放私有绝对路径和 raw data）；建议包含 schema、resourceID、manifestDigest、policySHA、report identity、caseCount=50、publishedVersion。

## 6. R3：把大题 Reader 变成真正可用、安全、有界的 OpenCode 工具（P0）

### 6.1 bindScopedReader 必须接收经认证的 Grant

现有 bindScopedReader(resource, manifest) 使用函数参数决定 allowedCases，既不校验 resource.sha256 与实际 manifest，也不检查完成标记，无法成为信任根。改成 bindVerifiedReader(accessGrant, verifiedReport) 或相同语义：

- 仅 Host 能加载并验证真实 manifest bytes、完成标志、每块 sha/size、路径边界、正式版本与 report identity。
- Reader session 绑定 principalID（Host session，不是模型自填）、role/stage/worker、campaign/round/pass、resource/version/policySHA、allowed caseIDs/fields、expiry 或一次调用生命周期。
- 每次 read 再验证 session grant、field 许可、caseID、段号与磁盘对象身份，不能仅凭索引里出现 caseID 就放行。
- 检查 realpath/lstat/nlink；不能接受任意 path 参数、不能通过 ../ 或大小写别名读取 sibling oracle。
- grant 的秘密/密钥、后台目录与 raw audit **不进入 Agent 的 read/list/edit paths、Prompt、环境回显或工具输出**。

### 6.2 真正流式/随机分页：禁用每页 readFile(整个大文件)

使用 fs.promises.open("r") 与 handle.read(buffer, offset/position)，单页读取不超过 Host 配置上限；建议默认 32–64 KiB、硬上限按 OpenCode 单次 output 与模型 token 预算选择，不能设无限；显式拒绝非法 maxBytes（NaN、Infinity、小数、负数、超限），不要静默向上提升成 1024 或任意 clamp 造成不可预期行为。

**UTF-8 及媒体无损：** 推荐通用底层按二进制 bytes 返回 base64 和精确 offset、length、chunkSHA，再由上层在明确文本 contentType 时采用增量 TextDecoder streaming 或移动 UTF-8 安全边界；绝不对任意字节切片直接 .toString("utf8") 然后把含替换字符的字符串称为无损原文。文本 Agent 界面可以在安全码点边界返回 text + cursor；非文本返回获准 MIME/资产引用或明确 unsupported_media（此阶段不能支持的类型不可假称已成功阅读）。

**完整性检查：** 每个 physical chunk 应有发布阶段保存的可信哈希，读时验证；如仅存整文件 SHA，可在打开 session 前流式检查一次完整文件，之后通过不可变安全存储／句柄绑定确保读取的是同一对象，不要每页重哈希全文件；完成标志、manifest、实际 file bytes 必须有可追溯的完整链。任何漂移 fail closed。

**Cursor：** 不能再是直接可改的 base64 JSON。使用服务端不可猜随机 opaque cursor/session 表，或由 Host 私钥 HMAC 认证 {session/principal, resourceVersion, caseID, field, offset, expiresAt, policySHA}。不得允许改 offset 跳到别的文件或偷看别的字段；即使同一合法内容允许随机跳页，也需要经过同一 grant 做范围/字段验证。过期、跨 session、跨 principal、畸形、旧版本 cursor 明确失败。cursor 不是任意 path。

**性能：** 一页 IO O(pageSize)，不随原题总 bytes 线性放大；不保留整个 9 MiB/100 MiB 文件 Buffer；对并发、取消信号、句柄关闭和累计 bytes/调用频次设置有界预算；不能悄悄截断整题，继续下一页直到 EOF。覆盖没有换行的单行 9 MiB 中文/emoji 与 PDF/binary 等特殊格式。

### 6.3 具体 Host 工具接线方式（已有范例，不要另起框架）

照已有 packages/opencode/src/tool/aev-local-search.ts 的模式：

1. 新建 packages/opencode/src/tool/aev-read-resource.ts，用 Tool.define("aev_read_resource", ...) 与 zod.strict() 申明 resourceID、caseID、field、cursor/maxOutputBytes；不允许输入系统 filePath。
2. execute() 先 ctx.ask({permission:"aev_read_resource", patterns:[固定安全 scope],...})；调用 auto-evolve/orchestrator 中 readResourceFromEnvironment()，只从 Host 下发的受信 session 文件/sha 解析。尊重 ctx.abort；输出只有授权正文分块及 version/case/offset/hash/nextCursor/EOF，不输出 Host 凭证。
3. 在 packages/opencode/src/tool/registry.ts 与 AevLocalSearchTool 类似按专用 env binding 存在时条件注册。无有效配置时**根本不注册**。
4. 在 opencode.ts :: makeOverridePermissions() 新增 aev_read_resource 的精确 allow 条件，其他 unknown tools 继续 "*" deny，bash/glob/grep/webfetch/task 一律 deny。
5. 在 runOpencodeTaskOnce() 对 reader 的 sourceHost、restricted、allowShell=false、scope/access fingerprint、evidenceRoot 与 permissionReadPaths 分离做校验；按 localSearchEnvironment() 同类模式生成私有 reader config 文件与 SHA 到 overrideConfigDir。配置文件必须在 Agent 可读路径之外。
6. protocol-plugins/training-invocation.ts :: runProtocolTrainingTask() 给 Reader 分配专属审计目录及 account fingerprint；它的 permissionExternalPaths 可以为了工具访问已准许的小文件授予**目录遍历**，但不能因此增加文件内容 read grant。
7. task-adaptation/invocation.ts 根据同一 compiledGrant 生成 readerScope（大题），Prompt 提供工具用法、index 的 public caseIDs，不在 Prompt dump 50 题全文，也不把 raw report 目录加入 permissionReadPaths。

**禁止简化成：** 只导出 readResourceChunk() 然后说“Agent 可以用”；或把原始 50 个 case JSON 全部放在 OpenCode readPaths，再宣称大题可使用 scoped reader；或把整目录 ACL 改成 allow/*。

## 8. 推荐 Commit 顺序、工程边界与撤回策略

**Commit 1（R0）**：修 unified access 的 Host 身份/默认拒绝/粒度权限，补基础负向测试。不能一次性迁移旧权限。
