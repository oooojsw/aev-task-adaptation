## 调用统计的模块边界与查账方法

本轮计量对象是接入共同任务请求钱包的新适配链，不是追溯修补所有旧实验。没有绑定该钱包的旧入口或外部任意脚本，不能凭扫描会话日志宣称全覆盖；后续任务应沿已冻结的 `execution.requestBudget` 和模型绑定启动，不能绕过它另发请求。

| 模块 | 请求身份及实际计量位置 | 如何解释次数 |
| --- | --- | --- |
| 任务解释 Intake | `role=intake`；原 SDK 经 `budgetedProviderFetch` | read/write/final 的模型工具循环中，每次 HTTP 都是独立 attempt；手动解释/完整 Plan 没有 Intake 模型请求 |
| 规划/重规划、工作单元执行 | `taskInvocation` 的角色，`training-invocation` 保存调用证据，实际 SDK HTTP 进同钱包 | 一次角色执行可包含多次 HTTP；角色运行次数不冒充 API 次数 |
| Workers、Lead、Reviewer、失败诊断 | 同一角色窗口及 request gate，经原训练驱动 | 阶段、轮、pass、generation 与角色一起追踪；共同钱包汇总，不新建角色消费账 |
| 独立执行 Agent / HTTP 执行 | `role=independent`；`taskRuntimeBudgets` 绑定 tool/HTTP 后端 | 一次正式验收可有多个请求；与训练侧分组但不分总额度 |
| 模型 Checker / 主动检查 | `role=checker`；相同预算传输或 tool session | 裁判工具循环每个模型请求均入钱包；确定性脚本检查不产生 LLM 请求 |
| Consolidation 消费者 | 复用 `independent` 和 Direct Chat 的显式 `requestBudgetTransport` | 每个用例请求单独入钱包；验收/合并汇总只是视图，不能再累计一次 |
| 换路线、恢复与交付 | 控制器、冻结证据、选定产物本地导出 | 这些动作自身没有额外“决定是否换路”的 LLM；已有完成回执复用不新增 API 请求 |

主账 `<requestBudget.root>/budget.json` 中每条 attempt 保存请求指纹、模型、角色、gate、预留、结算状态、可取得的 token 分项和响应结果类型。查询工具按 gate 还原 stage/round/pass/generation，输出逐次明细和 role/model/stage/generation 分组。只按原钱包结算消费；`accounting.json`、验收摘要和资源汇总用于核验调用血统，不能与主账相加。

输入/输出、缓存读写、推理 token 都保留原接口语义。OpenAI 缓存与推理通常已含在输入/输出中，分项不再叠加；Anthropic 缓存按其独立输入计量。HTTP 错误、流中断、取消和未知用量保留原 attempt；未报告字段列出未报告次数，未知总量维持预留，不按零。未获得价格依据时费用为 `null/unpriced`，token 记录不冒充账户余额或真实金额。

```powershell
bun run auto-evolve/scripts/report-task-usage.ts --budget E:/run/original-wallet-config.json
```

这里的配置必须是原钱包完整身份 `{root, scope, calls, tokens}`，不是另起一个钱包。命令不发模型请求；缺钱包、身份不符直接拒绝。已完成 SDK 离线联测：三次实际 HTTP 请求形成三条钱包记录，成功路径累计 72 token；失败路径保留前两次 36 token 和最后一次 HTTP500 的未知用量及原预留；原 Intake 完成回执复用不重复发送。上述数字仅为本地固定回复的计量夹具，不是模型训练成本估计。
