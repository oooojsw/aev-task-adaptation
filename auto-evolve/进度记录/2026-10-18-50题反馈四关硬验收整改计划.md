### B.2 绝对删除全局 Environment 授权

把 invocation.ts 中设置 process.env.OPENCODE_AEV_RESOURCE_READER_FILE 的代码完全删除。进程环境不是 per Campaign 授权容器。采用已经存在的 localSearchEnvironment 和 recomputeEnvironment 的安全模式：

    taskFeedback verifies receipt/manifest
      -> authorizeInvocation compiles verified grant
      -> runProtocolTrainingTask attaches grant to exact invocation
      -> runOpencodeTaskOnce checks restricted+sourceHost+noShell
      -> writes private frozen config in overrideConfigDir and hashes it
      -> childEnv for this run includes READER_CONFIG_PATH and configSHA
      -> ToolRegistry registers reader only for this child process
      -> aev_read_resource verifies grant before every read

扩展 OpencodeTaskInput 增加 resourceReaderGrant?/resourceReaderEvidenceRoot?，不能把 grant 的密钥、私有路径写进 Prompt、permissionReadPaths、attachedFiles、task-window.json，不能从父进程全局配置继承。一旦无 grant/config SHA 错，Host 拒绝启动 Reader。运行完成不能留下可被无权限 Agent 下次继承的 env。

opencode.ts 当前 makeOverridePermissions 默认星号 deny，必须在验证过 grant 且 sourceHost restricted allowShell=false 条件成立时，显式追加 aev_read_resource allow；否则不注册或 deny。不许设置通用通配 tool allow。工具实际 ctx.ask 通过才算成功。

### B.3 真正可信 Principal 与 Resource

当前 invocation.ts 以 effectiveResource.metadata 的 campaignID 和 round 作为“调用者身份”，必须改掉。Caller 的 campaignID/currentRound/passID/task/phase/workerID 来自当前 Campaign Host state；planSHA/stage/runtime 来自冻结 boundWindow；report owner/round/pass/receipt/candidate/dataset/model/policy 来自已验证正式 receipt+manifest。两边独立交叉比对，缺字段默认拒绝。

复用现有 profile_v2 的 RoleAccessPolicy/InformationViewDescriptor/compileRoleAccess 的边界与敏感度验证，不要重新造第三套权限模型。仅新 Consolidation opt-in 使用新 Reader；旧 open-book Oracle、multi_skill_merge_v2 语义保持独立。限定 Worker:explore、Lead:revise 且 frozen plan 明确 runtime.feedback + read action。Worker ID 必须在冻结 workers 范围内。错误 role、stage、task、model、plan、policy、campaign、未来轮次或错误 pass 不可通过自报 metadata 修改为合法。

大题数据只允许 Host-only Reader 读取。最终 restricted readPaths 可以有合法 public index/source Skill，但不能把所有巨型 case 文件或原始 judge trace 目录加入；若 role 有 search，不能把 >8 MiB 文件强塞 local-search scope 导致启动报错。grant 记录 reportSHA、session、principal、policy、allowedCaseIDs/fields，不把 raw private path 回显到作者。

## 4. GATE-C：Reader 安全、完整性、超大中文题与恢复

主要文件：consolidation/scoped-reader.ts、feedback-publisher.ts、feedback-evidence.ts、feedback.ts 及专用 Reader tests。B 阶段工具会话隔离已通过后再做本关。

### C.1 Reader 不得从公开 manifest 自己推导权力

readResourceFromEnvironment 当前直接解析一个 manifest 就列出 allowedCases，甚至当 OPENCODE_AEV_HMAC_SECRET 不存在时从公开 manifestSHA 推导“秘钥”，必须删除这种 fallback。使用 Host 独立生成的不可猜 session secret、可信 frozen scope 配置和绑定配置 SHA；缺任一字段 fail closed。HMAC cursor 需绑定 actorID/sessionID/role/workerID/campaignID/planSHA/resourceVersion/manifestSHA/caseID/field/offset/expiry，并使用常数时间比较。注意 HMAC 只能证明 cursor 未篡改，读取时仍要真正授权，不可用 HMAC 代替 ACL。

bindScopedReader 不接受任何未核验的 manifest 直接构造 trusted scope；需验证实际 manifest bytes 自身的 body digest、completed marker、出版身份、case 文件 digest/len、精确安全路径。对每次读取检查 source session grant、file realpath/lstat/no link、caseID、field、resource/version 和当前实际 bytes 与预期 digest 对应；不接受模型送入任意 filePath。可以在开启可信 session 时流式验证一次整个大文件并绑定不可变 storage/handle，再逐页校验 chunk；不能每页重哈希整文件。

### C.2 保留有界 IO，修复剩余边界

scoped-reader.ts 已使用 FileHandle.read()，保留该改进。maxBytes 必须是有限安全整数且处于预定范围，超过范围显式拒绝，不默默 clamp；处理 partial read、abort、EOF、0 bytes 无进展、文件被替换、read between stat and open 的竞态。UTF-8 文本按代码点安全边界返回；非文本媒体返回明确 MIME/授权资产引用或 unsupported_media，不能把图片文件名伪称读到内容。每页有准确 offset、bytes、chunkSHA、nextCursor/EOF，输出按工具预算不静默裁剪。

出版数据允许非常大，但必须有受控容量与流式/分片策略，不能写 50 个巨型 JSON 到内存导致 OOM，超过批准额度显式 capacity_exceeded，不把合法内容省略再声称“50 题已完整公开”。

### C.3 损坏反馈必须是错误，不能默默忽略

feedback-evidence.ts 不能只比较两个 JSON 自报的 manifestSHA256，必须真实重算 manifestBody hash，核验 .published marker 和所有需公开的 case 文件 SHA/bytes。feedback.ts 当前对 caseFeedback 解析 catch 空处理，须区分第一轮不存在（合法无反馈）与历史资源损坏（明确拒绝/不可用）。任何 manifest 被篡改、物理文件缺失、旧 session/hmac、symlink/junction/hardlink、重新发布同路径不同版本，都拒绝而不发布假的读权限。保持旧非 Consolidation 任务兼容。

### C.4 必须执行的离线测试

T-C1：至少 9 MiB 的合法中文/emoji/混合文本、无换行长文本，从原生有效 Unicode string 生成字节，先证明初始没有 U+FFFD，再分块到 EOF 拼回 bytes SHA 完全一致。

T-C2：至少 64 MiB 以上大文件压力测试，单页 I/O 有界，测峰值内存（不能每页加载全文件），不经 local-search 8MiB 限制。

T-C3：伪造/过期/跨主体 cursor、缺密钥、修改 configSHA、混用 Campaign、篡改 case bytes/manifest/body/marker、link/path escape、错误 maxBytes 必须失败。

T-C4：50 题出版在第 25 题中断、重复发布旧 attempt、恢复同身份 artifact，绝不标记假 complete，也不再次发送模型请求；fake provider call counter 不变。

T-C5：所有审计日志无原始私有数据/secret、只有必要 session/resource/case/offset/status 与安全 hash。
