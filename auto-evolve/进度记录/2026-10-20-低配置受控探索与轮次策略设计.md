# 低配置受控探索与轮次策略设计

日期：2026-10-20。只读代码基线：`9ea900b`，分支 `integration/20261020-controlled-exploration-v1`。

**状态：设计待实施。本文不是运行手册，不代表新增字段已经可以使用。** 本轮仅核对代码与独立只读复核，未修改运行逻辑、启动测试或调用模型。此前V1工程验收保持有效；本文是后续易用性与决策语义的增量设计，不回写历史任务。

**后续详细计划：** 用户要求复核外部评审并细化执行边界，新增[分阶段实施计划](2026-10-20-低配置受控探索分阶段实施计划.md)。模板接入、V2决策和严格预算保护分期验收；字段及恢复等实施细则以新计划为准，仍待讨论批准。本文保留为前序蓝图，不代表整份同时获准实施。

## 1. 目标及取舍

让AEV在原有共同Campaign内，按任务已有验收证据选择继续或启用一次备用路线；用户无需为每道任务另写一套探索材料。不能用“两轮没通过”统一代表局部最优，也不能要求报告、Skill和程序使用相同分数。

采用“简化请求 + 受信任务模板 + 冻结完整策略”。统一的是控制入口、证据身份、预算与交付，不是所有任务的质量函数。

保留V1的一次串行备用路线、固定合法起点、声明范围重建、正式合格档案与探索档案分离、同钱包、真实验收和恢复。此次不加入并行分支、UCB、MCTS、交叉融合、语义震荡检测、自动修改温度或新增判断Agent。重建只使候选不必沿用上一版正文，不能保证模型必然采用语义不同的方法。

## 3. 日常输入不增加材料

用户继续提供目标、已有材料、完整验收协议或模板、总预算。探索只增加一个可选意图；以下是拟议语义，不是可执行JSON配置。

| 用法 | 用户表达 | 系统行为 |
| --- | --- | --- |
| 原流程 | 不设置探索，或选“关闭” | 旧行为、旧指纹、旧恢复语义不变 |
| 常规探索 | “允许自动换一次路线” | 只从已批准模板解析策略；无合适模板则明确说明未启用 |
| 指定轮次 | “原路线第5轮结束后仍未完成，就另试” | 固定轮次窗口；不是声称检测到停滞 |
| 高级覆盖 | 调整最少/最多轮次或评分耐心 | 在模板授权范围内覆盖；冻结前检查相容性 |

接口建议用启动侧独立的可选 `explorationRequest` 表示意图，不能把字符串或简化字段直接填进现有 `Plan.exploration`。最终Plan仍保存展开后的完整策略。字段名与schema在实施时落定，示意不能被后续Agent当作现成入口。

不新增每任务的停滞报告、失败分类表、候选评分表或额外模型请求。所需观察全部来自原流程已有的正式验收与回执；看不出进步时承认信息不足，不让用户补造一份分数。

## 4. 复杂字段由谁补齐

新增受信的探索模板目录，与验收Profile关联，但不混写验收结论。按“所选Profile/执行后端/资源布局/预算绑定”匹配，不仅按skill或report名称匹配。

| 信息 | 既有来源或维护位置 |
| --- | --- |
| 目标、材料、交付文件 | 现有任务Catalogue及Plan |
| 什么算合格、first_pass/best_pass | 所选完整验收协议与Profile，探索不能改写 |
| 替换/保留范围、合法重建起点、只读依赖 | 项目适配器发布的探索模板，普通用户不用重复填 |
| 能否使用评分、指标方向/单位/最小可靠变化 | 已核验的评分适配与模板；没有就使用轮次窗口 |
| 阶段调用/token上限、存档容量 | 已有模型预算与执行器需求，加模板的有限上限 |
| 具体文件指纹、实际数量 | 绑定时由程序生成，不由模型手写 |

模板发布者只需为一种受支持的任务形态适配一次；同一数据集后续任务替换目标和材料即可。资源布局、执行器或权限超出模板时重新适配，不能把“低配置”说成任何新项目零适配。

多个Profile给出不兼容的探索模板时，不合并猜测或让LLM裁决。auto明确退回不探索并留下原因；显式要求特定策略则启动前拒绝。只有探索能力可退回，完整验收协议本身缺能力仍按现有机制阻断。

默认关闭。auto是用户已经允许探索后的模板解析，不是给所有旧任务静默开启。自然语言产生的设置只能在启动前作为可信请求确认/固定；训练侧角色不得修改它。LLM的Decision只选现有验收Profile与能力，不授予预算、权限或重建范围。

## 5. 轮次语义与不可回避的预算取舍

区分三种量：

- 全局演化轮：现有Campaign的round，受总上限约束；中断恢复同轮不额外计一轮。
- 路线已用轮：从该路线起点开始已关闭的演化轮；用于原路线最少/最多窗口及备用路线长度。
- 有效质量观察：正式验收正常完成且证据可核验的记录；API调用、pass、工作单元attempt均不是它。

故障、未结算请求、没有完成正式验收不提供质量观察，不能当普通失败触发换路线；它们已经发生的资源消耗不能抹掉。若消耗了轮次却没有可比较质量结果，最晚轮次窗口也不能把故障变成换路线许可；沿故障/阻断路径处理。

对拟议新策略定义：有效总轮数N取Plan与实际Campaign上限的较小值；原路线最少f、最多h；备用最少m、最多b。都是正整数；`f <= h`、`m <= b`、`h + m <= N`、`b <= N - f`。实际备用上限还受剩余全局轮次约束。固定第k轮换路线就是原路线 `f=h=k`。原V1 attempts=N继续保持“正常观察N次”的语义，不冒充精确全局轮次。

**保留原路线完整7轮并再给备用2轮，至少需要9轮；总上限7轮时最多只能按5+2分配。** 这不是算法能消除的矛盾。auto只使用用户批准的模板预算分配，启动摘要明示原路线被分配多少轮。没有批准这种取舍时不擅自截短；显式要求7+2但总额7时拒绝，不偷偷扩总额或缩任一边。

5+2、7+2只是解释配置的算术例子，不是OfficeQA推荐参数，更不是历史效果结论。旧任务需要第几轮通过的事实不能直接标定新策略最优阈值。

模板给出的“最少轮数”是备用开始前有足够资源的准入条件，不强制已经first_pass成功的任务继续运行，也不能保证未知计费或平台故障后仍完成这些轮。

## 6. 决策算法：少量模式，不造万能评分

### 6.1 固定轮次窗口

只有二元验收时首选。原路线每次正常关闭后，若已经符合完成条件则按原选择规则处理；否则未到k轮继续，到k轮检查切换条件后激活。它是预算分配策略，不叫局部最优检测。

auto的k来自已批准模板；没有经过明确取舍的模板不临时按二分之一、两轮或任务难度猜一个。用户可以自由覆盖k，只要资源与安全检查通过。

### 6.2 可选的可信评分停滞

只有原协议已经提供可核验、可比较的可信指标才开放。保持原selection及正式交付资格；首阶段沿用当前best_pass实际产物适配，不为无执行报告强造分数，也不要求放宽rejected候选的指标来源。

原路线在最少f轮后，满足评分耐心可提前换；最晚h轮按已批准窗口另试。不到h且仍有实质改善就继续。h是预先接受的资源分配边界，即使分数还在涨也可能换，因此原因必须写“原路线窗口用尽”，不能伪称停滞。

评分观察只比较同一冻结评价条件，至少包含协议/案例集合/评分器/材料与模型推理条件的可比身份；候选身份单独变化。噪声阈值与方向由可信模板给出，没有适用的单位/精度/噪声依据就不自动启用评分停滞。

确定性计算：第一条有效评分建立进展锚点；后续评分按方向计算相对锚点的改善，严格变好且达到最小变化量时更新锚点并清零耐心，否则有效评分的耐心加1。锚点与“正式最好交付版本”分开，小改善可以累计到跨过锚点阈值，不要求每轮都单独跳一个阈值。

缺指标分三种：协议不提供指标则编译期不用评分模式；正常拒绝且协议合法地没有指标则标“不可比较”，中断连续评分窗口、不增加评分停滞计数，仍受固定最晚窗口限制；宣称完成了必须有指标的评分但数据缺失/漂移则暂停核查。不能填0，也不能把无分数算连续没进步。确定性断链规则固定为：清零本路线评分耐心并清除进展锚点，下一条合法评分重新建立锚点；历史正式最好交付版本完全保留。这不是增加一个用户选项。

正文hash仅用于候选身份和恢复核验，不以hash不同判进步、不以hash相同独立判停滞。相同回执复用不增观察；同一轮多pass不增外层观察。随机评分能否比较及是否要求重复测量由原协议决定，不能为路线判断临时增加模型请求。

备用路线先获得模板规定的有限尝试窗口，不用“仍低于全局最好分”提前砍掉。首阶段最多一次切换，不在备用上再发起新备用；如将来增加备用局部评分耐心，必须独立按其本路线锚点计算，不复用原路线计数。

### 6.3 全部模式共用的优先级

```text
人工停止 / 安全事件 / 未结算请求或平台与数据故障
  -> 停止或暂停，保留证据；不能变成换路线理由
first_pass且本轮正式合格
  -> 正常交付，不强制换路线
best_pass且本轮正式合格
  -> 更新正式交付档案，继续下方调度；此处不执行旧stagnant
全局硬上限已到
  -> 结束；只交付已有正式合格版本
没有探索 / 本轮没有可核验的正常关闭结果
  -> 原流程或相应阻断路径
尚未达到本路线最少轮数
  -> 继续
固定窗口到期、可信评分满足冻结的停滞条件，或命中冻结的budget_boundary
  -> 核验起点、关闭屏障、剩余轮次和实际余额
  -> 合格则在同Campaign激活一次备用；不合格则按预定原因收尾
否则
  -> 原路线继续
```

first_pass不能为强制换路线而改成best_pass。探索启用时原stagnant仅保留其历史含义，不与新路线调度重复抢最终停止；关闭探索时旧逻辑完全保留。无结构化信号等平台保护仍能优先阻断，不能拿“最少轮数”强迫故障重试。

## 7. 预算：不把最少备用轮数当空头承诺

当前V1在切换时检查剩余预算，并保护本轮验收额度；后续新策略若对外承诺预留备用机会，就必须在原路线发请求时也保护这份余额。否则只做UI简化仍会出现“到第5轮但钱已用完”。

对calls与tokens分别计算备用最低额：`m * (每轮作者上限 + 每轮验收上限) + 最后交付预留`。额外固定消耗、已结算Intake、模型单请求预留、Reviewer和多pass累计按现有真实预算规则纳入，不使用平均消耗证明一定可运行。

编译时验证总任务至少覆盖原路线最少窗口和备用最低窗口；具体周期数与阶段上限由模板/适配器计算。信息缺失则不能承诺预留。共同轮末决定必须检查下一完整原路线轮是否可准入：如果不足以再完成原路线一轮并保有备用最低额，但当前余额仍足够备用，且本轮正常关闭、已满足原路线最少窗口，则产生显式的`budget_boundary`切换决定。这是预算分配触发，不叫评分停滞；其证据包括余额快照与账本版本，参与持久化决定身份。不能等到下一轮启动时直接推翻已存的continue决定。准入前仍核验余额一致性，异常变化沿暂停/恢复路径处理，不偷偷生成另一个决定。

准入时的“未来保护额”只是同一钱包的不可花边界，不是新增消费或第二次token扣账。对calls与tokens分别令每轮作者额为A、验收额为C、唯一最终交付额为D，备用周期保护额`F=m*(A+C)`，不把D再次装进F。原路线作者阶段保护`本轮验收剩余额+F+交付剩余额`；原路线验收阶段保护`F+交付剩余额`。已消耗的同轮/多pass额度按现有锁内规则扣除，不能保护已花额度。备用激活后F解除，备用请求仍逐次走原消费账本，并保留其本轮验收及唯一最终交付保护。

现有`request-budget.ts:234`的protection只允许同轮、同pass、同generation的后续阶段，不能直接塞入未来备用轮。实现需要在原钱包原子事务中增加可选的任务级保护状态，绑定冻结策略与代次，状态为held/activated/closed；新旧状态转换持久化、恢复幂等，不另造消费账本。激活意图与钱包转换相互核验，完成前禁止新代次请求；重复恢复不能二次释放或凭空增加余额。first_pass提前结束可在同事务解除未用备用额，仍保留交付所需额度。旧无探索钱包不生成此字段。未结算请求、超额报告和未知计费优先暂停。任何保护都不能保证外部服务必定成功。

不因为预留而阻断更高优先级的安全停止或已成功任务的交付。切换前重做实际余额核验，预算保护不替代验收器、租约和代次屏障。

## 8. 如何接进现有系统

```text
现有目标/材料/验收模板/预算 + 可选简化探索请求
  -> intake解释任务（不让模型批准探索权限）
  -> compileTask匹配受信模板并展开策略
  -> 严格校验Plan，保存解析依据及完整冻结身份
  -> 原prepareExecution和探索预检
  -> 原Campaign与completeTaskRound
  -> 决策函数读取既有正式观察
  -> 原事务激活 / 存档 / 选优 / harvest / delivery
```

实现建议：仅新增模板注册/解析的纯模块；任务侧增加一个可选简化请求。runtime模式需要新增轮次窗口及缺指标语义，因此采用独立版本策略，例如`aev.exploration-policy.v2`，V1继续原算法，不修改其历史含义。它是同控制器的新策略版本，不是第二套系统。

auto/manual_decision均在intake完成和Plan指纹落盘之前调用同一个解析器。绑定简化请求、受信模板版本/哈希、参数来源、完整展开策略、可比较评价身份及采用/未采用原因。完成后恢复只读原快照，不跟随模板升级重新编译。

manual_plan已有批准指纹，不得事后给它补exploration；使用旧完整策略原样运行。若要求新简化设置，应先生成新的完整Plan并走原批准流程；配置冲突启动前拒绝。批准主体和Catalogue授权边界不弱化。

auto能在理解任务前检查的预算、模板版本和后端限制先检查；最终Profile由intake选出后再次核验，避免假装所有条件在首次调用前都已知。任何新增读取都遵守资源可见性；私有答案和检查器不可公开内容不进入探索提示。

重用已有能力而非扩大它们：受限纯文件报告、当前受信JS软件执行、HTTP/Consolidation等只有通过实际Host预检才启用。联网研究、任意Shell或具有外部副作用的任务不能因为叫report/software就默认可重建；auto留下未启用原因并保留原可运行流程，显式要求不支持的模式则预检拒绝。

本轮不实施。后续获指令后，按以下范围递进，不能把后续增强当首版全部授权。

## 10. 当前结论

可行的最小改造不是让用户提供更多东西，而是让系统把已经掌握的信息编译成明确策略。普通任务只需允许或关闭探索；有需求时指定轮次。复杂字段集中在可版本化的受信模板里，运行时仍由现有Campaign负责。

共同协议和安全预算不变；二元任务使用透明的尝试窗口，评分任务可使用已有可信指标；不支持的项目明确降级或拒绝。只承诺有界尝试另一条路线，不承诺检测所有局部最优或必然产生新方法。

独立只读复核两轮：首轮提出预算保护重复计算、预算边界决定持久化、缺分锚点和best_pass旧停止冲突四处澄清；修订后确认这些设计矛盾已闭合，未发现新增必须修订项。此项只证明设计静态自洽，不等于实现或效果验证。Git仅记录本文及架构树指针，不提交运行产物。
