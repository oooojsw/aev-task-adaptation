## 0. 首先统一业务概念（严格遵守）

```text
Round 一轮完整工作
  -> 规划、执行、分析
  -> Skill 统筹 Agent 生成或修订候选
  -> 执行一份冻结的完整验收协议
      -> 泛化器功能：Checker 检查 Skill 本身
      -> 可选独立执行：空白执行 Agent 运行 Skill，生成答卷/产物（不是 Checker）
      -> 验证器功能：Checker 检查执行产物
      -> 一轮内可以调用多个 Checker，也可重复调用单个 Checker
  -> 正式验收汇总：合格、不合格、或平台/数据/评分故障
  -> Campaign 正常关闭这一轮，产生唯一正式闭轮证据
  -> V2 确定性路线决定函数
  -> continue / activate（一次备用）/ finish / hold
```

**绝对不可混淆**：Checker 调用、模型请求、pass、答卷、评分结果都不是 Round。V2 决定函数只能消费**完整验收后的正式 Round 关闭记录**，不能把多个 Checker 判词投票变成多轮，也不能由模型直接决定换方向。

## 2. B1 / 任务卡 A：定义 V2 纯决定器输入，只接收正式关闭的 Round

**目标文件**：新增 `exploration/decision-v2.ts`。建议直接定义以下结构并实现 `decideV2`。命名可轻微调整，但字段含义不得改变。

```ts
import type { ExplorationPolicyV2 } from "./policy-v2"

export type BranchV2 = "original" | "alternative"

export interface ClosedRoundV2 {
  campaign: string
  round: number
  branch: BranchV2
  closure: string
  receipt: string
  verdict: "passed" | "rejected"
  metric?: { value: number; comparison: string }
}

export interface DecisionV2Input {
  policy: Readonly<ExplorationPolicyV2>
  campaign: string
  rounds: readonly ClosedRoundV2[]
  current?: ClosedRoundV2
  branch: BranchV2
  activated: boolean
  firstPass: boolean
  stopped: boolean
  fault: boolean
  unresolved: boolean
  hardStop: boolean
  originReady: boolean
  effectiveMaxRounds: number
  remaining: { rounds: number; calls: number; tokens: number }
}

export interface DecisionV2 {
  action: "continue" | "activate" | "finish" | "hold"
  reason: string
  rounds: ClosedRoundV2[]
  identity: string
}

export function decideV2(input: DecisionV2Input): DecisionV2
```

### A.1 每个字段究竟来自哪里

| 字段 | 真实含义及未来可信来源 |
| --- | --- |
| `round` / `closure` | 正式 Campaign 关闭的 Round 编号和关闭身份，不是第几次 Checker |
| `receipt` / `verdict` | 完整验收协议汇总后的正式通过/拒绝回执；不得取单个模型 Checker 判词 |
| `metric.value` | 仅合格的 best_pass 执行产物从正式 Selection/验收中取得的数值 |
| `metric.comparison` | 同一协议、评分器、测试材料和推理配置的可比身份；**不包括候选自身** |
| `effectiveMaxRounds` | 未来 Host 提供 min(冻结 Plan.stop.rounds, 实际 Campaign.maxRounds) |
| `remaining` | 未来 Host 调用现有预算账本获得的真实剩余 rounds/calls/tokens |
| `policy` | `validateExplorationPolicyV2` 已校验的冻结策略，budget=best_effort |

**非常重要**：此轮 `receipt`、`comparison` 只能通过**离线 fixture** 模拟。真实 Host 生成并验证这些身份属于下一轮 S2-3。不能把“函数能比较两个 hex 字符串”说成“已证明真实 Checker 得分可比”。

**不要给接口添加** `checkerCalls`、`judgeCount`、`passes`、`modelSaysStagnant` 等字段。一轮里可能有三个 Checker，但向函数只交一条正式 `ClosedRoundV2`。

### A.2 具体写法：先校验归一化，不要直接用数组长度决定

在 `decideV2` 中，先归一化 `[...rounds, ...(current?[current]:[])]`：
1. campaign 必须非空且与每条闭轮记录一致；round 是从 1 开始的安全整数、整体严格递增；closure/receipt 为 64 位小写 hex；verdict 只有 passed/rejected；branch 只有 original/alternative。
2. 如果 current.round 已在历史中：全部字段规范化后 canonical 相同才复用，不增加 Round；有不同 receipt/closure/verdict/metric/comparison → 抛出 `round closure conflict`。同一 closure 不得出现在不同 Round。
3. 不同 Round 可以因为缓存复用相同**正式验收 receipt**，但只允许其 verdict、metric、comparison 全部相同；它们仍计入不同闭轮，但评分只算**一次新测量**。同 receipt 对应不同判定或比较身份 → 拒绝证据。
4. alternate 之后不能再出现 original；`activated`/`branch` 与真实路线一致。无正常关闭的故障轮次不得被造为 rejected 正常闭轮。
5. metric 有值必须是有限数，comparison 必须为合法身份；rejected 不得携带“已合格指标”。评分故障由 `fault` 等标志触发 hold，不应当转译成无分 rejected。
6. 保存 normalized rounds 克隆，不改传入数组；排序错误要拒绝，不要擅自重新排列抹平真实顺序。

本轮只是**纯数据合同**：不能读取 Host 文件或调用模型验证“真不真”，后续 lifecycle 必须把正式回执映射到此处。复用 `canonical`、`fingerprint`（路径：`../../protocol-plugins/identity`）；不要实现第二套 Hash 算法。

### A.3 输出身份（恢复时不能漂移）

返回 `identity` 需绑定策略 V2 内容、campaign、normalized rounds、effectiveMaxRounds、剩余额度、branch/activated/stop/fault/unresolved 状态与 action/reason；输入相同则身份相同。允许把 `current` 合并进 `rounds` 后省略原始分解形式，保证“同轮恢复重放”和“历史里已保存该轮”得到相同 identity。

不得使用当前时间、随机数、临时文件哈希或模型输出。当前仍不写磁盘 `state.json`，S2-3 才持久化已决定事实。


## 3. B1 / 任务卡 B：按固定优先级完成确定性换路逻辑

继续仅改新文件 `decision-v2.ts`。**严格按下面顺序**，不要根据任务描述临时发明停滞判断或调整预算。

### B.1 准备工作

先确定 f/h/m/b：f=policy.window.minimumRounds、h=policy.window.maximumRounds、m=policy.allowance.minimumRounds、b=policy.allowance.rounds。
有效 N 是 `effectiveMaxRounds`，必须是正安全整数；若冻结窗口与真实 N 冲突（`h+m>N` 或 `b>N-f`），不得启动备用，应明确 `hold/effective_window_incompatible`。remaining 的 rounds/calls/tokens 都必须是非负安全整数。原路线已正常关闭轮数来自 normalized rounds 中 branch=original 的**条数**，备用同理；不是最大 pass 号/请求数。

### B.2 决定优先级（按以下 if 顺序实现）

1. `stopped` → `finish/user_stop`；
2. `fault` 或 `unresolved` → `hold/infrastructure` 或 `hold/unresolved_request`；有历史合格候选也不能掩盖当前故障；
3. `firstPass=true` 且当前最后一个正式关闭 Round 的 verdict=passed → `finish/first_pass`，即使尚未达到窗口也交付；
4. `hardStop` 或 remaining.rounds/calls/tokens 有 0 → `finish/global_limit`；
5. 已在 alternative：若备用已正常关闭的 Round 数达到 b → `finish/alternative_limit`，否则 `continue/alternative_window`；不再 activate、不能因为低于原路线旧最好而提前结束；
6. 仍在 original 且正常闭轮数小于 f → `continue/original_minimum`；
7. original 在 f 到 h 之间，`trigger.kind=window` → `continue/original_window`；**f 不是自动换路点**；
8. `trigger.kind=metric` 且在 f 到 h 之间时，只有达到 B.3 的可信评分停滞条件才考虑换路，否则 `continue/metric_progress`；
9. original 正常闭轮数达到 h 时，无论 metric/window，换路意图原因均为 `window_exhausted`，**不宣称已经证明停滞**；
10. 有换路意图时检查 `originReady`、remaining.rounds >= m、完整最低备用阶段的 calls/tokens：`required=(authorX+acceptanceX)*m+deliveryX`。使用安全整数；起点不足 → `finish/origin_unavailable`，轮数不足 → `finish/cycle_rounds`，calls/tokens 不足 → `finish/cycle_budget`。全部满足才 `activate/window_exhausted` 或 `activate/metric_stagnation`。

不要在 `decideV2` 里进行文件重置/预算划账/真实激活。返回 `activate` 只是下个 Host 事务的建议。V2 是 best_effort，不提供未来额度保护；也不能借用备用 allowance 估算原路线的下一轮费用（旧 Host gate 负责）。

### B.3 metric 模式算法：只比较**已正式通过、可比**的评分

按 original 正常关闭 Round 顺序扫描，维护**可从历史重算的临时量**：

```text
anchorScore = undefined
continuousScored = 0
patienceUsed = 0
seenReceipt = Set()
comparisonIdentity = undefined
```

每条记录：
- 正常 rejected：清空本路线近期 anchor、continuousScored、patienceUsed；但不删除历史最佳候选（正式 Selection 管理）。没有“失败算零分”的规则。
- passed 缺 metric：`hold/metric_missing`；comparison 指纹与先前合法测量漂移：`hold/metric_identity_drift`。不得伪造 0 分或当作没有改进。
- passed 且是**新**正式 receipt：第一次新评分设 anchorScore=value、continuousScored=1、patienceUsed=0；之后按 max 的 `gain=value-anchorScore`，或 min 的 `gain=anchorScore-value` 计算。只有 `gain>0 && gain>=minimumDelta` 才更新 anchor 并将耐心清零，否则耐心 +1。
- 已出现过的 receipt：正常 Round 的闭轮计数照常增加，但该 receipt **不增加**评分样本数/耐心；同 receipt 若字段冲突则拒绝。
- 如果 rejected 中断连续合法评分，下一次 passed 是新的锚点；跨协议比较身份漂移仍不能混比，应 hold。
- 评分停滞的触发必须同时有：`closedOriginal>=f`，`continuousScored>=trigger.minimumObservations`，`patienceUsed>=trigger.patience`，且未到 h；否则继续原路线。到 h 强制按窗口边界考虑切换，而不是自称停滞。

**完整计算示例（max，minimumDelta=3，patience=2，minimumObservations=3，f=3，h=7）**：
- 独立正式评分 `50、56、57、57`：50 建锚；56 达到进步，重置耐心；57、57 均相对锚点 56 不足 3 分，耐心累计 2，满足指标条件 → `activate/metric_stagnation`（前提是预算/起点检查通过）。
- `50、56、rejected、57、57`：rejected 清空评分连续证据；后两条新评分尚未达到 minimumObservations=3 → 不可提前断言停滞。
- 第 4 条评分只复用第 3 条 receipt：原路线关闭 Round 依然 +1，但**不增加**停滞耐心。
- 评分器版本/测例/模型条件改变导致 comparison 指纹改变：`hold`，不是“退步”或“停滞”。
- 没有正式可信评分的任务用 `window`，不能用模型自评或论文摘要自称的 7/10 充数。

注意：V1 的 `decision.ts` 对重复候选和无指标的 metric 处理与 V2 设计不同，**不能直接把 V1 决策函数修改为 V2**；两个版本分别保留，不改 V1 身份算法。
