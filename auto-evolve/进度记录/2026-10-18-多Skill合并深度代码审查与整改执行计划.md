# 2026-10-18 多 Skill 合并深度代码审查与整改执行计划

> 状态：静态代码审查计划；本地 Agent 负责实施和测试。审查基线为功能 PR #3 的 0b92f2c；参考原计划 PR #2 和风险修正 PR #4。本文不表示测试已经运行或通过。

## 一、产品目标与验收口径

合并本身是 AEV 通用 Campaign 的学习任务，而非旧 Skill 学习完成后的外挂 Phase 2。输入为 50 份冻结的源 Skill，产物是一份实际注入模型上下文的 DIRECT_CHAT.md，完整发布正文 NFC 规范化、移除 Unicode 空白后不超过 5000 个 Unicode code points。URL、Markdown 注释、代码等仍计入，不允许把正文藏进 casebook 绕过上限。

每道原题独立执行一次无对话历史的 Direct Chat 请求；请求中完整包含相同候选 Skill、该题全部允许公开的材料、问题和固定输出合同。独立可信判题器完成全部 50 题后计算 pass_rate；沿用既有 selection.best_pass 保存正式通过率最高的历史候选。三轨 Intake 和旧合并流程保持兼容。50 题训练回测分数不等于盲测泛化能力。

## 二、深度静态审查发现

### P0-01：全局预算环境变量存在跨 Campaign 串扰

文件：auto-evolve/orchestrator/protocol-plugins/consolidation.ts；direct-chat/providers/openai-compatible.ts。

Consolidation 执行期间临时设置 process.env 中的 OPENCODE_AEV_REQUEST_BUDGET_FILE、SHA256、AEV_CONSOLIDATION_ENFORCE_BUDGET，随后恢复。进程内并发两个 Campaign 时，异步 HTTP 发送可能读取另一任务的预算绑定。单任务测试无法覆盖。

**实施**：沿 runDirectChatEvaluation → runner → provider-client → openai-compatible 显式传递 host-owned、不可变的 per-run budget/dispatch 上下文；Consolidation 不再写进程全局 env。旧 CLI 的环境变量兼容可以保留，但不得成为此 Profile 的预算来源。验证双 Campaign 并发 ledger 和 HTTP 发送严格隔离。

### P0-02：模型上下文配置字段不一致

文件：direct-chat/contract.ts；direct-chat/providers/openai-compatible.ts；consolidation.integration.test.ts。

模型合同定义 contextWindowTokens，预算调用却读取 model.contextTokens 并 fallback 16384；新增测试夹具恰好使用非合同字段 contextTokens:4096，可能掩盖真实模型配置误拒绝或预留不一致。

**实施**：统一 contextWindowTokens；对未知字段进行静态/运行时拒绝；检查 maxOutputTokens 与实际 provider payload，保证保守的 Token 事前预留，不把字符数/4 当成硬安全上界。修正夹具并执行完整类型检查。

### P0-03：随机请求 ID 不足以证明恢复幂等

文件：task-adaptation/budget-transport.ts、request-budget.ts；protocol-plugins/cache.ts。

当前每次 provider 发送生成随机 UUID；账本可按 ID 防重复，但崩溃重启或新的 runID 可能把同一题再次当成新请求。

**实施**：建立稳定请求身份：campaignID、planFingerprint、round、candidateSHA、datasetSHA、caseID、modelID、providerConfigSHA、evaluationAttempt。持久化 intent → reserved → dispatching → settled/uncertain；已经发送但结果未知的请求禁止隐式重试或退款。由宿主可信确认后才能创建新的 attempt。保留既有缓存半完成保护，不得删缓存强行重跑。

### P0-04：评测依赖未完整冻结

文件：protocol-plugins/consolidation.ts；direct-chat/contract.ts、runner.ts。

当前输入主要验证 dataset.bundle.jsonl 和 models.json 哈希，但逐题材料可能从 sourcePathInternal、assetPathInternal、imagePathInternal 读取本地文件，privateOracle 也依赖判题脚本、答案和参数。仅顶层 JSONL 不变，不能保证实际模型材料和评分口径不变。

**实施**：建立冻结依赖 DAG：所有材料、附件、图像/PDF、OCR/转换器版本、validator 脚本、私有答案/奖励文件、Prompt 模板及模型参数均记录规范路径、长度、SHA256。执行前、缓存命中和恢复时验证，发生漂移即 fail closed；防止 symlink、路径逃逸和检查后替换。

### P0-05：共享预算须绑定最终批准的 Plan

文件：task-adaptation/prepare-task-run.ts、prepare-execution.ts、budget-policy.ts；protocol-plugins/builtins.ts。

Intake 前预算从 catalogue.stop 构造，执行阶段使用 plan.stop，Consolidation 接收的 execution budget 仍是可选。必须核对 manual_plan 和最终批准 stop 的约束不会产生较宽松的第二份预算；Planner/Lead/Reviewer 与 Direct Chat 应共享同一冻结账本及总额。

**实施**：真实计费任务在预执行即检查受信预算绑定；绑定 final plan fingerprint、stop、scope、provider、model；缺失即 fail closed。模拟前面工作角色已消耗额度，确认 50 题只能使用剩余预算。

### P0-06：评分结构化结果与退出码一致性

文件：protocol-plugins/consolidation.ts；direct-chat/runner.ts。

verifyTraces 检查 parsed.passed，但仍允许 exitCode 为 0 或 1，可能容忍 passed=true 与非零退出码冲突。模型答错和判题器崩溃必须区别。

**实施**：验证器结构化输出、退出码、题目身份、候选 hash、材料 hash、评分脚本 hash 必须一致。判题异常、坏 JSON、缺题、无效汇总均为平台故障，不参与 best_pass；真正的 0/50 内容得分应保留为合法优化数据。

## 三、P1 改进

**作者视窗隔离**：source-manifest.ts 的 SourceRow 含 caseID，profile.ts 将完整 sources.json 作为 training/source_index 公开。公开索引仅保留源 Skill ID、主题、路径与哈希，允许作者按需阅读全部 50 份 Skill；caseID 对应、原题完整数据、oracle、隐藏答案、评分器均只留在宿主可信评测侧。禁止把 100 多份测试附件展平到作者的 TaskPlan.resources。

**5000 字双门**：保持完整发布 Skill 的硬字数上限，额外检查 Markdown 链接、围栏、控制/零宽字符和真实发布 hash；实际请求的上下文 Token 限制是独立门禁。material-budget.ts 对 Skill 的 trim 行为应有明确 hash 对应关系；禁止自动截断或改用摘要材料。

**有界反馈**：全量 50 题的可信证据仍须保存，公开给 Lead 的只有 total、passed、failed、pass_rate、错误类别统计及最多三个脱敏代表案例。建议公开文本上限 1200 字符并另有 Token 上限；绝不透传私有答案、原始 40 条错误日志或内部绝对路径。抽样不影响正式评分。

**Prompt 适配**：direct-chat/material-budget.ts 存在 OfficeQA 特定提示，新 Consolidation 任务须采用版本化通用单轮 Prompt，保留旧 Direct Chat CLI 默认行为。媒体/OCR 能力不足、附件缺失或上下文不够时，应在发送前拒绝而非裁切。

**缓存和审计**：缓存键及每轮回执须绑定完整依赖图、candidate hash、模型配置、Prompt 模板、validator 和预算 scope；保留真实 dispatch/usage/uncertain 状态。评测报告记录逐轮成绩、最优轮次、停止原因、预算用量和交付 SHA，不公开私有题目或答案。

先用最小独立 PR 修复 main 上的 CI，因为 pull_request_target 执行的是基础分支工作流，仅修功能分支不能立即消除 dev 错误。Consolidation 实现继续留在 PR #3 Draft，由本地 Agent 按 G0–G5 分批提交并附真实测试证据；本计划仅作为独立文档 PR，不改业务代码，不运行测试，不直接合并 main。

禁止：旧合并器重新成为父控制器；第四条 Intake；把隐藏评测材料放到作者视窗；URL/注释不计数；只评分三道抽样题；以 maxAttempts=1 代替真实发送幂等；用 process.env 传跨 Campaign 预算；用顶层 JSONL hash 代替完整依赖；将本地专项测试通过声称为全链生产验收。

**最终完成定义**：同一通用 Campaign 能以冻结的 50 份源 Skill 归纳出≤5000 字候选，每题独立一次完整上下文 Direct Chat，受共享事前预算和恢复幂等保护；50 题可信验收、三例有界反馈、历史最优交付与旧功能兼容均由本地 Agent 提供同 SHA 的证据。
