## 1. 问题及判断

目标是减少持续沿同一方案局部修补的倾向，在有限资源内尝试不同方案。保留最佳交付物只能防止交付退化，不能证明搜索充分。应分开管理当前探索候选、合格候选档案和最终交付选择。

“局部最优”在这里指停滞和缺少方案变化的工程风险，尚未定义可证明的目标邻域与全局最优；“梯度消失”“马尔可夫链”“价值网络”只能作类比。没有必要将现有系统描述为RL、MCTS或模拟退火。

## 2. 当前代码核对

| 说法 | 当前源码事实 | 判断 |
| --- | --- | --- |
| best_pass 保留最好成果 | `task-adaptation/selection.ts` 仅保存正式通过候选，按冻结指标选择 | 有条件成立；first_pass 不执行这种指标择优，最高观察分的违规候选也不可交付 |

| 探索树已是MCTS | 树有状态、关注区和经验路由，未见通用访问计数/UCB/回传驱动的候选分支选择闭环 | 不应如此命名 |

| 当前固定temperature应自动升高 | 本次核对未证明所有训练角色均固定0.3/0.5，也未发现停滞调温闭环 | 不采用原文参数断言；调温须看真实模型及后端支持 |

## 4. 推荐：候选档案加受控分支探索

建议以AIDE式轻调度为实现骨架，借鉴ShinkaEvolve的多起点和档案。维持原Campaign、验收和交付，新增可显式选择的探索策略。暂不引入完整MCTS、并行种群、模型参数学习或自动交叉。

三个对象分开：

1. 当前候选：可以较差，用于探索，拥有自己的工作目录和血统。
2. 历史档案：保存冻结候选、父节点、方案假设、真实检查结果和成本；可区分未验收、结构合格、应用不通过、正式合格等状态。
3. 最佳交付版本：继续只从正式合格且协议一致的候选选取，不能被探索状态覆盖。

### 4.1 调度顺序

```text
当前路线正常修订与正式检查
  → 记录实际进展、失败类型和候选身份
  → 尚有进展：继续当前路线
  → 有足够有效判定且持续停滞：
      核对全局预算与停止条件
      → 从历史最好或互补方案选父版本，或从允许的原始材料重新构思
      → 在新候选目录建立分支，保留旧候选与全部证据
      → 明确新假设及这次改变的结构，生成候选
      → 走原检查及可选独立执行
      → 改善则更新交付选择；否则保存结果，有限继续或换分支
  → 预算、轮数或探索额度耗尽：交付已有合格版本并报告未解问题
```

只是退回最好版本反复重写仍可能停滞。因此父选择至少允许“最好版本”“已评估但行为互补的版本”“从合法原始材料重新构思”三种来源。首版可串行运行、保留少量方案，避免额外并发压力。具体档案容量、触发次数和分支上限属于待冻结策略参数，不在本调研中自动成为运行默认值。

### 4.2 如何换思路

Planner在改写前产出一个可核对的方案假设：当前受限的假设是什么、准备改变哪个组织或算法、预期解决哪类问题、怎样用现有协议判断。Lead按该方案生成新候选，可选择局部改进、整篇重构或独立重建。

报告可换论证结构或补相反证据；程序可换算法和数据结构；Skill可改决策流程、前提条件及异常处理。不能把“压缩到一半字数”当通用变异操作，因为可能违反交付要求或丢失必要信息。

新候选可以暂时比最好版本低，保留有限后续机会以跨越中间退步；但不得绕过内容、安全、格式硬门，也不能晋升为交付版本。适合再探索与允许最终交付是不同资格。仅改字体、措辞或重复相同正文不自动算方案变化；哈希查重只能识别字节重复，语义多样性判断仍有不确定性。

如已有同协议逐题结果，可用得失模式帮助挑选互补候选；报告任务则使用冻结检查维度和证据缺口。多样性帮助安排探索，不修改正式评分、不随意加一项新颖性分来宣布获胜。

### 4.3 预算、停止和恢复

探索决定应在Campaign正常关闭本轮、下一轮尚未开始的边界作出。只允许在软停滞条件即将触发时，消耗预留且仍属于同一任务全局预算的探索额度。硬轮数、调用、token、时间和人工停止不能被“重新开局”清零或突破。

平台故障、判分错误和未知计费不是搜索停滞，不触发新分支或静默重发。没有合格版本时还要支持根据已完成的有效拒绝证据探索，不能只依赖现有versions目录，因为它目前只保存正式通过版本。

切换时新建候选并记录父ID、候选和协议指纹、动作、原因、已用预算及完成标记，不清空唯一工作目录。选定父候选后重建该分支的候选相关反馈；旧反馈作为有明确来源的历史证据，不能伪装成本候选成绩。全局安全边界和故障经验继续保留，分支局部死路与阻碍重新计算，避免旧blockedBy封死新路线。

跨分支仍用同一冻结任务、协议、允许材料和预算；盲测信息不参与搜索。确定性检查可以冻结复用；随机模型的同文本重复评分是否复用或重测须事先声明，不能只挑最高一次。分数轻微变化可能是噪声，不能自动归因于结构改进。

## 5. 可能修改的位置与首版验证

| 部分 | 候选改造 |
| --- | --- |
| Plan / schema / 目录 | 可选探索策略及参数冻结，未配置沿用当前行为 |
| Campaign runner | 正常关闭后的探索决策；启动与恢复路径共用逻辑 |
| 候选档案 | 补足已评估非合格候选的可审计快照，与交付versions分开 |
| 父选择 / 分支实例化 | 新目录复制、合法候选映射、来源和协议指纹校验 |
| Planner / Lead窗口 | 新假设、父版本、允许原材料和带身份的历史反馈 |
| selection / delivery | 维持正式合格条件；探索父选择不更改最终胜出规则 |
| 停止 / 预算 / 恢复 | 所有分支共用总预算；决定与执行可恢复、不可重复扣费 |

首版先离线验证：当前路径不变；从旧父版本确实形成独立候选；中间退步后新路线能继续且不覆盖最佳交付；无合格起点仍有有界探索；相同候选去重；协议漂移和过预算阻断；故障不计停滞；切换中断恢复不重复调用；报告和Skill共用策略但使用各自验收规则。

离线夹具证明状态转移，不证明能突破真实任务局部最优。真实效果验证另做固定总预算对照：原连续修补策略与受控分支策略使用同一任务、来源和验收；比较最终质量、有效方案覆盖、调用/token和时间。此前已暂停或已完成的实验不自动重启，先查重并形成复用判定。
